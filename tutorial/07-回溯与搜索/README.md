# 07 回溯与搜索

> **这一章学什么**：回溯是"**暴力枚举的聪明版**"——它系统地走遍决策树的每个分支，走不通就"撤销"退回上一步。子集、组合、排列、棋盘填充，全是同一个模板的变体。
> **为什么重要**：回溯是面试**出现频率最高**的算法之一，几乎每场都会碰到。它模板固定，一旦掌握"做选择 → 递归 → 撤销选择"三步，就能解决一大批题。

## 一、回溯是什么

**回溯 = 深度优先遍历一棵"决策树"**。树的每个节点是一个"部分解"，每条边是一次"选择"。走到叶子（完整解）就收集，走不通就"回退"（撤销上一次选择）再试别的分支。

```
                    [] 空
            /        |        \
          [1]       [2]       [3]        ← 第一层：选第一个数
        /    \       |
     [1,2]  [1,3]  [2,3]                  ← 第二层：在剩余里选
```

**回溯和 DFS 的关系**：回溯就是 DFS + "撤销操作"。普通 DFS 走过就不回头，回溯走到底后会**撤销选择、退回去尝试别的分支**，所以能枚举出所有方案。

## 二、回溯通用模板（必须背到默写）

```java
List<List<Integer>> res = new ArrayList<>();
List<Integer> path = new LinkedList<>();   // 当前路径（部分解）

void backtrack(选择列表) {
    if (满足结束条件) {
        res.add(new ArrayList<>(path));    // ★ 收集时必须拷贝快照
        return;
    }
    for (选择 : 选择列表) {
        if (需要剪枝) continue;             // 不合法的分支直接跳过
        path.add(选择);                     // ① 做选择
        backtrack(新的选择列表);            // ② 递归进入下一层
        path.remove(path.size() - 1);       // ③ 撤销选择（回溯的灵魂）
    }
}
```

**三个关键点，缺一不可**：
1. **收集结果必须 `new ArrayList<>(path)` 拷贝**——`path` 全程是同一个对象，直接 `add(path)` 存的是引用，最后全变空。
2. **做选择和撤销选择必须成对出现**——`add` 之后一定要有对应的 `remove`，否则路径会污染后续分支。
3. **剪枝写在循环开头**——提前跳过不合法分支，是回溯从"超时"到"AC"的关键。

## 三、三类问题的区别（本章核心）

| 问题 | 顺序是否重要 | 控制手段 | `[1,2]` 和 `[2,1]` |
| --- | --- | --- | --- |
| **子集 / 组合** | 不重要 | `start` 参数（只往后选） | 算同一个 |
| **排列** | 重要 | `used[]` 数组（标记已用） | 算两个 |
| **棋盘填充** | 看位置 | 逐行/逐格放置 + 合法性检查 | — |

**一句话判别**：问"组合/子集"→ 用 `start`；问"排列/顺序"→ 用 `used`。这是回溯选型的第一反应。

## 四、剪枝：从"超时"到"AC"的关键

回溯的理论复杂度常是指数级，**剪枝**就是提前砍掉不可能产生答案的分支：

| 剪枝类型 | 做法 | 例子 |
| --- | --- | --- |
| **可行性剪枝** | 当前已不可能满足条件，直接返回 | 组合总和里 `sum > target` 就 break（需先排序） |
| **去重剪枝** | 同一层跳过重复元素 | `if (i > start && nums[i] == nums[i-1]) continue;` |
| **数量剪枝** | 剩余元素不够凑够 k 个，提前停 | 组合：`i <= n - (k - path.size()) + 1` |

> **去重的关键是"树层去重"而非"树枝去重"**：先排序，然后 `i > start && nums[i] == nums[i-1]` 跳过——这保证同一层不选重复值，但同一条路径上的重复值仍可用。详见 [01 回溯模板与思想](01-回溯模板与思想.md)。
