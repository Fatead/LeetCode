# 00 学习路线与刷题方法论

> 这一章不讲算法，只讲**怎么刷题**。很多人的问题不是"不会算法"，而是"刷了 300 题还是不会"。看完这一章，你的刷题效率至少能翻一倍。

---

## 一、先把心态摆正

### 1.1 刷题不是背题

LeetCode 上 3000+ 道题，但**核心模板不超过 60 个**。比如：

- 「滑动窗口」「二分查找」「前缀和」「差分」——数组类的四大件
- 「二叉树三种遍历 + 后序位置」「回溯三步走」「DP 五步法」——各一个模板
- 「并查集」「拓扑排序」「Dijkstra」——图论三个模板

真正要背的是这 60 个模板，题目只是模板的不同包装。**看到题目第一反应应该是"这题套哪个模板"，而不是"这题我见过吗"。**

### 1.2 允许自己看题解

很多人有个错误的自尊心：「看题解就等于没做出来」。

正确的做法是分阶段：

| 阶段 | 单题思考时限 | 超时后怎么办 |
| --- | --- | --- |
| 新手（前 100 题） | 15 分钟 | 直接看题解，看懂后关掉题解默写一遍 |
| 进阶（100~300 题） | 30 分钟 | 看**思路**（不看代码），自己写 |
| 面试冲刺（300+） | 20 分钟 | 看最优解，对比自己的解法差在哪 |

**死磕 2 小时做出一道简单题，是最低效的学习方式。** 你需要的是在单位时间内见识足够多的模式。

### 1.3 「做过就忘」是正常的，解法只有重复

第一次做出某道题，大脑只是"临时记住"；要在 48 小时内、1 周后、1 个月后各重做一次，才会变成长期记忆。

本教程每章都有「**二刷清单**」，就是给这个节奏用的。

## 二、刷题方法论：五步法

拿到一道题，按下面五步走，形成肌肉记忆：

### 第 1 步：读题 + 手算样例（2 分钟）

不要跳过。**用纸笔把小样例手动算一遍**，这一步能暴露 80% 的边界问题。

> 例：`Two Sum`，`nums = [2,7,11,15], target = 9`
> 手算：2 + 7 = 9 ✓，答案 `[0,1]`。

### 第 2 步：确定题型，锁定模板（3 分钟）

问自己三个问题：

1. **输入是什么？** 数组 / 链表 / 树 / 图 / 字符串 / 矩阵？
2. **要求什么？** 计数 / 最值 / 是否存在 / 枚举所有方案 / 求方案数？
3. **规模多大？** 从 `n` 的范围倒推允许的时间复杂度。

这张表必须刻在脑子里（**这是全教程最重要的一张表**）：

| 输入规模 n | 允许的时间复杂度 | 应该想到的算法 |
| --- | --- | --- |
| ≤ 10 | `O(n!)`、`O(2^n)` | 回溯、全排列、暴力枚举 |
| ≤ 20 | `O(2^n)` | 状态压缩 DP、回溯 + 剪枝 |
| ≤ 100 | `O(n^4)` | 区间 DP、四重循环优化 |
| ≤ 500 | `O(n^3)` | Floyd、区间 DP |
| ≤ 5000 | `O(n^2)` | 线性 DP、双重循环 |
| ≤ 10^5 | `O(n log n)` | 排序、二分、堆、单调栈 |
| ≤ 10^6 ~ 10^7 | `O(n)` | 双指针、滑动窗口、前缀和、哈希 |
| ≥ 10^8 | `O(log n)`、`O(1)` | 数学、快速幂、位运算 |

> **反推技巧**：如果 `n ≤ 10^5`，你写出 `O(n^2)` 就是错的，直接想 `O(n log n)`；如果 `n ≤ 20`，那基本就是状压或回溯。

### 第 3 步：写出暴力解法（5 分钟）

**永远从暴力开始。** 理由有三：

1. 暴力解法保证你能 AC（哪怕超时），心里有底
2. 暴力解法往往直接暴露**冗余计算在哪**，优化的方向就是消除冗余
3. 面试时先讲暴力再讲优化，是加分项

> 仓库里的实战示范：[src/array/ThreeNum.java](../src/array/ThreeNum.java) 里同时保留了 `threeSum2`（三重循环暴力，注释写着"超出时间限制"）和 `threeSum`（排序 + 双指针）。**把两个版本放在一个文件里对比，是这个仓库最好的学习习惯之一。**

### 第 4 步：找冗余，逐步优化（15 分钟）

优化的四个常用方向：

| 方向 | 手段 | 例子 |
| --- | --- | --- |
| 消除重复枚举 | 排序 + 双指针 | 三数之和：`O(n^3)` → `O(n^2)` |
| 空间换时间 | 哈希表 | 两数之和：`O(n^2)` → `O(n)` |
| 复用子问题结果 | 记忆化 / DP | 爬楼梯：`O(2^n)` → `O(n)` |
| 利用单调性 | 单调栈 / 单调队列 | 滑动窗口最大值：`O(nk)` → `O(n)` |

### 第 5 步：AC 之后必须做的三件事（5 分钟）

大部分人在这一步就跑了，但**这三件事才是真正的学习**：

1. **看别人的最优解**。排序区第一个解法往往是神仙写法，学会它。
2. **写一句话总结**，格式：`这题是【模板名】，关键突破点是【XXX】，边界是【XXX】`。
   > 例：`三数之和是【排序+双指针】，关键突破点是固定第一个数后退化成两数之和，边界是去重时 nums[i]==nums[i-1] 要 continue。`
3. **记录到错题本**（见下文）。

## 三、错题本怎么记

不需要花哨的工具，一个 Markdown 文件就够。每道题记三行：

```markdown
## 3. 无重复字符的最长子串（滑动窗口） 2024-03-15
- 思路：右指针扩张，出现重复就移动左指针；用 map 记录字符最后位置
- 卡点：写成 while 里 left++ 会退化 O(n^2)，应该直接 left = max(left, map[c]+1)
- 结论：滑动窗口的"收缩条件"是判断难点，牢记"窗口内始终满足题设"
```

**关键点**：写「**卡点**」比写「思路」重要 100 倍。下次复习时你只需要看卡点。

## 四、学习路线（16 周计划）

### 4.1 分阶段目标

| 阶段 | 周次 | 目标 | 目标题量 | 达成标准 |
| --- | --- | --- | --- | --- |
| **入门** | 第 1~3 周 | 建立模板感 | 90 题 | 能独立做出 Easy 题，Medium 题 30 分钟内出思路 |
| **专题突破** | 第 4~10 周 | 逐个攻破专题 | 150 题 | 看到题能说出所属模板，Medium 题稳定 AC |
| **综合提升** | 第 11~14 周 | 混合刷题 + Hard | 80 题 | Hard 题能想出框架，Medium 题 20 分钟内 AC |
| **面试冲刺** | 第 15~16 周 | 高频题 + 模拟面 | 50 题 | 白板/共享屏幕能边写边讲 |

**总计约 370 题**。不要贪多，**一题顶三题（做透）> 三题各做一遍**。

### 4.2 各阶段题目分配

#### 第 1~3 周：入门（90 题）

按这个顺序刷，**不要跳**：

| 顺序 | 专题 | 题量 | 对应章节 |
| --- | --- | --- | --- |
| 1 | 数组基础 + 双指针 | 25 | [01 数组与双指针](01-数组与双指针/README.md) |
| 2 | 哈希表 | 15 | [02 哈希表](02-哈希表/README.md) |
| 3 | 链表 | 15 | [03 链表](03-链表/README.md) |
| 4 | 字符串 | 10 | [04 字符串](04-字符串/README.md) |
| 5 | 栈与队列 | 10 | [05 栈与队列](05-栈与队列/README.md) |
| 6 | 二分查找 | 15 | [01.3 二分查找](01-数组与双指针/03-二分查找.md) |

**这一阶段的口号**：**简单题要求"一次过"**，包括边界、包括空输入。不要把简单题做错。

#### 第 4~10 周：专题突破（150 题）

| 周 | 专题 | 题量 | 对应章节 |
| --- | --- | --- | --- |
| 4 | 递归与分治 | 15 | [06 递归与分治](06-递归与分治/README.md) |
| 5 | 回溯 | 25 | [07 回溯与搜索](07-回溯与搜索/README.md) |
| 6 | 贪心 | 15 | [08 贪心](08-贪心/README.md) |
| 7~8 | 动态规划 | 40 | [09 动态规划](09-动态规划/README.md) |
| 9 | 树 | 35 | [10 树](10-树/README.md) |
| 10 | 图与并查集 | 20 | [11 图与并查集](11-图与并查集/README.md) |

**这一阶段的口号**：**每个专题先抄模板，再做题**。不抄模板直接做题，等于重新发明轮子。

#### 第 11~14 周：综合提升（80 题）

- 按「公司高频题」列表刷（LeetCode 会员有，免费替代：[16 附录](16-附录/README.md)）
- 每天 1 道 Hard，重点练**思路拆解**，不要求独立写出全部细节
- 每周做一次**限时模拟**：2 道 Medium + 1 道 Hard，60 分钟

#### 第 15~16 周：面试冲刺（50 题）

- 只刷高频题，每道题要求：**5 分钟讲清思路 + 20 分钟 bug-free 写出**
- 练习**口述**：边写边说"这里我用哑结点是为了避免头结点被删除的特判"
- 复习错题本

### 4.3 每天的时间分配（以每天 2 小时为例）

```
20 分钟   复习昨天的错题（重做，不看答案）
70 分钟   做新题 2~3 道（含看题解、默写）
20 分钟   总结：写一句话结论 + 记错题本
10 分钟   阅读即将进入的专题的模板（预习）
```

> **注意**：复习旧题的时间不能少于 20%。新手最爱犯的错就是"只做新题不复盘"。

## 五、面试中的解题流程

面试和刷题最大的区别：**你要说话**。推荐这套流程：

```
1. 复述题目，确认理解          ("我理解是……，对吗？")
2. 确认边界和约束              ("数组会有重复元素吗？n 的范围是多少？")
3. 手算一个小例子              ("我用 [2,7,11,15] 走一遍")
4. 说暴力解 + 复杂度           ("最直接是两重循环，O(n^2)")
5. 提优化方向，征询同意        ("我可以用哈希表把查找降到 O(1)，这样可以吗？")
6. 写代码，边写边解释          ("这里我定义 left 和 right 两个指针……")
7. 用样例手动跑一遍代码        ("代入样例：第一轮 left=0, right=3 ...")
8. 主动分析复杂度和边界        ("时间 O(n)，空间 O(n)；空数组返回 []")
```

**加分项**：

- 主动提边界（空输入、单元素、全相同、溢出）
- 写出代码后主动说「这里其实有个变量命名可以更好」——展示 code review 意识
- 卡住时说「我先写一个能跑的版本，再优化」——不要沉默

**减分项**：

- 拿到题就开始写，不沟通
- 写完不测样例就说「好了」
- 用 `Integer.MAX_VALUE` 时不说溢出风险

## 六、常见误区清单

| 误区 | 后果 | 正确做法 |
| --- | --- | --- |
| 只按题号顺序刷 | 前 100 题全是简单模拟，学不到套路 | 按专题刷 |
| 追求题量 | 300 题全是"看一眼题解就过" | 每道题要求能默写 |
| 不做 Hard | 面试 Hard 直接放弃 | 每周 1 道 Hard，练思路即可 |
| 不看最优解 | 一直用 `O(n^2)` 混过 Medium | AC 后必看排序区第一个解法 |
| 不做旧题 | 一周后忘光 | 严格遵守 48 小时 / 1 周 / 1 月 复刷节奏 |
| 一上来就追求最优解 | 卡死，浪费时间 | 先写暴力，再优化 |
| 不开编译器，纯手写 | 面试时语法报错 | 平时就在 IDE 里写（本仓库就是 IDEA 工程） |

## 七、本仓库的使用方式

本仓库是一个 **IntelliJ IDEA 工程**（见 [leetcode.iml](../leetcode.iml)），`src` 是源码根目录，每个知识点一个包，每个文件一道题，**都带 `main` 方法可以直接运行**。

### 7.1 编译运行单道题

```bash
# 在仓库根目录
javac -d out src/array/ThreeNum.java
java -cp out array.ThreeNum
```

### 7.2 在 IDEA 里刷题的正确姿势

1. `src` 下新建一个包（比如 `src/myPractice`）
2. 从 LeetCode 复制类名 → 新建文件 → 粘贴模板
3. 在 `main` 里造样例，本地跑通再提交到 LeetCode
4. **保留失败/暴力的解法**，加注释说明为什么慢（参考 [src/array/ThreeNum.java](../src/array/ThreeNum.java) 的 `threeSum2`）

### 7.3 教程与代码如何配合

- **不想看长文** → 只看每章的「Java 通用模板」+ [16 附录](16-附录/README.md)
- **想深入理解** → 读每章的「核心思想」和「为什么这样写」
- **想练手** → 每章末尾有「练习题单」，直接去 LeetCode 搜题号
