# 03 背包问题

> **一句话理解**：背包问题是"**从一堆物品里选，使总价值最大/方案数最多**"。记住两条铁律就够用了：**0-1 背包内层逆序、完全背包内层正序；求组合先遍历物品、求排列先遍历容量。**

---

## 一、背包问题全景图

| 类型 | 每个物品 | 典型问法 | 内层遍历方向 |
| --- | --- | --- | --- |
| **0-1 背包** | 只能选 0 或 1 次 | 能否装满 / 最大价值 | 容量**逆序** |
| **完全背包** | 可选无限次 | 凑出方案数 / 最少个数 | 容量**正序** |

**为什么内层方向不同？** 用一维 `dp` 时：
- **0-1 背包逆序**：保证 `dp[j]` 用的是"上一轮（没放当前物品）"的值，每个物品只被考虑一次。
- **完全背包正序**：允许 `dp[j]` 用"本轮（已放过当前物品）"的值，所以同一个物品能被重复选。

这是背包问题**最核心、最易错**的一个点，务必理解而非死记。

---

## 二、0-1 背包模板

**问题**：`n` 件物品，第 `i` 件重 `weight[i]`、值 `value[i]`，背包容量 `W`，每件最多选一次，求最大总价值。

### 2.1 二维 dp（易理解）

```java
int[][] dp = new int[n + 1][W + 1];        // dp[i][j] = 前 i 件、容量 j 的最大价值
for (int i = 1; i <= n; i++)
    for (int j = 0; j <= W; j++) {
        dp[i][j] = dp[i - 1][j];                       // 不选第 i 件
        if (j >= weight[i - 1])                        // 容量够才能选
            dp[i][j] = Math.max(dp[i][j], dp[i - 1][j - weight[i - 1]] + value[i - 1]);
    }
return dp[n][W];
```

### 2.2 一维滚动（面试首选）

```java
int[] dp = new int[W + 1];                 // dp[j] = 容量 j 的最大价值
for (int i = 0; i < n; i++)
    for (int j = W; j >= weight[i]; j--)   // ★ 逆序！保证每件只选一次
        dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
return dp[W];
```

**逆序的直觉**：如果正序，`dp[j - weight[i]]` 可能已经包含了"本轮刚放进去的第 `i` 件"，于是第 `i` 件被放了两次——这就违背了 0-1 背包"每件最多一次"的规则。逆序时 `dp[j - weight[i]]` 一定还是上一轮的旧值。

## 三、0-1 背包应用

### 3.1 分割等和子集（416 题）

**问题**：能否把数组分成两个和相等的子集？等价于"**能否从数组选出若干数，恰好凑成 `sum/2`**"——这就是容量为 `sum/2` 的 0-1 背包（物品重量 = 价值 = 元素值，问能否装满）。

```java
boolean canPartition(int[] nums) {
    int sum = 0;
    for (int x : nums) sum += x;
    if (sum % 2 != 0) return false;        // 和为奇数，不可能平分
    int target = sum / 2;
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;                          // 容量 0 恒可装满（什么都不选）
    for (int x : nums)
        for (int j = target; j >= x; j--)  // 0-1 背包逆序
            dp[j] = dp[j] || dp[j - x];
    return dp[target];
}
```

*分割等和子集是【0-1 背包的"能否装满"版】，关键突破点是【转化为"能否选出子集凑成 sum/2"】，边界是【和为奇数直接 false，dp[0]=true】。*

### 3.2 其他 0-1 背包题

- **目标和（494 题）**：加正负号凑成 target，转化为求"正数子集和 = (sum+target)/2"的方案数。
- **最后一块石头的重量 II（1049 题）**：把石头分两堆使差最小，转化为"尽量凑接近 `sum/2`"。

## 四、完全背包模板

把 0-1 背包的内层逆序改成**正序**，就是完全背包（物品可无限选）：

```java
int[] dp = new int[W + 1];
for (int i = 0; i < n; i++)
    for (int j = weight[i]; j <= W; j++)   // ★ 正序！允许重复选同一物品
        dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
return dp[W];
```

## 五、完全背包应用：组合 vs 排列（最易混）

**这是背包问题的第二个核心难点**：遍历物品和遍历容量的先后顺序，决定了算的是"组合数"还是"排列数"。

### 5.1 零钱兑换 II（518 题）：求组合数

**问题**：用 `coins` 凑出 `amount`，每种硬币无限个，求**组合数**（`[1,2]` 和 `[2,1]` 算同一种）。

```java
int change(int amount, int[] coins) {
    int[] dp = new int[amount + 1];
    dp[0] = 1;                             // 凑出 0 元有 1 种方法（什么都不拿）
    for (int coin : coins)                 // ★ 外层物品，内层容量 → 组合数
        for (int x = coin; x <= amount; x++)
            dp[x] += dp[x - coin];
    return dp[amount];
}
```

> 参考实现：[src/dp/ChangeCoins.java](../../src/dp/ChangeCoins.java)（仓库实现与此一致）

**为什么外层物品 = 组合数？** 因为先固定硬币种类的加入顺序（先考虑完所有用 `coin1` 的情况，再加 `coin2`），每种组合只会按"硬币从小到大"的固定顺序被统计一次，不会出现 `[1,2]` 和 `[2,1]` 重复。

### 5.2 组合总和 IV（377 题）：求排列数

**问题**：同样凑 `target`，但 `[1,2]` 和 `[2,1]` 算**不同**方案（求排列数）。

```java
int combinationSum4(int[] nums, int target) {
    int[] dp = new int[target + 1];
    dp[0] = 1;
    for (int x = 1; x <= target; x++)      // ★ 外层容量，内层物品 → 排列数
        for (int num : nums)
            if (x >= num) dp[x] += dp[x - num];
    return dp[target];
}
```

**一张表记死组合与排列**：

| 求什么 | 遍历顺序 | 记忆口诀 |
| --- | --- | --- |
| **组合数**（不计顺序） | 外层物品、内层容量 | "物品在外，顺序被固定" |
| **排列数**（计顺序） | 外层容量、内层物品 | "容量在外，每一步都能选任意物品" |

## 六、零钱兑换（322 题）：求最少硬币数

**问题**：凑出 `amount` 的**最少硬币个数**（凑不出返回 -1）。这是完全背包求最值，**内外层顺序无所谓**（因为求的是个数最小，和组合/排列顺序无关）：

```java
int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);           // 初始化为"不可能"的大值
    dp[0] = 0;                             // 凑 0 元需要 0 个硬币
    for (int coin : coins)
        for (int x = coin; x <= amount; x++)
            dp[x] = Math.min(dp[x], dp[x - coin] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
```

**为什么初始化为 `amount+1`？** 它比任何可能的真实答案（最多 `amount` 个 1 元硬币）都大，相当于"正无穷"，最后若没被更新过就说明凑不出，返回 -1。

> 仓库里 [src/dp/MinTotal.java](../../src/dp/MinTotal.java) 是"三角形最小路径和（120 题）"，不是本题；零钱兑换最少个数版可按上面的标准模板练习。

*零钱兑换是【完全背包求最值】，关键突破点是【`dp[x]=min(dp[x], dp[x-coin]+1)`，初始化为不可达大值】，边界是【dp[0]=0，最终 `dp[amount]` 没被更新则返回 -1】。*
