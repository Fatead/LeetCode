# 04 表达式与解析

> **一句话理解**：所有"表达式求值 / 字符串解析"题都是**在栈上模拟一个有限状态机**——栈保存"还没被满足的上下文"（待匹配的括号、待重复的次数、待回溯的目录），指针一次扫描完成解析。

---

## 一、什么时候能用栈做解析

### 判定标准

| 题目结构 | 该用什么 | 举例 |
| --- | --- | --- |
| **后缀表达式**（操作符在操作数后） | 一个数字栈，见操作符就弹两个算一个 | 150 |
| **中缀表达式**，只有 `+ -` 和括号 | 数字栈 + 符号栈 / 结果变量 + 符号变量 | 224 |
| **中缀表达式**，含 `* /` 优先级 | 符号栈结算优先级，或"遇到运算符才算上一个数" | 227 |
| **重复结构** `k[...]`、嵌套方括号 | 两个栈：次数栈 + 字符串栈 | 394 |
| **路径 / 层级**，`..` 表示回退 | 一个字符串栈模拟目录 | 71 |
| **标签 / 配对**，`<A>...</A>` 必须匹配 | 一个栈存标签名 | 591 |
| **需要"遇到错误就报错"** | 递归下降（`expr → term → factor`） | 385、726 |

### 什么时候**不能**用

| 场景 | 为什么不行 | 该用什么 |
| --- | --- | --- |
| 表达式有**变量 / 赋值 / 函数调用** | 单次扫描的栈模型不够表达符号表 | 递归下降 + 作用域栈 |
| 需要**运算符优先级 + 右结合**（如 `^`） | 用 `>=` 出栈要改成 `>` | 调整优先级比较方向 |
| 需要**语法树**而不只是求值 | 栈求出的是值，丢掉了树结构 | 递归下降 / Shunting-yard 输出 AST |
| 超长表达式且需要**任意精度** | `int` 溢出 | `BigInteger` / 手写高精度 |

### 两套主流方法对比

| | 双栈（Shunting-yard） | 符号变量 + 栈（推荐） |
| --- | --- | --- |
| 空间 | 两个栈，`O(n)` | 一个栈，`O(n)` |
| 代码量 | 多（要写优先级表、出栈循环） | 少（一个 `switch`） |
| 支持括号 | 要额外处理 | 天然支持（把括号当"保存现场"） |
| 支持一元负号 | 要额外判断 | 天然支持 |
| 适合场景 | 需要生成后缀表达式/AST | LeetCode 224/227 求值 |

**结论：LeetCode 上求值优先用"符号变量 + 栈"，生成表达式才用双栈。**

## 二、解析类问题的通用状态机思路

任何解析题都可以这样拆解：

```
① 状态：我"当前正在处理"什么？
     —— 一个数？一段文本？一个刚读到的运算符？

② 上下文栈：哪些信息"内层处理完后外层还需要"？
     —— 括号外的结果与符号、重复次数、上一层字符串、上一层标签名

③ 转移：读到每种字符时做什么？
     数字  → 累加到"当前数"
     运算符 → 结算"当前数"到栈/结果，记下新运算符
     左括号 → 把"外层上下文"压栈，重置当前状态
     右括号 → 用栈顶上下文合并"内层结果"

④ 收尾：循环结束后还有没有"没结算完的当前状态"？
     —— 最后一个数字、没闭合的括号
```

**第 ④ 步是最高频的漏写点**：中缀求值写到最后，最后一个数字还没被"运算符触发结算"，必须补一次。

## 三、Java 通用模板

### 3.1 模板 A：后缀表达式求值

```java
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * 后缀（逆波兰）表达式求值
 *
 * 后缀表达式的优势：不需要括号、不需要优先级表，一次左到右扫描即可。
 * 规则：遇到数字压栈；遇到运算符弹出栈顶两个数，算完再压回去。
 */
public int evalRPN(String[] tokens) {
    Deque<Integer> stack = new ArrayDeque<>();

    for (String t : tokens) {
        switch (t) {
            case "+": {
                int b = stack.pop();      // ★ 第一个弹出的是右操作数
                int a = stack.pop();
                stack.push(a + b);
                break;
            }
            case "-": {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a - b);        // ★ 顺序不能反！是 a - b
                break;
            }
            case "*": {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a * b);
                break;
            }
            case "/": {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a / b);        // ★ Java 整数除法向 0 截断，正好符合题目
                break;
            }
            default:
                stack.push(Integer.parseInt(t));   // 负数、多位数都能直接解析
        }
    }
    return stack.pop();                        // 最后栈里只剩一个数
}
```

#### 关键点解释

**① 为什么 `int b = stack.pop(); int a = stack.pop();` 而不写成一行？**

因为 `int a = stack.pop(), b = stack.pop();` 的求值顺序是从左到右，会让 `a` 拿到**栈顶**（右操作数），语义反了。**分两行写，变量名自解释，最不容易错。**

**② 为什么减法/除法必须区分顺序？**

```
tokens = ["4", "2", "-"]     后缀对应中缀 4 - 2

压 4 → [4]
压 2 → [4, 2]        栈顶是 2
遇到 '-': b = 2（栈顶，右操作数）, a = 4（栈底，左操作数）
        a - b = 4 - 2 = 2 ✅

若写成 b - a：2 - 4 = -2 ❌
```

**③ 为什么不用手写字符串转数字？**

`Integer.parseInt("-4")` 直接支持负号和多位数。仓库 `ReversePolishNotation.java` 手写了一个 `StrToInt`，逻辑正确（也处理了 `-`），但**多了一份容易写错的代码**，且没处理 `+` 前缀和溢出。**推荐直接用 `Integer.parseInt`。**

**④ `switch` 里的 `{}` 能省吗？**

不能。Java 的 `switch` 里多个 `case` 共享作用域，若都声明 `int b`、`int a` 会**编译报错**（variable already defined）。**加花括号给每个 `case` 独立作用域**，这是 Java 的硬性要求。

**边界**：
- `tokens` 为空：题目保证合法输入，不会为空；若为空，最后 `stack.pop()` 会抛异常。可加 `if (tokens.length == 0) return 0;`
- 单个数字 `["7"]`：不进入任何 `case`，`default` 压栈，返回 7 ✅
- 溢出：题目保证结果在 `int` 范围内 ✅

### 3.2 模板 B：中缀表达式求值（支持 `+ - * /` 与括号）

```java
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * 中缀表达式求值模板
 *
 * 核心思路（"符号变量 + 栈"，比双栈短得多）：
 *   - res 表示【当前括号层】已经累加的结果
 *   - sign 表示【当前正在读的这个数】的符号
 *   - num 表示【当前正在读的数】
 *   - 遇到运算符：把 sign * num 结算进 res，然后更新 sign
 *   - 遇到 '('：把 (res, sign) 压栈（保存现场），然后 res = 0, sign = 1
 *   - 遇到 ')'：先结算最后一个 num，再取出栈里的现场合并
 *
 * 优先级技巧：+ 和 - 直接结算；* 和 / 立刻用栈顶的数算掉。
 */
public int calculate(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int res = 0;        // 当前层的结果
    int num = 0;        // 正在读的数
    int sign = 1;       // 正在读的数的符号：1 或 -1

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);

        if (Character.isDigit(c)) {
            num = num * 10 + (c - '0');          // ① 多位数：边读边累加
        } else if (c == '+' || c == '-') {
            res += sign * num;                    // ② 结算上一个数
            num = 0;
            sign = (c == '+') ? 1 : -1;           // ③ 记下新符号（这就是一元负号的来源）
        } else if (c == '(') {
            stack.push(res);                      // ④ 保存现场：外层结果
            stack.push(sign);                     //    保存现场：括号前的符号
            res = 0;
            sign = 1;
        } else if (c == ')') {
            res += sign * num;                    // ⑤ 结算括号内最后一个数
            num = 0;
            res *= stack.pop();                   //    乘上括号前的符号
            res += stack.pop();                   //    加上括号前的结果
        }
        // 空格：什么都不做（落在 else 外面自然跳过）
    }

    res += sign * num;                            // ★ ⑥ 收尾：最后一个数还没结算！
    return res;
}
```

#### 关键点解释

**① 为什么 `num = num * 10 + (c - '0')`？**

这是"边扫描边构造数字"的标准写法。`num * 10` 把已有数字左移一位，`+ (c - '0')` 加上新的一位。

```
s = "123"
i=0: num = 0*10 + 1 = 1
i=1: num = 1*10 + 2 = 12
i=2: num = 12*10 + 3 = 123
```

**②③ 为什么"遇到运算符才结算上一个数"？**

因为读取数字时我们还**不知道**它后面跟着什么。只有读到运算符（或到达末尾），才能确定"这个数读完了"，此时才能把它乘以符号累加进 `res`。**这是"延迟结算"思想，也正是第 ⑥ 步收尾必须存在的原因。**

**④ 括号处理为什么压的是 `(res, sign)` 而不是 `(res, num)`？**

因为括号内是一个**独立的子表达式**，它的结果需要乘上"括号前的符号"再加到"括号前的结果"上。

```
2 - (3 + 4)

到 '(' 时：res = 2, sign = -1（因为刚读到 '-'）
压栈：res=2, sign=-1
括号内：res = 3 + 4 = 7
到 ')' 时：
  res = 7
  res *= stack.pop()  → 7 * (-1) = -7
  res += stack.pop()  → -7 + 2 = -5  ✅
```

**顺序很重要：先弹出的必须是 `sign`（后压入的），再弹出的才是 `res`（先压入的）。** 这符合栈的 LIFO。

**⑤ 一元负号是怎么被自然处理的？**

```
-3 + 5

i=0 c='-': res += 1 * 0 = 0; num = 0; sign = -1
i=1 c='3': num = 3
i=2 c='+': res += -1 * 3 = -3; num = 0; sign = 1
i=3 c='5': num = 5
收尾: res += 1 * 5 = 2  ✅
```

**关键是 `res += sign * num` 在 `num = 0` 时是无害的**，所以开头的负号能顺利写进 `sign`，不需要任何特殊分支。同理 `-(...)`、`(-3)` 都能自然处理。

**⑥ 为什么收尾必须有 `res += sign * num`？**

```
s = "30"

循环中没有任何运算符触发结算！
若省略收尾：res 一直是 0，返回 0 ❌
加上收尾：res += 1 * 30 = 30 ✅
```

**这是中缀求值最高频的漏写。** 更隐蔽的情形：`"1+2"` —— `+` 结算了 1，但 2 从未被结算，没这行就返回 1。

**⑦ `*` 和 `/` 的优先级怎么处理？**

在上面这份模板里 `sign` 只可能是 `1`/`-1`，所以它实际处理不了 `* /`。要支持乘除，把 `sign` 换成"待应用的运算符"，并在乘除时**立刻**弹栈顶结算：

```java
public int calculate2(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int num = 0;
    char op = '+';                                 // 上一个运算符，初始视为 '+'

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (Character.isDigit(c)) {
            num = num * 10 + (c - '0');
        }
        // ★ 读到运算符 / 空格外的最后一个字符时，结算"上一个数"
        if ((!Character.isDigit(c) && c != ' ') || i == s.length() - 1) {
            switch (op) {
                case '+': stack.push(num); break;
                case '-': stack.push(-num); break;              // 减法 = 压入相反数
                case '*': stack.push(stack.pop() * num); break; // 乘法立刻算掉
                case '/': stack.push(stack.pop() / num); break; // 除法立刻算掉
            }
            op = c;                                 // 记下当前运算符
            num = 0;
        }
    }
    int ans = 0;
    while (!stack.isEmpty()) {
        ans += stack.pop();                         // 剩下的全是加法
    }
    return ans;
}
```

**为什么 `* /` 要"立刻算掉"？** 因为它们优先级高，遇到它们时**左边那个数已经可以确定不会再有更高优先级的运算来结合它了**。而 `+ -` 要先压栈，因为后面可能跟一个 `*` 让右边的数先结合。

```
s = "3+2*2"

i=0 '3': num=3
i=1 '+': op='+'(初始) → push 3     stack=[3]      op='+'  num=0
i=2 '2': num=2
i=3 '*': op='+' → push 2           stack=[3,2]    op='*'  num=0
i=4 '2': num=2；i == len-1 → 结算
        op='*' → push(2 * 2 = 4)   stack=[3,4]
最后 ans = 3 + 4 = 7 ✅
```

**`switch` 里没有 `default` 会怎样？** `op` 初值是 `'+'`，且只在读到运算符时才更新，所以 `op` 永远是四个之一。但 `if` 的触发条件包含"`c` 是任意非空格非数字字符"（比如题目外的字符），保险起见可以加 `default: break;`。

### 4.2 LeetCode 227. 基本计算器 II

**题意**：计算只含 `+ - * /`、非负整数和空格的表达式，除法向 0 截断。

**思路（先暴力再优化）**：暴力是"先中缀转后缀再求值"（两个阶段，两套栈）。优化点是：**利用"乘除优先级高于加减"这一条，把问题压扁成"全是加法"**——遇到 `+`/`-` 就把数（带符号）压栈，遇到 `*`/`/` 就立刻和栈顶结算，最后把栈里所有数相加。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int calculate(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int num = 0;
    char op = '+';

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (Character.isDigit(c)) {
            num = num * 10 + (c - '0');
        }
        if ((!Character.isDigit(c) && c != ' ') || i == s.length() - 1) {
            switch (op) {
                case '+': stack.push(num); break;
                case '-': stack.push(-num); break;
                case '*': stack.push(stack.pop() * num); break;
                case '/': stack.push(stack.pop() / num); break;
                default: break;
            }
            op = c;
            num = 0;
        }
    }
    int ans = 0;
    while (!stack.isEmpty()) {
        ans += stack.pop();
    }
    return ans;
}
```

**易错点**：
- 触发条件必须包含 `i == s.length() - 1`，否则最后一个数不结算。
- `op` 必须初始化为 `'+'`，保证第一个数能被 `case '+': stack.push(num)` 处理。
- 表达式中数字**可能有多位**（如 `"123+456"`），必须用 `num = num * 10 + ...`。
- **减法不写 `stack.push(-num)` 而写 `stack.push(stack.pop() - num)` 也能过**（因为 `-` 和 `+` 是左结合、同优先级），但"压入相反数"更符合"把一切化成加法"的思路。
- `"14/3*2/4"` 这类**连续乘除**：`/` 立刻算，`*` 立刻算，保证左结合顺序。

```
s = "14/3*2/4"

i=0..1: num=14
i=2 '/': op='+'(初始) → push 14       stack=[14]      op='/'  num=0
i=3 '3': num=3
i=4 '*': op='/' → push(14/3 = 4)      stack=[4]       op='*'  num=0
i=5 '2': num=2
i=6 '/': op='*' → push(4*2 = 8)       stack=[8]       op='/'  num=0
i=7 '4': num=4；i == len-1 → 结算
        op='/' → push(8/4 = 2)        stack=[2]
ans = 2 ✅
```

> 参考实现：[src/number/Calculator2.java](../src/number/Calculator2.java)（**仓库版本**用"双栈 + 反向搬运 + 分两轮算乘除和加减"，**逻辑正确**（我逐个 case 推过 `"3+2*2"`、`"10-4"`、`"1-1+1"`、`"1*2*3"` 都对），但两级栈反转 + 三次重排让可读性很差，建议用上面的"单栈 + 符号变量"写法）

**复杂度**：时间 `O(n)`；空间 `O(n)`（最坏全是加减，栈装下所有数）。

*基本计算器 II 是【单栈 + 运算符变量 + 化归为加法】的模板，关键突破点是【乘除立刻与栈顶结算，加减压入带符号的数，最后统一求和就自动满足了优先级】，边界是【最后一个数要靠 i == len-1 触发结算；op 初值必须是 '+'】。*

### 4.3 LeetCode 224. 基本计算器

**题意**：计算含 `+ -`、括号、空格的表达式（**无乘除**），可能有**一元负号**。

**思路（先暴力再优化）**：暴力是递归地把括号内子串拿出来递归求值（要不断 `substring`，`O(n^2)`）。优化点是：**不递归、不切字符串，把"括号外的现场"压进栈**——这正是[模板 B](#32-模板-b中缀表达式求值支持----与括号)。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int calculate(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    int res = 0;      // 当前括号层的结果
    int num = 0;      // 正在读的数
    int sign = 1;     // 正在读的数的符号

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (Character.isDigit(c)) {
            num = num * 10 + (c - '0');
        } else if (c == '+' || c == '-') {
            res += sign * num;
            num = 0;
            sign = (c == '+') ? 1 : -1;
        } else if (c == '(') {
            stack.push(res);          // 先压外层结果
            stack.push(sign);         // 再压括号前的符号（后压先弹）
            res = 0;
            sign = 1;
        } else if (c == ')') {
            res += sign * num;        // 结算括号内最后一个数
            num = 0;
            res *= stack.pop();       // 先弹出的是 sign
            res += stack.pop();       // 后弹出的是外层 res
        }
        // c == ' ' → 什么都不做
    }
    res += sign * num;                // ★ 收尾
    return res;
}
```

**仓库版本对照**：`Calculator.java` 走的是**正统的双栈 Shunting-yard 路线**——先用「输出队列 + 符号栈」把中缀转成后缀，再用一个数字栈求值。它的优先级表 `priority()` 处理了 `+ - * /`，`(` 的优先级返回 `-1` 保证不会被 `)` 之外的运算符弹出，思路完全正确。

| 项 | 仓库 `Calculator.java` | 推荐版本 |
| --- | --- | --- |
| 路线 | 中缀 → 后缀 → 求值（两阶段） | 一次扫描直接求值 |
| 支持 `* /` | ✅ | ❌（要支持需改成 4.2 的写法） |
| 支持一元负号 | ❌（`"-3"` 会把 `-` 当二元运算符，栈里只有 1 个数时 `pop` 崩） | ✅ |
| 支持括号 | ✅ | ✅ |
| 代码量 | 约 70 行 | 约 35 行 |

**如果你要一份"既能处理 224 又能处理 227、还支持一元负号"的通用代码，就用递归下降**（见[第五节](#五递归下降解析简介)），别硬改双栈。

> 参考实现：[src/number/Calculator.java](../src/number/Calculator.java)（**仓库版本**：中缀转后缀双栈，正统但未处理一元负号）、[src/number/Calculator2.java](../src/number/Calculator2.java)（**仓库版本**：符号栈 + 数字栈，支持乘除但不支持括号）

### 4.4 LeetCode 394. 字符串解码

**题意**：`k[encoded_string]` 表示 `encoded_string` 重复 `k` 次，可任意嵌套，如 `3[a2[c]]` → `accaccacc`。

**思路（先暴力再优化）**：暴力是"找最内层括号 → 展开 → 重新扫描字符串"，每轮 `O(n)`，最坏 `O(n^2)`。优化点是：**一次扫描，把"外层已经攒好的字符串"和"当前重复次数"分别压栈，遇到 `]` 就一次性展开内层。**

```java
import java.util.ArrayDeque;
import java.util.Deque;

public String decodeString(String s) {
    Deque<Integer> countStack = new ArrayDeque<>();       // 每个 '[' 对应的重复次数
    Deque<StringBuilder> strStack = new ArrayDeque<>();   // 每个 '[' 之前的已积累字符串
    StringBuilder cur = new StringBuilder();              // 当前层正在积累的字符串
    int count = 0;                                        // 正在读的重复次数（可能多位）

    for (char c : s.toCharArray()) {
        if (Character.isDigit(c)) {
            count = count * 10 + (c - '0');               // ① 次数可能多位：100[leetcode]
        } else if (c == '[') {
            countStack.push(count);                       // ② 保存现场
            strStack.push(cur);
            cur = new StringBuilder();                    // 新的一层从空串开始
            count = 0;
        } else if (c == ']') {
            int k = countStack.pop();
            StringBuilder prev = strStack.pop();          // ③ 取回外层已攒的字符串
            for (int i = 0; i < k; i++) {
                prev.append(cur);                         // 展开内层 k 次接到外层后面
            }
            cur = prev;                                   // ④ 当前层变成合并后的结果
        } else {
            cur.append(c);                                // 普通字母：直接追加
        }
    }
    return cur.toString();
}
```

**为什么 `strStack` 存 `StringBuilder` 而不是 `String`？**

因为展开时要 `prev.append(cur)` 反复追加。如果存 `String`，每次 `+=` 都会新建对象，`k` 次展开就产生 `O(k)` 个中间字符串。存 `StringBuilder` 让展开是**原地追加**，总复杂度保持 `O(输出长度)`。

**为什么 `count` 必须在 `[` 之后清零？**

```
s = "3[a]2[bc]"

i=0 '3': count = 3
i=1 '[': countStack=[3], strStack=[""], cur="", count=0   ← 必须清零
i=2 'a': cur = "a"
i=3 ']': k=3, prev="" → prev = "aaa" → cur = "aaa"
i=4 '2': count = 2                                        ← 若没清零，这里会变成 32！
i=5 '[': countStack=[2], strStack=["aaa"], cur="", count=0
i=6 'b': cur = "b"
i=7 'c': cur = "bc"
i=8 ']': k=2, prev="aaa" → prev = "aaabcbc" → cur = "aaabcbc"
返回 "aaabcbc" ✅
```

**嵌套是怎么工作的？** 每遇到一个 `[` 就压一层"外层现场"，遇到 `]` 就弹一层并合并。栈深度 = 嵌套深度。

```
s = "3[a2[c]]"

i=0 '3': count=3
i=1 '[': push(3) / push("")        countStack=[3]      strStack=[""]        cur=""
i=2 'a': cur="a"
i=3 '2': count=2
i=4 '[': push(2) / push("a")       countStack=[3,2]    strStack=["","a"]    cur=""  count=0
i=5 'c': cur="c"
i=6 ']': k=2, prev="a" → prev="acc" → cur="acc"
i=7 ']': k=3, prev="" → prev="accaccacc" → cur="accaccacc"
返回 "accaccacc" ✅
```

**边界**：
- `s = ""`：返回 `""` ✅
- `s = "abc"`（无括号）：`cur` 直接攒成 `"abc"` ✅
- `k` 是多位（`100[leetcode]`）：靠 `count = count * 10 + ...` ✅
- `]` 之后的字母（如 `"2[a]b"`）：`cur = "a"`... 等等，`]` 时 `cur = "aa"`，然后 `'b'` 追加 → `"aab"` ✅

**仓库版本对照**：`DecodeString.java` 用了类似的 `countStack` + `strStack`，但因引入了 `tempStr` 和 `result` 两个额外变量、且靠 `if(s.charAt(s.length()-1) != ']')` 来收尾，**在 `"2[a]b"` 这类"括号后又跟内容"的输入上会出问题**（`]` 之后没有 `[` 时 `tempStr` 与外层字符串的拼接依赖 `strStack` 非空，逻辑分支过多）。推荐上面这份无收尾特判的版本。

> 参考实现：[src/string/DecodeString.java](../src/string/DecodeString.java)

**复杂度**：时间 `O(m)`（`m` 是展开后的总长度，每个字符只被追加常数次）；空间 `O(m)`（结果 + 栈）。

*字符串解码是【双栈保存现场】的模板，关键突破点是【`[` 时同时压入"次数"和"外层已攒字符串"，`]` 时弹栈并原地 append 展开】，边界是【次数可能多位要清零；`strStack` 必须存 StringBuilder 避免重复拷贝】。*

### 4.5 LeetCode 71. 简化路径

**题意**：把 Unix 风格路径化简——`/` 合并、`.` 跳过、`..` 回退一级、结果以 `/` 开头且不以 `/` 结尾。

**思路**：`..` 的语义是"回退到上一个目录"，这是**标准的后进先出**——用栈。按 `/` 切分后逐个处理，栈里就是最终的目录列表。

```java
import java.util.LinkedList;

public String simplifyPath(String path) {
    // 用 LinkedList 当栈：末尾是栈顶，迭代顺序天然是栈底→栈顶
    LinkedList<String> stack = new LinkedList<>();

    for (String part : path.split("/")) {
        if (part.isEmpty() || part.equals(".")) {
            continue;                       // "" (连续斜杠) 和 "." 都跳过
        }
        if (part.equals("..")) {
            if (!stack.isEmpty()) {
                stack.removeLast();         // ★ 只有非空才回退，根目录的 .. 是无效操作
            }
        } else {
            stack.addLast(part);            // 普通目录名入栈
        }
    }

    if (stack.isEmpty()) {
        return "/";                         // 根目录
    }
    StringBuilder sb = new StringBuilder();
    for (String dir : stack) {              // ★ LinkedList 迭代 head→tail = 栈底→栈顶
        sb.append('/').append(dir);
    }
    return sb.toString();
}
```

**为什么"根目录的 `..` 是无效操作"？**

```
path = "/../"     期望返回 "/"

split("/") → ["", "..", ""]
  ""  → 跳过
  ".." → 栈空，什么都不做（不能弹，否则空栈异常）
  ""  → 跳过
栈空 → 返回 "/" ✅
```

**为什么结果不以 `/` 结尾？** 因为我们是"每个目录前加一个 `/`"，最后一个目录后面自然没有 `/`。

```
栈 = ["home", "user"]（栈底→栈顶）
迭代拼接："/home" → "/home/user" ✅
```

**⚠️ 坑：用 `ArrayDeque` 当栈时不能直接 `for` 迭代！**

```java
Deque<String> dq = new ArrayDeque<>();
dq.push("home");     // push = addFirst，所以 head 是 "home"（栈顶）
dq.push("user");     // head 是 "user"
for (String s : dq) {
    // 迭代顺序是 head → tail，即 "user", "home" —— 栈顶到栈底，顺序反了！
}
// 正确做法：用 dq.descendingIterator()（tail → head）
```

**这就是为什么本题推荐用 `LinkedList` 当栈**：`LinkedList` 的 `addLast/removeLast` 是栈操作，而它的迭代器是 `head → tail`，正好等于栈底 → 栈顶，天然正确。**用 `Deque` 时要么改用 `descendingIterator()`，要么出栈时再 `reverse`。**

**边界**：
- `path = "/"`：`split` 得到 `[""]`，全部跳过，栈空 → `"/"` ✅
- `path = "/..."`：`"..."` 是合法目录名（不是 `..`），入栈 → `"/..."` ✅
- `path = "/a/./b/../../c/"`：处理完是 `["c"]` → `"/c"` ✅
- `path = "/home//foo/"`：连续斜杠产生空串，跳过 → `"/home/foo"` ✅

> 参考实现：[src/stack/SimplifyPath.java](../src/stack/SimplifyPath.java)（**仓库版本**用 `Stack<String>` + `get(i)` 顺序访问，结果正确；但 `ans.append("/" + pathStack.get(i))` 里的 `"/" + ...` 每次都会新建字符串，应写成 `ans.append('/').append(pathStack.get(i))`）

**复杂度**：时间 `O(n)`（`split` 一次 + 一次遍历）；空间 `O(n)`（栈 + `split` 结果数组）。

*简化路径是【字符串栈模拟文件系统】的模板，关键突破点是【`..` 就是 pop，`.` 和空串就是 skip，栈里剩下的就是最终目录序列】，边界是【栈空时 `..` 必须忽略；用 Deque 当栈时迭代顺序是栈顶→栈底，要反转】。*

### 4.6 LeetCode 591. 标签验证器

**题意**：验证一段代码是否由合法的标签组成。规则：整个 code 必须被**恰好一个**闭合标签包裹；标签名是 1~9 个大写字母；`<![CDATA[...]]>` 内部内容原样保留、可含任意字符（包括 `<`）。

**思路（先暴力再优化）**：暴力是正则匹配 + 递归，规则一多变就写不动。优化点是：**`<` 开头只有两种可能（开始标签 / 结束标签 / CDATA），用一个指针从左到右分情况处理，配一个栈存标签名。**

```java
import java.util.ArrayDeque;
import java.util.Deque;

public boolean isValid(String code) {
    if (code.isEmpty()) {
        return false;                             // 空串不是合法标签
    }
    Deque<String> stack = new ArrayDeque<>();
    int i = 0, n = code.length();

    while (i < n) {
        // ★ 根标签一旦闭合，后面就不允许再有内容（i > 0 排除开头）
        if (i > 0 && stack.isEmpty()) {
            return false;
        }

        if (code.startsWith("<![CDATA[", i)) {
            if (stack.isEmpty()) {
                return false;                     // CDATA 必须在标签内部
            }
            int j = code.indexOf("]]>", i);
            if (j < 0) {
                return false;                     // CDATA 未闭合
            }
            i = j + 3;                            // 整段当作纯文本跳过
        } else if (code.startsWith("</", i)) {
            int j = code.indexOf('>', i);
            if (j < 0) {
                return false;
            }
            String tag = code.substring(i + 2, j);
            if (stack.isEmpty() || !stack.peek().equals(tag)) {
                return false;                     // 没有对应的开始标签 / 名字不匹配
            }
            stack.pop();
            i = j + 1;
        } else if (code.charAt(i) == '<') {
            int j = code.indexOf('>', i);
            if (j < 0) {
                return false;
            }
            String tag = code.substring(i + 1, j);
            if (tag.length() < 1 || tag.length() > 9) {
                return false;                     // ① 名字长度 1~9
            }
            for (int k = 0; k < tag.length(); k++) {
                if (!Character.isUpperCase(tag.charAt(k))) {
                    return false;                 // ② 只能是大写字母
                }
            }
            stack.push(tag);
            i = j + 1;
        } else {
            if (stack.isEmpty()) {
                return false;                     // 标签外的普通文本非法
            }
            i++;                                  // 标签内的普通文本，跳过
        }
    }
    return stack.isEmpty();                       // ③ 所有标签都已闭合
}
```

#### 为什么这个分情况能覆盖全部规则

| 输入片段 | 进入的分支 | 校验点 |
| --- | --- | --- |
| `<![CDATA[ ... ]]>` | 分支 1 | 必须在标签内、必须有 `]]>` |
| `</TAG>` | 分支 2 | 必须有 `>`、必须与栈顶完全相等 |
| `<TAG>` | 分支 3 | 必须有 `>`、长度 1~9、全大写 |
| 普通字符 | 分支 4 | 必须在标签内部 |
| 循环结束 | 最后一行 | 栈必须为空 |

**为什么分支 1 要额外判 `stack.isEmpty()`？** 因为循环开头的 `i > 0 && stack.isEmpty()` 判断在 `i == 0` 时不生效。若输入直接以 `<![CDATA[` 开头（如 `"<![CDATA[abc]]>"`），那它**不构成合法的 code**（code 必须以开始标签打头），必须靠分支内的判空拦住。

**为什么分支 4 要判 `stack.isEmpty()`？** 拦住"根标签前有文本"（如 `"abc<A></A>"`）和"根标签后有文本"（如 `"<A></A>abc"`，其实循环开头的检查已经拦住了）两种情况。

**CDATA 为什么可以直接跳过？** 因为 CDATA 是**词法单元**，它的内容是原样的，不参与标签匹配。所以找到 `]]>` 后整段跳过，不解析其中任何 `<`。

```
code = "<A><![CDATA[</A>]]></A>"

i=0: '<' → 分支 3，tag = "A"（1 位大写 ✓）→ push → stack=["A"]，i=3
i=3: CDATA → j 指向 "]]>" 起点，i 跳到 CDATA 之后
     注意：CDATA 里的 "</A>" 被当成纯文本，不会弹栈！✅
i=...: '</' → tag = "A"，与栈顶匹配 → pop → stack=[]，i=n
返回 stack.isEmpty() = true ✅
```

**边界**：
- `""`：早退 `false` ✅（题目保证长度 ≥ 1，但防御性写法更稳）
- `"<A></A>"`：`true` ✅
- `"<A></A><B></B>"`：第一个 `</A>` 后 `stack` 空，下一轮循环开头 `i > 0 && isEmpty` → `false` ✅
- `"<A>"`：循环结束 `stack = ["A"]` → `false` ✅
- `"<A></B>"`：名字不匹配 → `false` ✅
- `"<AAAAAAAAAA></AAAAAAAAAA>"`：长度 10 → `false` ✅
- `"<a></a>"`：小写 → `false` ✅
- `"<A><B></B></A>"`：嵌套合法 → `true` ✅

> 参考实现：**仓库中没有本题实现（已用 `grep -r isValidTag src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：时间 `O(n)`（`indexOf` 的总推进量是 `O(n)`，不会反复回退；标签名检查的总长度也是 `O(n)`）；空间 `O(n)`（栈深度 = 嵌套深度）。

*标签验证器是【指针 + 栈的单遍词法扫描】的模板，关键突破点是【把 `<` 开头的情况分成"CDATA / 结束标签 / 开始标签"三支，CDATA 整段跳过不解析】，边界是【根标签闭合后不能再有内容；CDATA 和普通文本必须在标签内部；空串要早退】。*

## 五、递归下降解析简介

栈能求值，但**写规则更复杂的解析（带优先级、一元、函数调用、生成 AST）时，递归下降是最清晰的**。核心思想：**为语法里的每个非终结符写一个函数，函数之间互相调用。**

### 5.1 文法

```
expr   := term  (('+' | '-') term)*
term   := factor (('*' | '/') factor)*
factor := number | '(' expr ')'
```

**优先级体现在文法层次里**：`expr` 只处理 `+ -`，`term` 只处理 `* /`，`factor` 处理最小单元。层次越深绑定越紧。

### 5.2 代码

```java
class Parser {
    private final String s;
    private int pos = 0;

    Parser(String s) {
        this.s = s;
    }

    public int parse() {
        return expr();
    }

    /** expr := term (('+' | '-') term)* */
    private int expr() {
        int val = term();
        while (pos < s.length() && (s.charAt(pos) == '+' || s.charAt(pos) == '-')) {
            char op = s.charAt(pos++);
            int rhs = term();                 // ★ 递归调用 term，自然实现"先算乘除"
            val = (op == '+') ? val + rhs : val - rhs;
        }
        return val;
    }

    /** term := factor (('*' | '/') factor)* */
    private int term() {
        int val = factor();
        while (pos < s.length() && (s.charAt(pos) == '*' || s.charAt(pos) == '/')) {
            char op = s.charAt(pos++);
            int rhs = factor();
            val = (op == '*') ? val * rhs : val / rhs;
        }
        return val;
    }

    /** factor := number | '(' expr ')' */
    private int factor() {
        if (s.charAt(pos) == '(') {
            pos++;                            // 跳过 '('
            int val = expr();                 // ★ 括号内重新从最高层开始
            pos++;                            // 跳过 ')'
            return val;
        }
        int val = 0;
        while (pos < s.length() && Character.isDigit(s.charAt(pos))) {
            val = val * 10 + (s.charAt(pos++) - '0');
        }
        return val;
    }
}
```

### 5.3 调用轨迹

```
输入 "2*(3+4)"，pos 从 0 开始

parse() → expr()
  expr(): val = term()
    term(): val = factor()
      factor(): s[0]='2' 是数字 → val = 2，pos = 1
    term(): s[1]='*' → op='*'，pos = 2；rhs = factor()
      factor(): s[2]='(' → pos = 3；val = expr()
        expr(): val = term()
          term(): val = factor()
            factor(): s[3]='3' → val = 3，pos = 4
          term(): s[4]='+' 不是 * / → 返回 3
        expr(): s[4]='+' → op='+'，pos = 5；rhs = term()
          term(): val = factor()
            factor(): s[5]='4' → val = 4，pos = 6
          term(): s[6]=')' 不是 * / → 返回 4
        expr(): val = 3 + 4 = 7；s[6]=')' 不是 + - → 返回 7
      factor(): pos = 7，跳过 ')'
      返回 7
    term(): val = 2 * 7 = 14；pos = 7 == len → 返回 14
  expr(): pos == len → 返回 14
结果 14 ✅
```

### 5.4 递归下降 vs 栈：怎么选

| 维度 | 递归下降 | 栈（迭代） |
| --- | --- | --- |
| 可读性 | ★★★★★（文法和代码一一对应） | ★★★☆☆ |
| 加新语法 | 只加一个函数 / 一个分支 | 要改优先级表和出栈逻辑 |
| 栈溢出风险 | 有（嵌套极深时） | 无（手动栈在堆上） |
| 是否易加错误检查 | 容易（每个函数抛出具体错误） | 较难 |
| LeetCode 适用 | 385、726、770、1096 | 224、227、150、394 |

> **实战建议**：题目只要"求值"，优先写栈版（代码短、面试写得完）；一旦出现"自定义运算符优先级""函数调用""变量作用域"，立刻切递归下降。

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 逆波兰求值把 `pop` 顺序写反 | 减法和除法结果取反/取倒数 | 先弹出的是**右**操作数，`a = 第二个pop` |
| 逆波兰求值手写 `StrToInt` | 负号、多位数、溢出边界容易漏 | 直接用 `Integer.parseInt` |
| `switch` 多个 `case` 声明同名变量 | 编译报 "variable already defined" | 每个 `case` 加 `{}` 独立作用域 |
| 中缀求值最后一个数字不结算 | `"30"` 返回 0，`"1+2"` 返回 1 | 循环后补 `res += sign * num;` |
| `* /` 也压进符号栈等最后算 | 优先级错误，`3+2*2` 得 10 | 乘除立刻与栈顶结算 |
| 括号处理压栈顺序写反 | 结果错得离谱 | 先压 `res` 再压 `sign`；弹出时先 `sign` 后 `res` |
| 忘了处理多位数 | `"123"` 被当成 `1`、`2`、`3` | `num = num * 10 + (c - '0')` |
| 字符串解码用 `String` 存外层串 | 反复 `+=` 产生大量临时对象 | 存 `StringBuilder`，原地 `append` |
| 字符串解码 `count` 在 `[` 后不清零 | 下一次次数被拼成 `32` 这种 | `[` 分支里 `count = 0` |
| 简化路径用 `ArrayDeque` 直接 `for` 迭代 | 输出目录顺序颠倒 | 用 `LinkedList` 或 `descendingIterator()` |
| 简化路径空栈时执行 `..` | `NoSuchElementException` | 先判 `!stack.isEmpty()` |
| 标签验证器不检查"根标签后还有内容" | `"<A></A><B></B>"` 误判为合法 | 循环开头判 `i > 0 && stack.isEmpty()` |
| 标签验证器把 CDATA 内部当标签解析 | CDATA 里的 `<` 被误认成标签 | 遇到 `<![CDATA[` 直接跳到 `]]>` 之后 |
| 标签验证器不判空串 | `""` 返回 `true` | 开头 `if (code.isEmpty()) return false;` |
