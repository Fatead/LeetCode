# 01 栈与队列基础

> **一句话理解**：栈是"后进先出（LIFO）"，队列是"先进先出（FIFO）"——所有栈/队列题目的本质，都是**发现题目里藏着一种"后进先出"或"先进先出"的对称结构**，然后用它把嵌套/顺序关系一次扫完。

---

## 一、什么时候能用栈 / 队列

栈和队列本身不是"算法"，它们是**用来保存"还没处理完的东西"的容器**。所以判断标准不是"题目像不像栈"，而是：

| 信号 | 该用什么 | 为什么 |
| --- | --- | --- |
| 出现**配对**：括号、标签、引号 | 栈 | 最后一个左括号必须最先被右括号匹配 —— 典型的后进先出 |
| 出现**嵌套结构**：`( () () )`、表达式求值 | 栈 | 内层先算完，外层才知道结果 |
| 需要**抵消/消除**相邻相同项 | 栈（或当栈用的 `StringBuilder`） | 新元素和"最近的未消除元素"比较 |
| 需要**撤销/回退**最近一步 | 栈 | 最近的操作最先被撤销 |
| 处理顺序必须**和输入顺序一致**（BFS、层序） | 队列 | 先入队先出队 |
| 需要**固定容量 / 先进先出**的缓冲区 | 队列（循环队列） | 队列天然按时间顺序 |
| 需要**在滑动过程中取最值** | 单调队列（见 [03 单调队列](03-单调队列.md)） | 队列 + 单调性 |
| 需要**下一个更大/更小元素** | 单调栈（见 [02 单调栈](02-单调栈.md)） | 栈 + 单调性 |

### 什么时候**不能**用

| 场景 | 为什么不行 | 该用什么 |
| --- | --- | --- |
| 需要按**值的大小**取最小/最大 | 栈/队列只认顺序，不认大小 | 优先队列（见 [05 优先队列](05-优先队列与设计题.md)） |
| 需要**随机访问**中间元素 | 只能访问栈顶/队首队尾 | 数组 / 哈希表 |
| 需要**按出现次数**排序输出 | 顺序信息不够 | 哈希 + 排序/桶 |
| 括号匹配但允许 `*` 当通配符 | 单栈无法处理"两种可能的匹配" | 双栈记下标（如 678，仓库 `ValidString.java`） |

## 二、Java 语言基本功：请用 `Deque`，不要用 `Stack`

### 2.1 为什么不推荐 `java.util.Stack`

```java
// ❌ 能跑，但不推荐
Stack<Integer> stack = new Stack<>();
```

| 问题 | 说明 |
| --- | --- |
| 继承自 `Vector` | 每个方法都加 `synchronized`，单线程刷题纯属浪费 |
| 名字误导 | 它其实是"动态数组 + 栈语义"，不是真正的栈 |
| 官方文档明说 | JavaDoc 原话：*"A more complete and consistent set of LIFO stack operations is provided by the Deque interface and its implementations"* |
| 允许随机访问 | 暴露了 `get(i)`、`elementAt(i)`，容易写出不是栈语义的代码 |

**正确姿势**：

```java
Deque<Integer> stack = new ArrayDeque<>();   // 当栈用（LIFO）
Deque<Integer> queue = new ArrayDeque<>();   // 也可以当队列用（FIFO）
Queue<Integer> queue2 = new ArrayDeque<>();  // 声明成 Queue 更符合意图
```

> ⚠️ `ArrayDeque` **不允许存 `null`**（会抛 `NullPointerException`），而 `LinkedList` 允许。刷题时这反而是一道安全网。

### 2.2 `Deque` 的 **两套** API（新手最容易混的地方）

`Deque` 同时是栈和队列，所以它有**两套方法名**，一套"栈语义"，一套"队列语义"：

| 操作 | 栈语义（LIFO） | 队列语义（FIFO） | 抛异常版 |
| --- | --- | --- | --- |
| 尾部添加 | `push(e)` | `offer(e)` / `add(e)` | `addLast(e)` |
| 头部添加 | — | `push(e)` 也是加到头部 | `addFirst(e)` |
| 尾部取出 | — | `poll()` | `removeLast()` |
| 头部取出 | `pop()` | `poll()` | `removeFirst()` |
| 查看 | `peek()` | `peek()` | `getFirst()` |

**这张表看不懂没关系，记住下面这个"完整对照表"就够了**：

| 意图 | 推荐方法 | 失败时的行为 |
| --- | --- | --- |
| 入栈 | `stack.push(x)` | 等价 `addFirst` |
| 出栈 | `stack.pop()` | 空栈抛 `NoSuchElementException` |
| 看栈顶 | `stack.peek()` | 空栈返回 `null` |
| 入队 | `queue.offer(x)` | 等价 `addLast`，容量受限时返回 `false` |
| 出队 | `queue.poll()` | 空队返回 `null` |
| 看队首 | `queue.peek()` | 空队返回 `null` |

> **一句话记忆**：**`push/pop/peek` 是栈，`offer/poll/peek` 是队列**；两套里的 `peek` 是共享的，`Deque` 的队首恰好也是栈顶。

### 2.3 常见的三个 Java 坑

```java
// 坑 1：poll() 返回 Integer，可能为 null，直接拆箱会 NPE
int x = queue.poll();            // ❌ 队列空时 NPE
Integer x2 = queue.poll();       // ✅ 或者先判空

// 坑 2：Deque 当成 LinkedList 用会 O(n)
Deque<Integer> d = new ArrayDeque<>();
d.removeLastOccurrence(3);       // O(n)，别在循环里用

// 坑 3：字符栈用 char[] + 一个下标更香（常数小 10 倍）
char[] st = new char[s.length()];
int top = 0;
st[top++] = c;                   // 入栈
char t = st[--top];              // 出栈
boolean empty = (top == 0);      // 判空
```

## 三、Java 通用模板：两个栈实现队列

LeetCode 232「用栈实现队列」，也是《剑指 Offer》09。仓库里对应 `queue/CQueue.java`。

```java
import java.util.ArrayDeque;
import java.util.Deque;

class MyQueue {
    private final Deque<Integer> in = new ArrayDeque<>();   // 只负责进
    private final Deque<Integer> out = new ArrayDeque<>();  // 只负责出

    public MyQueue() { }

    public void push(int x) {
        in.push(x);                 // 进队列永远只压 in
    }

    public int pop() {
        if (out.isEmpty()) move();  // ★ 只在 out 空的时候搬运
        return out.pop();
    }

    public int peek() {
        if (out.isEmpty()) move();
        return out.peek();
    }

    public boolean empty() {
        return in.isEmpty() && out.isEmpty();   // ★ 两个都空才算空
    }

    /** 把 in 全部倒进 out：in 的栈顶（最新）= out 的栈底，顺序就正过来了 */
    private void move() {
        while (!in.isEmpty()) {
            out.push(in.pop());
        }
    }
}
```

### 为什么这样写

#### ① 为什么 `move()` 只在 `out` 为空时调用？

这是本模板**唯一的关键**。如果每次 `pop` 都搬运，元素会被反复倒腾，复杂度退化到 `O(n)` 每次。

- `out` 非空时，它栈顶就是"最早进队列的元素"，直接 `pop` 即可。
- `out` 空了才说明"前面排队的人已经全部出去了"，这才需要把 `in` 里新的一批倒过来。

**摊还分析**：每个元素一生只被搬一次（`in` → `out`），所以 n 次操作总共 `O(n)`，均摊 `O(1)`。

```
push(1) push(2) push(3)      in: [1,2,3]  out: []          （栈顶在右）
pop()  → move()              in: []       out: [3,2,1]     （栈顶在右，1 在顶）
pop()  → 直接 pop            out: [3,2]   → 返回 1
push(4)                      in: [4]
peek() → out 非空，不搬运     out: [3,2]   → 返回 2
```

#### ② 为什么 `empty()` 要检查两个栈？

`in` 或 `out` 任意一个非空，队列里就还有元素。"搬运"不是连续发生的，完全可能出现 `in = [4]`、`out = [2]` 的中间状态。

#### ③ 为什么用 `push/pop` 而不是 `offer/poll`？

两个栈都是纯 LIFO 用法，用栈语义方法（`push/pop/peek`）读起来语义最清晰。也可以写 `addLast/removeLast`，但没必要。

> 参考实现：[src/queue/CQueue.java](../src/queue/CQueue.java)

## 四、Java 通用模板：用队列实现栈（单队列版）

LeetCode 225。仓库里 `stack/QueueAsStack.java` 用的是**双队列互相倒**的写法，思路没问题但代码较长；这里给出更短的单队列写法。

```java
import java.util.ArrayDeque;
import java.util.Queue;

class MyStack {
    private final Queue<Integer> q = new ArrayDeque<>();

    public MyStack() { }

    public void push(int x) {
        q.offer(x);
        // ★ 把新元素"转到队首"：原来的 size-1 个元素依次出队再入队
        for (int i = q.size() - 1; i > 0; i--) {
            q.offer(q.poll());
        }
    }

    public int pop() {
        return q.poll();       // push 保证了队首就是"栈顶"
    }

    public int top() {
        return q.peek();
    }

    public boolean empty() {
        return q.isEmpty();
    }
}
```

### 为什么这样写

#### ① 核心思想：**在 `push` 时就把队首变成栈顶**

队列只能从队尾进、队首出。要让"最后进来的"变成"最先出去的"，就得在入队后把它**转到队首**。做法是把前面 `size-1` 个元素依次"出队再入队"——它们相对顺序不变，只是被挪到了新元素后面。

```
push(1): q=[1]
push(2): offer(2) → q=[1,2]；循环 1 次：poll 出 1，offer 回 → q=[2,1]   队首是 2 ✓
push(3): offer(3) → q=[2,1,3]；循环 2 次：
         poll 2 → offer 2 → q=[1,3,2]
         poll 1 → offer 1 → q=[3,2,1]                                    队首是 3 ✓
```

#### ② 复杂度取舍

| 方案 | push | pop | top |
| --- | --- | --- | --- |
| 单队列（上面这种） | `O(n)` | `O(1)` | `O(1)` |
| 双队列（仓库 `QueueAsStack.java`） | `O(1)` | `O(n)` | `O(n)` |

两种都合法，LeetCode 都给过。**面试时说明"我把代价放在 push 还是 pop，取决于哪种操作更频繁"就赢了。**

#### ③ 为什么 `for (int i = q.size() - 1; i > 0; i--)` 里的 `size()` 可以在循环条件里直接读？

因为 `q.size()` 只在**初始化**时求值一次，之后 `i` 自己递减，不受循环体内 `offer/poll` 影响。如果写成 `for (int i = 0; i < q.size() - 1; i++)` 就会因为队列长度始终不变而**死循环**——这是个很常见的坑。

> 参考实现：[src/stack/QueueAsStack.java](../src/stack/QueueAsStack.java)

## 五、Java 通用模板：最小栈

LeetCode 155。要求 `push / pop / top / getMin` 全部 `O(1)`。

### 5.1 方法一：辅助栈（推荐，最好写）

```java
import java.util.ArrayDeque;
import java.util.Deque;

class MinStack {
    private final Deque<Integer> data = new ArrayDeque<>();
    private final Deque<Integer> minStack = new ArrayDeque<>();   // 栈顶恒为当前最小值

    public MinStack() { }

    public void push(int val) {
        data.push(val);
        // ★ minStack 为空 或 val 更小（含相等）时，才同步压入
        if (minStack.isEmpty() || val <= minStack.peek()) {
            minStack.push(val);
        }
    }

    public void pop() {
        int val = data.pop();
        if (val == minStack.peek()) {     // ★ 弹出的正好是最小值，辅助栈也要弹
            minStack.pop();
        }
    }

    public int top() {
        return data.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

**为什么 `push` 要用 `<=` 而不是 `<`？**

如果写 `<`，当压入两个相同的当前最小值时，`minStack` 只会有一个副本。此后 `pop` 掉一个，`minStack.pop()` 会把唯一副本弹掉，最小值信息就丢了。

```
push(0) push(0)  → data=[0,0]  minStack 必须也是 [0,0]
pop()            → data=[0]    若 minStack 是 [0] 则再 pop 后 getMin() 会崩
```

**用 `<=` 的代价**：最坏空间 `O(n)`（所有元素都相等时）。可以接受，因为 `O(n)` 本来就是辅助栈的量级。

### 5.2 方法二：差值法（单栈 + 一个 `min` 变量，`O(1)` 额外空间）

**思想**：栈里不存真实值，存 `真实值 - 当前最小值` 的**差值**。差值 `< 0` 说明这个元素**刷新了最小值**，同时它也就是恢复上一个最小值的关键。

```java
import java.util.ArrayDeque;
import java.util.Deque;

class MinStack2 {
    private final Deque<Long> stack = new ArrayDeque<>();   // ★ 必须用 long 装差值
    private long min;                                       // 当前最小值（真实值）

    public MinStack2() { }

    public void push(int val) {
        if (stack.isEmpty()) {
            min = val;
            stack.push(0L);          // 第一个元素差值为 0
        } else {
            long diff = (long) val - min;   // ★ 先转 long，val 与 min 相减可能溢出 int
            stack.push(diff);
            if (diff < 0) {          // val 比 min 小 → 刷新最小值
                min = val;
            }
        }
    }

    public void pop() {
        long diff = stack.pop();
        if (diff < 0) {              // ★ 弹掉的是"刷新过最小值的元素"，要回滚 min
            min = min - diff;        // 等价于 min = 上一个 min，因为 diff = val - 上一个min 且 val = 当前min
        }
    }

    public int top() {
        long diff = stack.peek();
        return diff < 0 ? (int) min : (int) (min + diff);
        // diff >= 0 时，真实值 = min + diff；diff < 0 时，真实值就是 min
    }

    public int getMin() {
        return (int) min;
    }
}
```

**为什么必须用 `long`？** `val - min` 的范围可达 `[-2^31+1, 2^31-1]` 之外，例如 `val = Integer.MAX_VALUE`、`min = -1` 时差值是 `2^31`，**正好溢出 int**，变成负数，会让 `diff < 0` 的判断出错、把 `min` 错误地更新。

**为什么 `pop` 里 `min = min - diff` 能回滚？** 设压入 `val` 时旧最小值为 `oldMin`，则 `diff = val - oldMin`，且因为 `diff < 0` 所以 `min` 被更新成了 `val`。回滚时 `min - diff = val - (val - oldMin) = oldMin`。✅

> 参考实现：[src/stack/MinStack.java](../src/stack/MinStack.java)（**仓库版本**：`pop` 时若弹出最小值就重新线性扫描求最小值，单次 `pop` 是 `O(n)`；思路对但不符合题目 `O(1)` 要求，建议用上面的辅助栈版）、[src/stack/MiniStack.java](../src/stack/MiniStack.java)（`min()` 直接 `Collections.min`，同为 `O(n)`）

## 六、典型例题

### 6.1 LeetCode 20. 有效的括号

**题意**：给定只含 `()[]{}` 的字符串，判断括号是否按正确顺序闭合。

**思路（先暴力再优化）**：暴力做法是反复扫描并删除相邻的 `()`、`[]`、`{}`，直到字符串不再变化——每轮 `O(n)`，最多 `n/2` 轮，`O(n^2)`。**冗余在于"重复扫描已经配平的部分"**。用栈只需要一次扫描：碰到左括号就把它**期望的右括号**压栈，碰到右括号就检查栈顶是否等于它。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public boolean isValid(String s) {
    if (s.length() % 2 == 1) {        // 长度奇数必然不合法，提前剪枝
        return false;
    }
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(') {
            stack.push(')');          // ★ 压入"期望匹配的右括号"，而不是左括号本身
        } else if (c == '[') {
            stack.push(']');
        } else if (c == '{') {
            stack.push('}');
        } else {
            // 右括号：栈空（没有左括号配对）或栈顶不是它 → 不合法
            if (stack.isEmpty() || stack.pop() != c) {
                return false;
            }
        }
    }
    return stack.isEmpty();           // ★ 全部配平才合法，别漏了这句
}
```

**为什么"压入期望的右括号"这个技巧更优雅？** 因为它把"判断类型 + 匹配"合并成一次 `!=` 比较，省掉了一个 `switch` 或 `Map` 查表。注意 `stack.pop() != c`：`pop()` 返回 `Character`，与 `char` 比较时会自动拆箱，这里不会有 `null` 问题（前面已经 `isEmpty()` 判过）。

> 参考实现：[src/stack/ValidParentheses.java](../src/stack/ValidParentheses.java)、[src/stack/validBracket.java](../src/stack/validBracket.java)（**仓库版本**思路一致，但用 `Stack`；`validBracket` 的 `else if` 链在"右括号不匹配"时会静默走到结尾，靠最后的 `size() == 0` 兜底，逻辑正确但可读性差，建议用上面的写法）

**复杂度**：时间 `O(n)`（每个字符恰好进出栈一次）；空间 `O(n)`（最坏全是左括号）。

*有效的括号是【配对消除栈】的模板，关键突破点是【把左括号翻译成它期望的右括号再压栈，让匹配判断变成一次相等比较】，边界是【字符串长度为奇数要提前返回 false，以及循环结束后栈必须为空】。*

### 6.2 LeetCode 1047. 删除字符串中的所有相邻重复项

**题意**：反复删除相邻且相同的两个字符，直到无法继续（例：`abbaca` → `ca`）。

**思路**：暴力做法每轮 `O(n)` 且需要多轮。观察"消除后产生的新相邻对"，本质是**最近未消除的元素**与新元素比较——这正是栈。而且因为结果就是一串字符，可以直接拿 `StringBuilder` 当栈用。

```java
public String removeDuplicates(String s) {
    StringBuilder sb = new StringBuilder();     // sb 的末尾 = 栈顶
    for (char c : s.toCharArray()) {
        if (sb.length() > 0 && sb.charAt(sb.length() - 1) == c) {
            sb.deleteCharAt(sb.length() - 1);   // 与栈顶相同 → 一起消掉
        } else {
            sb.append(c);                       // 否则入栈
        }
    }
    return sb.toString();                       // StringBuilder 天然是"栈底→栈顶"的顺序
}
```

**为什么可以用 `StringBuilder` 替代栈？** 因为本题**不需要在栈顺序和输出顺序之间做转换**：栈底到栈顶就是最终字符串从左到右的顺序。用真正的 `Deque` 还要再 `reverse()` 一次（仓库版本就是这么做的）。

**用 `char[]` 手写更快的版本**：

```java
public String removeDuplicates2(String s) {
    char[] st = new char[s.length()];
    int top = 0;
    for (char c : s.toCharArray()) {
        if (top > 0 && st[top - 1] == c) {
            top--;                 // 出栈
        } else {
            st[top++] = c;         // 入栈
        }
    }
    return new String(st, 0, top);
}
```

> 参考实现：[src/string/RemoveDuplicates.java](../src/string/RemoveDuplicates.java)（**仓库版本**用 `Stack<Character>` + 双指针 `i` 的手动推进 + 最后 `reverse()`，逻辑正确；但 `while` 循环里手动改 `i` 很容易写出越界，推荐上面的 `StringBuilder` 写法）

**复杂度**：时间 `O(n)`（每个字符最多入栈、出栈各一次）；空间 `O(n)`（`StringBuilder` / `char[]`）。

*删除相邻重复项是【当栈用的 StringBuilder】的模板，关键突破点是【把"消除后新产生的相邻对"交给栈自动处理，不用重扫】，边界是【判空 `sb.length() > 0` 必须在 `charAt(length-1)` 之前】。*

### 6.3 LeetCode 155. 最小栈

### 6.4 LeetCode 946. 验证栈序列

**题意**：`pushed` 是入栈序列，判断 `popped` 是否可能是某个合法的出栈序列。

**思路（先暴力再优化）**：暴力是枚举所有出栈可能再比对，指数级。优化点在于——**模拟时不要"提前决定何时出栈"，而是"能出就出"**。因为若一个元素出栈后导致后面无法匹配，任何一种"故意压着不出"的选择都不可能更优（贪心选择的正确性：出栈顺序是题目给定的，能匹配就必须匹配，否则 `popped` 的下一个元素永远等不到）。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public boolean validateStackSequences(int[] pushed, int[] popped) {
    Deque<Integer> stack = new ArrayDeque<>();
    int j = 0;                                  // popped 的指针
    for (int x : pushed) {
        stack.push(x);
        // ★ "能出就出"：栈顶等于 popped[j] 就立刻弹出
        while (!stack.isEmpty() && j < popped.length && stack.peek() == popped[j]) {
            stack.pop();
            j++;
        }
    }
    return j == popped.length;                  // 全部弹出才算合法
}
```

**为什么"能出就出"不会漏解？** 因为 `popped` 是固定序列，`popped[j]` 必须**现在**被弹出，否则后面的元素会压在它上面、永远出不来。所以"该出的时候不出"只会让局面更差，不存在"故意不出反而更优"的情况。这是**交换论证**（exchange argument）的一个标准应用。

**边界**：`pushed.length != popped.length` 时直接返回 `false`（可以加一行早退）。仓库的 `ValidStackSeq.java` 里没有这个判断，`ValidStackSequences.java` 里加了。

> 参考实现：[src/stack/ValidStackSequences.java](../src/stack/ValidStackSequences.java)（**推荐**，结构最接近上面写法）、[src/stack/ValidStackSeq.java](../src/stack/ValidStackSeq.java)（**仓库版本**多了一个末尾的 `while` 补刀，实际上已经被主循环覆盖，属于冗余代码）

**复杂度**：时间 `O(n)`；空间 `O(n)`。

*验证栈序列是【模拟 + 贪心出栈】的模板，关键突破点是【"能出就出"的贪心不会漏解，因为压着不出只会让局面更糟】，边界是【两个数组长度不等要早退，`j` 的越界要防】。*

### 6.5 LeetCode 856. 括号的分数

**题意**：`()` 得 1 分，`AB` 得 `A + B` 分，`(A)` 得 `2 * A` 分（`A` 可为空、可为复合）。求整个字符串的分数。

**思路**：暴力是递归解析，写起来啰嗦。用栈**自底向上**算：每个"层"在栈里占一个位置，遇到 `)` 就把当前层的值 `v` 与下面一层的值 `w` 合并。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int scoreOfParentheses(String s) {
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(0);                             // ★ 哨兵：最外层的"当前累计分数"
    for (char c : s.toCharArray()) {
        if (c == '(') {
            stack.push(0);                     // 进入新的一层，该层分数从 0 开始
        } else {
            int v = stack.pop();               // 刚结束的这一层的分数
            int w = stack.pop();               // 外层已累计的分数
            // () 直接得 1； (A) 得 2*v。Math.max(2*v, 1) 正好统一这两种情况
            stack.push(w + Math.max(2 * v, 1));
        }
    }
    return stack.pop();
}
```

**为什么 `Math.max(2 * v, 1)` 能统一两种情况？** 当 `A` 为空（即刚遇到的是 `()`），此时 `v = 0`，`2 * v = 0`，取 `max` 得到 1 ✅；当 `A` 非空，`v ≥ 1`，`2 * v ≥ 2 > 1`，取 `2 * v` ✅。

**另一种 `O(1)` 空间解法**（`()` 的贡献是 `2 ^ depth`）：

```java
public int scoreOfParentheses2(String s) {
    int ans = 0, depth = 0;
    for (int i = 0; i < s.length(); i++) {
        if (s.charAt(i) == '(') {
            depth++;
        } else {
            depth--;
            if (s.charAt(i - 1) == '(') {       // 找到一对紧邻的 "()"
                ans += 1 << depth;              // 它对答案的贡献是 2^depth
            }
        }
    }
    return ans;
}
```

> 参考实现：[src/stack/ParenthesesScore.java](../src/stack/ParenthesesScore.java)（与栈版本完全一致，推荐对照阅读）、[src/string/CostOfBracket.java](../src/string/CostOfBracket.java)（**仓库版本**里有个乘法变体 `w * Math.max(v + 1, 1)`，仅对本题的输入分布成立，不具备通用性，**不建议模仿**）

**复杂度**：栈版时间 `O(n)`、空间 `O(n)`；计数版时间 `O(n)`、空间 `O(1)`。

*括号的分数是【分层累加栈】的模板，关键突破点是【用哨兵 0 表示最外层，`Math.max(2*v, 1)` 统一了 `()` 与 `(A)` 两种情况】，边界是【哨兵必须保证最后的 `stack.pop()` 不会空栈】。*

### 6.6 LeetCode 1021. 删除最外层的括号

**题意**：把每个"原始括号串"（不可再分的最小配平单位）的最外层括号删掉，再拼接。

**思路**：本题**不需要真的用栈**——只需要一个"当前嵌套深度"计数器。深度 `≥ 1` 说明这个字符在内层（要保留），深度归 `0` 说明这一对是最外层（要删）。

```java
public String removeOuterParentheses(String s) {
    int level = 0;
    StringBuilder res = new StringBuilder();
    for (char c : s.toCharArray()) {
        if (c == ')') {
            level--;                  // ★ 先降级：')' 自己不算"内层"
        }
        if (level >= 1) {
            res.append(c);            // 只有在内层才输出
        }
        if (c == '(') {
            level++;                  // ★ 后升级：'(' 先输出，再进入更深一层
        }
    }
    return res.toString();
}
```

**为什么 `)` 要"先减再判断"，`(` 要"先判断再加"？**

```
输入: ( ( ) ( ) ) ( ( ) ) ( )
level: 0 1 2 1 2 1 0 1 2 1 0 1 ...
输出:    ( )  ( )      ( )      ( )

关键：第一个 '(' 使 level 从 0→1，它自己不该输出 → 必须先判断(level>=1 时为 false)，再加
      最后一个 ')' 使 level 从 1→0，它自己也不该输出 → 必须先减到 0，再判断
```

如果两处顺序写反，就会把最外层括号也输出。

> 参考实现：[src/stack/RemoveOuterParentheses.java](../src/stack/RemoveOuterParentheses.java)（与上面完全一致）

**复杂度**：时间 `O(n)`；空间 `O(n)`（输出），除输出外额外空间 `O(1)`。

*删除最外层括号是【嵌套深度计数】的模板，关键突破点是【`(` 先判断后加、`)` 先减后判断，正好让最外层两个字符都被跳过】，边界是【`level` 一定不会变成负数，因为输入保证合法】。*

### 6.7 LeetCode 1441. 用栈操作构建数组

**题意**：用 `Push` / `Pop` 操作（列表初始为空）把 `1..n` 变成 `target`（严格递增）。

**思路**：从 1 扫到 `target` 的最后一个值；在 `target` 里就只 `Push`，不在就 `Push` 再 `Pop`（即"过一下而已"）。

```java
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;

public List<String> buildArray(int[] target, int n) {
    Set<Integer> need = new HashSet<>();
    int max = 0;
    for (int x : target) {
        need.add(x);
        max = Math.max(max, x);       // ★ 只需扫到 target 的最大值，不用扫到 n
    }
    List<String> res = new ArrayList<>();
    for (int i = 1; i <= max; i++) {
        if (need.contains(i)) {
            res.add("Push");          // 命中，留下
        } else {
            res.add("Push");
            res.add("Pop");           // 不命中，进又出
        }
    }
    return res;
}
```

**关键**：循环上界是 `target` 的最大值而不是题目给的 `n`，能少输出很多无用操作（`n` 可能高达 100，而 `target` 只有几个数）。因为严格递增的特性，其实**不需要 `HashSet`**——用双指针比较 `target[j] == i` 即可，空间从 `O(k)` 降到 `O(1)`。

> 参考实现：[src/stack/BuildArray.java](../src/stack/BuildArray.java)

**复杂度**：时间 `O(n)`；空间 `O(k)`（`HashSet`，可优化到 `O(1)`）。

*用栈操作构建数组是【顺序模拟】的模板，关键突破点是【只扫到 target 的最大值，且严格递增可以用指针代替哈希】，边界是【`target` 为空时 `max` 保持 0，循环不执行】。*

## 七、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 用 `java.util.Stack` | 代码慢、被面试官追问 | 用 `ArrayDeque` + `push/pop/peek` |
| `Deque` 里混用 `add` 和 `push` | `add` 加到尾部、`push` 加到头部，顺序全乱 | 一个容器只用一套语义，别混 |
| `pop()` / `poll()` 前不判空 | `NoSuchElementException` 或 `NPE` | 先 `isEmpty()`，或用 `peek()` 探 |
| 括号匹配循环结束后忘记 `return stack.isEmpty()` | `"("` 这种只有左括号的输入误判为合法 | 最后一定要判空 |
| 最小栈 `push` 时用 `<` 而不是 `<=` | 重复最小值被提前弹走，`getMin()` 出错 | 用 `<=`，保证副本数量一致 |
| 差值法用 `int` 存 `val - min` | 差值溢出，`< 0` 判断错误，`min` 被污染 | 用 `long` 存差值 |
| 两栈实现队列时每次 `pop` 都搬运 | 摊还复杂度退化成 `O(n)` | 只在 `out` 为空时搬运 |
| 单队列实现栈时 `for` 条件写 `i < q.size()` | `size()` 每次重算，且出队入队后长度不变 → 死循环 | 先缓存 `int size = q.size()`，或写成 `i = q.size() - 1; i > 0; i--` |
| 用 `StringBuilder` 当栈时，`charAt(length - 1)` 前没判空 | `StringIndexOutOfBoundsException` | `sb.length() > 0 &&` 短路放前面 |
| 验证栈序列没有校验两数组长度 | 越界或错误通过 | 开头加 `pushed.length != popped.length → false` |
