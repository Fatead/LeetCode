# 05 优先队列与设计题

> **一句话理解**：优先队列（堆）是"**我不关心全部顺序，只关心当前最好的是谁**"——它把 `O(n)` 的"找最值"降到 `O(1)` 的"看堆顶"，代价是插入/删除变成 `O(log n)`；而设计题考的是"**用最少的额外状态把一个操作变成 O(1)**"。

---

## 一、什么时候能用优先队列

### 判定标准

| 题目信号 | 该用什么 | 举例 |
| --- | --- | --- |
| "第 K 大 / 第 K 小" | 大小为 K 的**小顶堆**（求第 K 大）/ **大顶堆**（求第 K 小） | 215、703、剑指 40 |
| "前 K 个高频 / 最接近 / 最热门" | 堆 + 哈希计数（或桶排序） | 347、692、973 |
| "数据流中位数" | **对顶堆**（大顶堆 + 小顶堆） | 295 |
| "合并 K 个有序序列" | 堆里放每个序列的当前头 | 23、373、378、632 |
| "每次取最小 / 最大，取完再放回去" | 堆 | 621、1046、1642 |
| "任务/区间按时间顺序模拟" | 堆按开始时间或结束时间排序 | 253、1834、1882 |
| "设计一个 O(1) 取最值的结构" | 辅助单调队列 / 双结构 | 155、剑指 59-II |

### 什么时候**不能**用

| 场景 | 为什么不行 | 该用什么 |
| --- | --- | --- |
| 需要 `O(1)` 取**滑动窗口**的最值 | 堆的懒删除会让堆膨胀，且 `poll` 是 `O(log n)` | 单调队列（见 [03](03-单调队列.md)） |
| 需要**任意删除**指定元素 | `PriorityQueue` 的 `remove(Object)` 是 `O(n)` | `TreeMap` / 索引堆 / 平衡树 |
| 需要**有序遍历全部元素** | 堆只能保证堆顶最小 | `TreeMap` / 排序 |
| 只需要**一次**取第 K 大 | 排序 `O(n log n)` 或快速选择 `O(n)` 更快 | 快排分区（见 [01 章 06 排序与快速选择](../01-数组与双指针/06-排序与快速选择.md)） |
| 数据量小（`n ≤ 100`） | 堆的常数比排序大 | 直接 `Arrays.sort` |

### 堆 vs 其他结构

| 需求 | 堆（`PriorityQueue`） | 排序 | 单调队列 | `TreeMap` |
| --- | --- | --- | --- | --- |
| 取最值 | `O(1)` | `O(1)` 取首/尾 | `O(1)` | `O(log n)` |
| 插入 | `O(log n)` | 不支持（要重排） | 摊还 `O(1)` | `O(log n)` |
| 删除任意元素 | `O(n)`（懒惰 `O(log n)`） | — | 只能删两端 | `O(log n)` |
| 空间 | `O(k)` 可只留 TopK | `O(n)` | `O(k)` | `O(n)` |
| 典型场景 | TopK、多路归并 | 需要全序 | 滑动窗口 | 需要前驱后继 |

## 二、Java 语言基本功：`PriorityQueue` 与自定义 `Comparator`

### 2.1 默认就是小顶堆

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();          // ★ 默认小顶堆
PriorityQueue<Integer> minHeap2 = new PriorityQueue<>(Comparator.naturalOrder());

// 大顶堆的三种写法
PriorityQueue<Integer> maxHeap1 = new PriorityQueue<>(Comparator.reverseOrder());          // 最清晰
PriorityQueue<Integer> maxHeap2 = new PriorityQueue<>((a, b) -> Integer.compare(b, a));    // 推荐
PriorityQueue<Integer> maxHeap3 = new PriorityQueue<>((a, b) -> b - a);                    // ⚠️ 可能溢出
```

> ⚠️ **`(a, b) -> b - a` 有溢出风险**。当 `a = Integer.MIN_VALUE`、`b = 1` 时 `b - a` 溢出成负数，比较结果完全错乱。**面试坚持写 `Integer.compare(b, a)` 或 `Comparator.reverseOrder()`。**

### 2.2 常用方法对照

| 意图 | 方法 | 失败行为 | 复杂度 |
| --- | --- | --- | --- |
| 建堆 | `new PriorityQueue<>()` | — | `O(1)` |
| 从集合建堆 | `new PriorityQueue<>(collection)` | — | `O(n)`（堆化，不是 `n log n`！） |
| 插入 | `offer(e)` / `add(e)` | `add` 容量不足抛异常 | `O(log n)` |
| 取堆顶（不删） | `peek()` | 空返回 `null` | `O(1)` |
| 弹出堆顶 | `poll()` | 空返回 `null` | `O(log n)` |
| 删除指定元素 | `remove(Object)` | 找不到返回 `false` | **`O(n)`** 定位 + `O(log n)` 调整 |
| 大小 | `size()` | — | `O(1)` |
| 判空 | `isEmpty()` | — | `O(1)` |

**两个高频坑**：

```java
// 坑 1：PriorityQueue 的迭代顺序【不保证有序】！
PriorityQueue<Integer> pq = new PriorityQueue<>(List.of(5, 1, 3));
for (int x : pq) System.out.print(x);   // 可能是 1 5 3，不是 1 3 5
// 想按序输出必须反复 poll()
while (!pq.isEmpty()) System.out.print(pq.poll());

// 坑 2：PriorityQueue 不允许 null
pq.offer(null);                          // NullPointerException
```

### 2.3 自定义 `Comparator`：四种写法

```java
// 场景：按 int[] 的第二个元素升序（第二个相同时按第一个降序）

// ① Lambda（最简洁，面试首选）
PriorityQueue<int[]> pq1 = new PriorityQueue<>((a, b) ->
        a[1] != b[1] ? Integer.compare(a[1], b[1]) : Integer.compare(b[0], a[0]));

// ② 静态工厂链（可读性最好）
PriorityQueue<int[]> pq2 = new PriorityQueue<>(
        Comparator.comparingInt((int[] a) -> a[1])
                  .thenComparing((int[] a) -> a[0], Comparator.reverseOrder()));

// ③ 匿名内部类（Java 8 之前的写法，代码长）
PriorityQueue<int[]> pq3 = new PriorityQueue<>(new Comparator<int[]>() {
    @Override
    public int compare(int[] a, int[] b) {
        return Integer.compare(a[1], b[1]);
    }
});

// ④ 对象实现 Comparable（适合自定义类）
class Task implements Comparable<Task> {
    int priority;
    @Override
    public int compareTo(Task o) {
        return Integer.compare(o.priority, this.priority);   // 注意：反向 = 大顶堆
    }
}
PriorityQueue<Task> pq4 = new PriorityQueue<>();
```

**`compare(a, b)` 的返回值语义**：

| 返回值 | 含义 | 在堆里的效果 |
| --- | --- | --- |
| 负数 | `a` 排在 `b` 前面 | `a` 更靠近堆顶 |
| 0 | 相等 | 顺序不定 |
| 正数 | `a` 排在 `b` 后面 | `b` 更靠近堆顶 |

> **记忆口诀**：**返回负数 = "a 优先"；想让大的优先，就写 `compare(b, a)`。**

### 2.4 从集合 `O(n)` 建堆

```java
List<Integer> list = new ArrayList<>(List.of(3, 1, 4, 1, 5));
PriorityQueue<Integer> pq = new PriorityQueue<>(list);   // O(n) 堆化，不要循环 offer
```

`PriorityQueue(Collection)` 构造器内部走的是 `heapify`（自底向上），是 `O(n)`；而循环 `offer` 是 `O(n log n)`。**数据量大时这个常数差很明显。**

## 三、Java 通用模板

### 3.1 模板 A：TopK（大小为 K 的堆）

```java
import java.util.PriorityQueue;

/**
 * TopK 通用模板：求"第 K 大"或"前 K 大"
 *
 * 核心思想：维护一个【大小为 K 的小顶堆】。
 *   堆里是"目前见过的最大 K 个数"，堆顶是这 K 个里最小的
 *   → 堆顶就是"第 K 大"
 *   新元素比堆顶大，就把堆顶挤掉（它连 TopK 都进不去）
 *
 * ⭐ 为什么求"第 K 大"用小顶堆而不是大顶堆？
 *   因为要淘汰的是"目前 TopK 里最小的那个"，必须能 O(1) 看到它 → 它必须在堆顶。
 */
public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> minHeap = new PriorityQueue<>();   // 小顶堆
    for (int x : nums) {
        minHeap.offer(x);
        if (minHeap.size() > k) {
            minHeap.poll();          // 弹出最小的，堆里始终保留最大的 k 个
        }
    }
    return minHeap.peek();           // 堆顶 = 这 k 个里最小的 = 第 k 大
}
```

**复杂度**：时间 `O(n log k)`（每个元素一次 `O(log k)` 的插入，最多 n 次弹出）；空间 `O(k)`。

**对比其他解法**：

| 解法 | 时间 | 空间 | 是否修改原数组 | 适用 |
| --- | --- | --- | --- | --- |
| 全排序 | `O(n log n)` | `O(log n)` | 是 | `n` 小、代码最短 |
| **小顶堆** | `O(n log k)` | `O(k)` | 否 | `k` 小、`n` 是流式数据 |
| 快速选择 | `O(n)` 平均，`O(n^2)` 最坏 | `O(1)` | 是 | 一次性、`n` 大、允许改数组 |
| 桶排序（频次题） | `O(n)` | `O(n)` | 否 | 值是"频次"且范围有限 |

### 3.2 模板 B：对顶堆（动态中位数）

```java
import java.util.PriorityQueue;

/**
 * 对顶堆模板：动态维护中位数
 *
 * 把数据分成两半：
 *   maxHeap（大顶堆）存较小的一半，堆顶是【左半部分最大值】
 *   minHeap（小顶堆）存较大的一半，堆顶是【右半部分最小值】
 *
 *   "对顶"：两个堆顶正好把有序数组切成两半，中间就是这个中位数
 *
 *   ┌─────────────┬─────────────┐
 *   │  maxHeap    │  minHeap    │
 *   │ 较小的一半   │  较大的一半  │
 *   │  ...  4  7  │  9  12  ... │
 *   └──────┬──────┴──┬──────────┘
 *          └ 堆顶7   堆顶9 ┘   → 中位数 = (7+9)/2
 *
 * 不变式（必须始终满足）：
 *   ① maxHeap.size() == minHeap.size()  或  maxHeap.size() == minHeap.size() + 1
 *   ② maxHeap 的所有元素 <= minHeap 的所有元素
 */
class MedianFinder {
    private final PriorityQueue<Integer> maxHeap =
            new PriorityQueue<>((a, b) -> Integer.compare(b, a));   // 较小的一半（大顶堆）
    private final PriorityQueue<Integer> minHeap =
            new PriorityQueue<>();                                  // 较大的一半（小顶堆）

    public void addNum(int num) {
        // ① 先无条件塞进 maxHeap
        maxHeap.offer(num);
        // ② 立刻把 maxHeap 的最大值"倒"给 minHeap —— 这一步保证了不变式 ②
        minHeap.offer(maxHeap.poll());
        // ③ 若 minHeap 变多了，再把它的最小值倒回 maxHeap —— 这一步保证不变式 ①
        if (maxHeap.size() < minHeap.size()) {
            maxHeap.offer(minHeap.poll());
        }
    }

    public double findMedian() {
        if (maxHeap.size() > minHeap.size()) {
            return maxHeap.peek();                                  // 奇数个：maxHeap 多一个
        }
        return (maxHeap.peek() + minHeap.peek()) / 2.0;             // ★ 2.0 才做浮点除法
    }
}
```

**为什么 `addNum` 只有三步，不需要判断 `num` 该去哪个堆？**

这是对顶堆最优雅的地方：**"先塞 maxHeap，再倒给 minHeap，再看要不要倒回来"** 这套固定动作自动完成了分流。

```
插入 3 的过程：
① maxHeap.offer(3)              maxHeap=[3]           minHeap=[]
② minHeap.offer(maxHeap.poll()) maxHeap=[]            minHeap=[3]
③ maxHeap.size()=0 < 1 → maxHeap.offer(minHeap.poll())
                                maxHeap=[3]           minHeap=[]

插入 1：
① maxHeap.offer(1)              maxHeap=[3,1]（堆顶3） minHeap=[]
② minHeap.offer(3)              maxHeap=[1]           minHeap=[3]
③ 1 < 1? 否 → 不动
   结果 maxHeap=[1], minHeap=[3]   中位数 = (1+3)/2.0 = 2.0 ✅

插入 5：
① maxHeap.offer(5)              maxHeap=[5,1]（堆顶5） minHeap=[3]
② minHeap.offer(5)              maxHeap=[1]           minHeap=[3,5]（堆顶3）
③ 1 < 2 → maxHeap.offer(3)      maxHeap=[3,1]         minHeap=[5]
   结果 中位数 = 3 ✅（有序 1,3,5）
```

**为什么 `findMedian` 用 `maxHeap.size() > minHeap.size()` 判断奇偶？**

因为不变式 ① 保证 `maxHeap.size()` 只可能等于 `minHeap.size()` 或比它大 1。所以：
- 大 1 → 总数为奇数，中位数就是 `maxHeap.peek()`
- 相等 → 总数为偶数，中位数是两个堆顶的平均

**为什么必须写 `/ 2.0` 而不是 `/ 2`？**

`(a + b)` 是 `int`，`/ 2` 会做整数除法（`(1+2)/2 = 1`，丢掉小数）。**`/ 2.0` 让被除数转成 `double`。** 另一种写法是 `(a + b) / 2.0` 或 `(double)(a + b) / 2`。

**为什么 `(maxHeap.peek() + minHeap.peek())` 不会溢出？** 在 295 里值域是 `-10^5 ~ 10^5`，两个相加远不溢出。**但如果值域是 `Integer.MAX_VALUE`，就必须写成 `maxHeap.peek() / 2.0 + minHeap.peek() / 2.0`。**

## 四、典型例题

### 4.1 LeetCode 215. 数组中的第 K 个最大元素

见[模板 A](#31-模板-a-topk大小为-k-的堆)。

**仓库版本对照**：`KthElement.java` 提供了三种解法——`Arrays.sort` 全排序、小顶堆、以及手写的 `buildMaxHeap` + `maxHeap` 调整（**注意仓库里 `buildMaxHeap` 的循环是 `for (int i = heapSize/2; i >= 0; i--) maxHeap(nums, i, nums.length)`，内部递归调用 `maxHeap` 时把 `heapSize` 参数误传成 `nums.length`，导致堆化范围不受控；这段代码没有被主方法调用，属于未完成的手写堆**）。

```java
public int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();
    for (int i : nums) {
        heap.add(i);
        if (heap.size() > k) {
            heap.poll();
        }
    }
    return heap.peek();
}
```

> 参考实现：[src/array/KthElement.java](../src/array/KthElement.java)（**仓库版本**：`findKthLargest` 全排序，`findKthLargest2` 小顶堆，与上面写法一致）、[src/array/KthLargest2.java](../src/array/KthLargest2.java)（703 数据流第 K 大：**注意 `add` 里 `queue.size() < k` 时直接 `add`；`else if (queue.peek() < val)` 才替换**，这就是模板 A 的在线版本）、[src/array/KthLargest.java](../src/array/KthLargest.java)、[src/array/LeastNumbers.java](../src/array/LeastNumbers.java)（剑指 40：大顶堆求"最小 K 个数"，以及快排分区版 `getLeastNumbers2`）

**边界**：
- `k == nums.length`：堆里装下全部元素，堆顶是全局最小，即"第 n 大" = 最小值 ✅
- `k == 1`：堆里只有 1 个元素（当前最大），返回全局最大 ✅
- 有重复元素：堆按值比较，重复值互不影响 ✅

**复杂度**：时间 `O(n log k)`；空间 `O(k)`。

*第 K 大元素是【大小为 K 的堆】的模板，关键突破点是【求第 K 大要用小顶堆，因为要淘汰的是"当前 TopK 里最小的"，它必须能被 O(1) 看到】，边界是【k == n 和 k == 1 都要能自然工作；比较器禁止写减法防溢出】。*

### 4.2 LeetCode 347. 前 K 个高频元素

**题意**：返回数组中出现频率最高的 `k` 个元素（顺序任意）。

**思路（先暴力再优化）**：

| 解法 | 做法 | 时间 | 空间 |
| --- | --- | --- | --- |
| 暴力 | 哈希计数后按频次全排序 | `O(n + m log m)` | `O(m)` |
| **堆** | 哈希计数 + 大小为 `k` 的小顶堆 | `O(n + m log k)` | `O(m + k)` |
| **桶排序** | 哈希计数 + 桶（下标 = 频次） | `O(n)` | `O(n)` |

优化的那一步消除了什么：暴力要**把所有不同元素的频次全排一遍**；堆只需要维护"前 k 名"，桶排序则利用"**频次的值域只有 `[1, n]`**"这个额外信息，把排序变成计数。

#### 解法一：哈希 + 小顶堆

```java
import java.util.HashMap;
import java.util.Map;
import java.util.PriorityQueue;

public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) {
        freq.merge(x, 1, Integer::sum);              // 比 getOrDefault 更简洁
    }

    // 小顶堆：按频次升序，堆里保留频次最高的 k 个
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
    for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
        pq.offer(new int[]{e.getKey(), e.getValue()});
        if (pq.size() > k) {
            pq.poll();                                // 频次最低的被挤掉
        }
    }

    int[] res = new int[k];
    for (int i = 0; i < k; i++) {
        res[i] = pq.poll()[0];
    }
    return res;
}
```

**为什么堆里存 `int[]{元素, 频次}` 而不是只存元素？** 因为比较需要频次，但输出需要元素。如果只存元素，比较时还得反复 `freq.get(x)`（虽然也能工作，但多一次哈希查找）。

**仓库版本对照**：`array/TopKFrequent.java` 的 `topKFrequent2` 用的是同样的思路，但**手写了一个匿名 `Comparator` 比较 `ints[1] - t1[1]`（减法有溢出风险，不过频次不会溢出）**，且"先判断 `queue.size() == k` 再决定是否替换"的写法比"先 `offer` 再 `poll`"多一层分支。**推荐"先 offer 再按 size 弹"**，边界更统一。

#### 解法二：哈希 + 桶排序（`O(n)`）

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

@SuppressWarnings("unchecked")
public int[] topKFrequent2(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) {
        freq.merge(x, 1, Integer::sum);
    }

    // ★ 桶：下标就是频次（范围 0..n），桶里放该频次的所有元素
    List<Integer>[] buckets = new List[nums.length + 1];
    for (Map.Entry<Integer, Integer> e : freq.entrySet()) {
        int f = e.getValue();
        if (buckets[f] == null) {
            buckets[f] = new ArrayList<>();
        }
        buckets[f].add(e.getKey());
    }

    int[] res = new int[k];
    int idx = 0;
    // ★ 从高频桶往低频桶扫，凑够 k 个就停
    for (int f = buckets.length - 1; f >= 0 && idx < k; f--) {
        if (buckets[f] != null) {
            for (int v : buckets[f]) {
                res[idx++] = v;
                if (idx == k) {
                    break;
                }
            }
        }
    }
    return res;
}
```

**为什么桶排序能到 `O(n)`？** 因为**频次一定是 `[1, n]` 之间的整数**，值域有限。计数排序的思想就是"用值当数组下标"，避免了 `O(m log m)` 的比较排序。

**`new List[n + 1]` 的坑**：Java 不允许创建泛型数组，`new List[n+1]` 会有 unchecked 警告。两种处理：

```java
@SuppressWarnings("unchecked")                       // 方案一：压制警告（刷题常用）
List<Integer>[] buckets = new List[nums.length + 1];

List<List<Integer>> buckets = new ArrayList<>();     // 方案二：用嵌套 List（无警告）
for (int i = 0; i <= nums.length; i++) buckets.add(new ArrayList<>());
```

### 4.4 LeetCode 23. 合并 K 个升序链表

**题意**：把 `k` 个升序链表合并成一个升序链表。

**思路（先暴力再优化）**：

| 解法 | 做法 | 时间 | 空间 |
| --- | --- | --- | --- |
| 暴力 1 | 全部节点拆下来排序再串起来 | `O(N log N)` | `O(N)` |
| 暴力 2 | 逐个和答案链表两两合并 | `O(k^2 · m)`（`m` 是单链平均长度） | `O(1)` |
| **分治** | 两两合并，共 `log k` 轮 | `O(N log k)` | `O(log k)` 递归栈 |
| **优先队列** | 堆里放每个链表的当前头，每次取最小的 | `O(N log k)` | `O(k)` |

（`N` 是总节点数。）两种最优解都是 `O(N log k)`，**区别在于：分治不额外占空间（只有递归栈），优先队列是"在线式"的——它还能处理"链表是流式给出"的场景。**

#### 解法一：优先队列

```java
import java.util.PriorityQueue;

public ListNode mergeKLists(ListNode[] lists) {
    if (lists == null || lists.length == 0) {
        return null;
    }
    // 小顶堆：按节点值比较
    PriorityQueue<ListNode> pq = new PriorityQueue<>(
            (a, b) -> Integer.compare(a.val, b.val));

    // ★ 初始化：只放每个链表的"当前头"，不放全部节点
    for (ListNode node : lists) {
        if (node != null) {
            pq.offer(node);
        }
    }

    ListNode dummy = new ListNode(0);      // 傀儡头节点
    ListNode tail = dummy;

    while (!pq.isEmpty()) {
        ListNode cur = pq.poll();          // 当前最小的节点
        tail.next = cur;
        tail = cur;
        if (cur.next != null) {
            pq.offer(cur.next);            // ★ 把该链表的下一个节点补进堆
        }
    }
    tail.next = null;                      // 保险：切断可能残留的旧连接
    return dummy.next;
}
```

**为什么堆里只放 `k` 个节点，而不是全部 `N` 个？**

这就是 `O(N log k)` 而不是 `O(N log N)` 的关键：

```
不放全部：堆大小恒为 k
  每次 poll 出一个最小 → O(log k)
  把它的后继补进去   → O(log k)
  共 N 次 → O(N log k)

放全部：初始化 O(N)，之后每次 poll 是 O(log N)
  共 N 次 → O(N log N)
```

**`tail.next = null` 是必须的吗？** 在本题里，`tail` 每次都被赋成 `cur`，最后 `tail` 指向的一定是某个原链表的末节点（`next == null`），所以可以省略。**但加上它是防御性写法**——如果题目变成"合并后要截断到某个长度"，少了这行就会带上多余的尾巴。

#### 解法二：分治（仓库实现）

```java
public ListNode mergeKLists2(ListNode[] lists) {
    if (lists.length == 0) return null;
    if (lists.length == 1) return lists[0];
    return mergeTwoLists(
            mergeKLists2(Arrays.copyOfRange(lists, 0, lists.length / 2)),
            mergeKLists2(Arrays.copyOfRange(lists, lists.length / 2, lists.length)));
}

public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    ListNode head = new ListNode(0);        // 傀儡头节点
    ListNode pt = head;
    while (l1 != null && l2 != null) {
        if (l1.val < l2.val) {
            pt.next = l1;
            l1 = l1.next;
        } else {
            pt.next = l2;
            l2 = l2.next;
        }
        pt = pt.next;
    }
    pt.next = (l1 != null) ? l1 : l2;        // ★ 剩下的一整段直接接上
    return head.next;
}
```

**为什么"剩下的一整段可以直接接上"？** 因为两个输入链表都是升序的，当一个链表耗尽时，另一个链表剩下的部分本身就是升序的，且都大于已合并部分的最大值。**这个技巧让收尾从两个 `while` 变成一行。**

**分治版的一个小问题**：`mergeKLists2` 里的 `Arrays.copyOfRange` 每层递归都要**复制数组**，额外开销是 `O(k log k)` 时间和 `O(k log k)` 空间。更省的写法是传下标区间 `merge(lists, lo, hi)`，避免复制：

```java
private ListNode merge(ListNode[] lists, int lo, int hi) {
    if (lo == hi) return lists[lo];
    int mid = lo + (hi - lo) / 2;
    return mergeTwoLists(merge(lists, lo, mid), merge(lists, mid + 1, hi));
}
```

> 参考实现：[src/listTable/MergeKLists.java](../src/listTable/MergeKLists.java)（**仓库版本是分治版**，`mergeTwoLists` 用了傀儡头节点，写得规范；`mergeKLists` 用 `Arrays.copyOfRange` 切分，注意上面提到的复制开销）、[src/listTable/MergeKList.java](../src/listTable/MergeKList.java)、[src/listTable/MergeTwoList.java](../src/listTable/MergeTwoList.java)、[src/listTable/MergeTwoLists.java](../src/listTable/MergeTwoLists.java)、[src/listTable/MergeLists.java](../src/listTable/MergeLists.java)

**注意 `ListNode` 的定义**：仓库里 `MergeKLists.java` 用的是**私有内部类**：

```java

    int val;
    ListNode next;
    ListNode(int x) { this.val = x; }
}
```

提交 LeetCode 时要用平台自带的定义，**只写 `mergeKLists` 方法体，不要重新定义 `ListNode`**（会编译冲突）。

**复杂度**：优先队列 `O(N log k)` 时间 / `O(k)` 空间；分治 `O(N log k)` 时间 / `O(log k)` 递归栈空间（若用 `copyOfRange` 还要加 `O(k log k)`）。

*合并 K 个升序链表是【多路归并 + 优先队列】的模板，关键突破点是【堆里只放每个链表的当前头，取一个补一个，堆大小恒为 k，把 O(N log N) 压到 O(N log k)】，边界是【初始化要跳过 null 链表；空数组返回 null；尾节点的 next 要切断】。*

### 4.5 LeetCode 621. 任务调度器

**题意**：`tasks` 是大写字母表示的任务，相同任务之间必须间隔至少 `n` 个时间单位（可以安排空闲），求执行完全部任务的最短时间。

**思路（先暴力再优化）**：

| 解法 | 做法 | 时间 | 空间 |
| --- | --- | --- | --- |
| 暴力 | 按时间轴逐格模拟，每格找"冷却结束且剩余最多"的任务 | `O(t · 26 · n)` | `O(26)` |
| **公式** | 找出现次数最多的任务，按"桶"算 | `O(t)` | `O(26)` |
| **优先队列** | 每轮取最多 `n+1` 个剩余最多的任务 | `O(t log 26)` | `O(26)` |

#### 解法一：公式法（最优，`O(t)` 且常数极小）

```java
public int leastInterval(char[] tasks, int n) {
    int[] count = new int[26];
    int maxCount = 0;
    for (char c : tasks) {
        count[c - 'A']++;
        maxCount = Math.max(maxCount, count[c - 'A']);
    }
    // 出现次数等于最大次数的任务有几种
    int maxKinds = 0;
    for (int c : count) {
        if (c == maxCount) {
            maxKinds++;
        }
    }
    // 按"桶"排：maxCount 个桶，桶间间隔 n，最后一个桶只放 maxKinds 个
    int byFormula = (maxCount - 1) * (n + 1) + maxKinds;
    return Math.max(tasks.length, byFormula);   // ★ 任务种类多到填满所有空隙时，答案就是任务总数
}
```

**公式是怎么来的？** 设想把"出现最多的那个任务"竖着排成若干列（桶）：

```
tasks = [A,A,A,B,B,B], n = 2, maxCount = 3, maxKinds = 2

桶 1: A B _
桶 2: A B _
桶 3: A B          ← 最后一个桶不需要补空闲

时间轴:  A B _ A B _ A B
下标:    0 1 2 3 4 5 6 7     共 8

公式: (maxCount - 1) * (n + 1) + maxKinds = 2 * 3 + 2 = 8 ✅
```

**为什么最后的 `Math.max(tasks.length, byFormula)` 不能省？**

```
tasks = [A,B,C,D,E,F,G], n = 100, maxCount = 1, maxKinds = 7
公式: (1-1) * 101 + 7 = 7
实际: 7 个任务都不相同，不需要等待，答案是 7 而不是 0 ✅（公式也给 7）

反例：tasks = [A,B,C], n = 0, maxCount = 1, maxKinds = 3
公式: 0 * 1 + 3 = 3，tasks.length = 3 → max = 3 ✅

再看：tasks = [A,A,B,C,D,E], n = 2, maxCount = 2, maxKinds = 1
公式: 1 * 3 + 1 = 4
实际: A B C A D E → 6（任务种类够多，空隙被填满了）
Math.max(6, 4) = 6 ✅  ← 这就是为什么必须取 max
```

**关键结论**：当"非最多次数的任务足够多"时，它们能把 `maxCount` 桶之间的所有空隙填满，此时瓶颈是任务总数而不是冷却间隔。

#### 解法二：优先队列模拟

```java
import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;

public int leastInterval2(char[] tasks, int n) {
    int[] count = new int[26];
    for (char c : tasks) {
        count[c - 'A']++;
    }
    PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());  // 大顶堆
    for (int c : count) {
        if (c > 0) {
            pq.offer(c);
        }
    }

    int time = 0;
    while (!pq.isEmpty()) {
        int cycle = n + 1;             // 一轮最多放 n+1 个任务
        List<Integer> tmp = new ArrayList<>();
        int finished = 0;

        while (cycle > 0 && !pq.isEmpty()) {
            int cur = pq.poll();
            if (cur > 1) {
                tmp.add(cur - 1);      // 还有剩余，等这轮结束后再放回堆
            }
            finished++;
            cycle--;
        }

        for (int t : tmp) {
            pq.offer(t);
        }
        // ★ 还剩任务 → 这一轮用满 n+1；没任务了 → 只用 finished 个时间单位
        time += pq.isEmpty() ? finished : n + 1;
    }
    return time;
}
```

**为什么 `time += pq.isEmpty() ? finished : n + 1`？** 最后一轮不需要"补满冷却"，所以按实际执行的任务数计时；但只要还有任务剩下，这一轮就必须占满 `n+1` 个时间单位（其中不足的部分是空闲）。

**仓库版本对照**：`greedy/LeastInterval.java` 是**逐格模拟版**——每一格把所有任务的冷却时间减 1，然后挑"冷却为 0 且剩余次数最多"的任务执行；若没有可执行的就 `continue`（空转）。**逻辑正确**，但：

| 项 | 仓库 `LeastInterval.java` | 优先队列版 | 公式版 |
| --- | --- | --- | --- |
| 时间 | `O(t · 26)`（每格扫两遍 map） | `O(t log 26)` | `O(t)` |
| 空间 | `O(26)` 两个 `HashMap` | `O(26)` | `O(26)` 数组 |
| 可读性 | 一般（两层 `for` + `flag`） | 好 | 最好 |
| 面试推荐 | 讲思路可以 | ✅ | ✅✅（面试首选） |

仓库版本有个小细节值得学：**它用 `timeMap.get(c) > 0` 递减冷却，用 `flag` 判断"本格是否只能空转"，这是"按时间轴模拟"的标准骨架**，遇到更复杂的调度约束（多种冷却、不同任务不同间隔）时，这个骨架比公式更通用。

> 参考实现：[src/greedy/LeastInterval.java](../src/greedy/LeastInterval.java)（**仓库版本是逐格模拟**，逻辑正确但常数较大）

**复杂度**：公式法 `O(t)` 时间 / `O(26)` 空间；优先队列法 `O(t log 26)`（约等于 `O(t)`）时间 / `O(26)` 空间。

*任务调度器是【桶公式 / 大顶堆逐轮模拟】的模板，关键突破点是【最少时间由"最多次数任务的冷却骨架"和"任务总数"两者的 max 决定】，边界是【必须取 max(tasks.length, byFormula)；优先队列版最后一轮按 finished 计时而不是 n+1】。*

### 4.6 LeetCode 622 / 641. 设计循环队列与循环双端队列

**题意**：
- **622**：设计循环队列，支持 `enQueue / deQueue / Front / Rear / isEmpty / isFull`。
- **641**：在此基础上再加 `insertFront / deleteLast / getFront / getRear`。

**思路（先暴力再优化）**：暴力的"数组 + 每次删除后搬移元素"是 `O(n)`。优化点是：**用"头下标 + 元素个数"两个变量代替"搬移"**，所有操作变 `O(1)`。

#### 622 循环队列

```java
class MyCircularQueue {
    private final int[] data;
    private int head;      // 队首元素所在下标
    private int count;     // 当前元素个数

    public MyCircularQueue(int k) {
        data = new int[k];
        head = 0;
        count = 0;
    }

    public boolean enQueue(int value) {
        if (isFull()) {
            return false;
        }
        data[(head + count) % data.length] = value;   // ★ 新元素放在"队尾的下一位"
        count++;
        return true;
    }

    public boolean deQueue() {
        if (isEmpty()) {
            return false;
        }
        head = (head + 1) % data.length;              // ★ 只移动 head，不搬移元素
        count--;
        return true;
    }

    public int Front() {
        return isEmpty() ? -1 : data[head];
    }

    public int Rear() {
        return isEmpty() ? -1 : data[(head + count - 1) % data.length];
    }

    public boolean isEmpty() {
        return count == 0;
    }

    public boolean isFull() {
        return count == data.length;
    }
}
```

**为什么用 `count` 而不是 `(tail + 1) % size == head` 来判断队满？**

经典的"牺牲一个空位"方案要维护 `head` 和 `tail` 两个下标，且队列容量实际只有 `k - 1`，非常反直觉。**用 `count` 直接把"满/空"变成两个清晰的条件，代价只是一个 `int`。**

**`(head + count) % data.length` 和 `(head + count - 1) % data.length` 的推导**：

```
容量 5，head = 3，count = 3  （元素在下标 3, 4, 0）

队尾元素下标 = head + count - 1 = 5 → % 5 = 0   ✅ 正好是 0
下一个入队位置 = head + count   = 6 → % 5 = 1   ✅ 1 是空的
```

`head + count` 最大值是 `2 * (k - 1)`，不会溢出 `int`（`k ≤ 1000` 左右）。

**为什么 `deQueue` 后不需要清空 `data[head]`？** 因为 `count` 已经把它排除在逻辑之外了，后续 `enQueue` 会覆盖它。

#### 641 循环双端队列

```java
class MyCircularDeque {
    private final int[] data;
    private int head;
    private int count;

    public MyCircularDeque(int k) {
        data = new int[k];
        head = 0;
        count = 0;
    }

    public boolean insertFront(int value) {
        if (isFull()) {
            return false;
        }
        // ★ 头指针往前退一格（注意负数取模：先加 length 再取模）
        head = (head - 1 + data.length) % data.length;
        data[head] = value;
        count++;
        return true;
    }

    public boolean insertLast(int value) {
        if (isFull()) {
            return false;
        }
        data[(head + count) % data.length] = value;
        count++;
        return true;
    }

    public boolean deleteFront() {
        if (isEmpty()) {
            return false;
        }
        head = (head + 1) % data.length;
        count--;
        return true;
    }

    public boolean deleteLast() {
        if (isEmpty()) {
            return false;
        }
        count--;                        // ★ 尾部删除只要减少 count，head 不用动
        return true;
    }

    public int getFront() {
        return isEmpty() ? -1 : data[head];
    }

    public int getRear() {
        return isEmpty() ? -1 : data[(head + count - 1) % data.length];
    }

    public boolean isEmpty() {
        return count == 0;
    }

    public boolean isFull() {
        return count == data.length;
    }
}
```

**关键坑：`head = (head - 1 + data.length) % data.length`**

Java 的 `%` 是**取余**，不是数学取模。`-1 % 5 = -1`（负数！），会导致数组下标越界。

```java
head = (head - 1) % data.length;              // ❌ head=0 时得到 -1 → ArrayIndexOutOfBoundsException
head = (head - 1 + data.length) % data.length; // ✅ 先加 length 保证非负
```

**为什么 `deleteLast` 只减 `count`？** 因为 `Rear()` 的计算完全依赖 `head + count - 1`。`count` 减 1 之后，原来的尾部元素自然落在"逻辑队列之外"，不需要任何指针调整。

**`k == 0` 怎么办？** `new int[0]` 之后 `(head + count) % 0` 会抛 `ArithmeticException`。**题目保证 `k >= 1`**，但如果你要写健壮的版本，`isFull()` 里 `count == data.length` 在 `k = 0` 时是 `0 == 0` 为真，所以 `insertFront/insertLast` 都会先返回 `false`，不会走到取模那行 —— **其实不会崩**。这是"用 `count` 判满"的额外好处。

**仓库版本对照**：`queue/MyCircularQueue.java` 和 `queue/MyCircularDeque.java` **用的是 `LinkedList` / `List`**，`remove(0)` 和 `add(front, value)` 都是 `O(n)`，而且 `rear`/`front` 两个字段在 `MyCircularDeque` 里根本没有被正确维护（`insertFront` 后 `front` 不变，`deleteLast` 后 `rear` 不变）。虽然靠 `list` 本身的顺序还能给出正确答案，但**完全没有实现"循环数组"这个考点**。这也是本题的典型错误：**以为用了 `List` 就实现了循环队列。**

| 项 | 仓库 `MyCircularQueue/Deque.java` | 推荐版本 |
| --- | --- | --- |
| 底层 | `LinkedList` | `int[]` 循环数组 |
| `enQueue` | `list.add` `O(1)` | `O(1)` |
| `deQueue` | `list.remove(0)` **`O(n)`** | `O(1)` |
| `insertFront` | `list.add(0, v)` **`O(n)`** | `O(1)` |
| `deleteLast` | `list.remove(size-1)` `O(1)` | `O(1)` |
| 是否体现"循环" | ❌ | ✅ |

> 参考实现：[src/queue/MyCircularQueue.java](../src/queue/MyCircularQueue.java)、[src/queue/MyCircularDeque.java](../src/queue/MyCircularDeque.java)（**仓库版本**：用 `LinkedList` 实现，接口签名完全正确，但 `deQueue` / `insertFront` 是 `O(n)`，没有体现循环数组的考点；建议改用上面的 `int[] + head + count`）

**复杂度**：所有操作 `O(1)`；空间 `O(k)`。

*循环队列是【数组 + 头下标 + 计数】的模板，关键突破点是【用 count 代替"牺牲一个空位"来区分满和空，所有位置都用 (head + offset) % length 算出来，无需搬移元素】，边界是【head 往前退时必须先加 length 再取模，因为 Java 的 % 对负数返回负数】。*

## 五、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 比较器写 `(a, b) -> a - b` | 大数相减溢出，堆序错乱 | `Integer.compare(a, b)` 或 `Comparator.reverseOrder()` |
| 以为 `PriorityQueue` 迭代有序 | 输出顺序错 | 反复 `poll()`，或用 `TreeMap` |
| 求第 K 大用大顶堆 | 无法 `O(1)` 看到"当前 TopK 里最小的" | 求第 K 大用小顶堆，求第 K 小用大顶堆 |
| 堆里放全部节点再做多路归并 | 复杂度退化到 `O(N log N)` | 只放每个序列的当前头，取一个补一个 |
| 对顶堆中位数写 `/ 2` | 偶数个时丢掉小数 | `/ 2.0` |
| 对顶堆两堆顶相加可能溢出 | 结果错误 | `peek() / 2.0 + peek() / 2.0` |
| `PriorityQueue` 里放 `null` | `NullPointerException` | 先判空再 `offer` |
| 循环队列用"牺牲一个空位"判满 | 容量变成 `k-1`，边界极易错 | 用 `count` 字段 |
| 循环队列 `head--` 直接取模 | `-1 % 5 = -1`，下标越界 | `(head - 1 + len) % len` |
| 用 `List` 冒充循环队列 | `remove(0)` / `add(0, v)` 是 `O(n)`，没实现考点 | 用 `int[]` + `head` + `count` |
| 任务调度器忘写 `Math.max(tasks.length, ...)` | 任务种类多的用例答案偏小 | 必须取 max |
| 分治合并 K 链表用 `copyOfRange` | 每层都复制数组，多出 `O(k log k)` 开销 | 改传下标区间 `merge(lists, lo, hi)` |
| 桶排序 `new List[n+1]` 不处理警告 | 编译警告（不影响正确性） | 加 `@SuppressWarnings("unchecked")` 或改用 `List<List<Integer>>` |
