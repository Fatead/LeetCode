# 03 单调队列

> **一句话理解**：单调队列是"**在滑动窗口右扩左缩的过程中，用一个双端队列维护窗口内的最值**"——队尾淘汰"永远不可能当最大值"的矮个子，队首淘汰"已经滑出窗口"的老人，取最值 `O(1)`，全程摊还 `O(n)`。

---

## 一、什么时候能用单调队列

### 判定标准

> **题目同时满足：① 有一个会滑动的窗口（或一个长度受限的"选择范围"）；② 需要在这个范围内取最大/最小值。**

具体信号：

| 题目字眼 | 该用什么 | 举例 |
| --- | --- | --- |
| "长度为 k 的滑动窗口中的最大值/最小值" | 单调队列 | 239、剑指 59-I |
| "窗口的 max - min ≤ limit 的最长区间" | 两个单调队列（一升一降） | 1438 |
| "设计一个队列，能 O(1) 取最大值" | 辅助单调队列（主队列 + 单调队列） | 剑指 59-II |
| "选一个间隔不超过 k 的前驱做 DP 转移" | DP + 单调队列优化 | 1425、1696、918 |
| "限制长度的子数组和最大/最小" | 前缀和 + 单调队列 | 862、1425 |
| "多路归并的当前最小值" | 优先队列（不是单调队列） | 23 |

### 什么时候**不能**用

| 场景 | 为什么不行 |
| --- | --- |
| 窗口**只增不减**（无收缩） | 那就退化成单调栈，见 [02 单调栈](02-单调栈.md) |
| 需要同时取**最大和最小**且要"同时满足两个约束" | 两个队列可以，但再加约束就要考虑其他结构 |
| 窗口内需要**第 k 大 / 中位数** | 单调队列只能维护"极值"，不能维护"序统计量" | 用对顶堆 / 平衡树 |
| 窗口是**二维**的 | 可以逐行+逐列做两次单调队列 | 见练习 |
| 元素会**被任意删除**（不是从两端走） | 双端队列只能淘汰队首队尾，中间删除做不到 | 用 `TreeMap` / 平衡树 |

### 单调队列 vs 单调栈 vs 优先队列

| 维度 | 单调栈 | 单调队列 | 优先队列（堆） |
| --- | --- | --- | --- |
| 操作端 | 只有栈顶 | 队首 + 队尾 | 插入任意，弹出堆顶 |
| 维护的东西 | "还没等到答案"的元素 | "窗口内还可能有用的"元素 | 全部待选元素 |
| 典型问题 | 下一个更大元素 | 滑动窗口最值 | 全局 TopK / 多路归并 |
| 摊还复杂度 | `O(n)` | `O(n)` | `O(n log n)` |
| 能否删过期元素 | 不涉及 | `O(1)` 从队首删 | 只能"懒删除"，堆会膨胀 |
| 单次取最值 | `O(1)` | `O(1)` | `O(1)` |
| 单次插入 | `O(1)` 摊还 | `O(1)` 摊还 | `O(log n)` |

> **一句话选择**：**窗口会滑动 → 单调队列；只要全局最值 → 优先队列。**

## 二、Java 通用模板（滑动窗口最大值）

```java
import java.util.ArrayDeque;
import java.util.Deque;

/**
 * 单调队列模板：求每个长度为 k 的窗口中的最大值
 *
 * 队列里存【下标】，对应的 nums 值从队首到队尾【单调递减】。
 *   - 队首 = 当前窗口最大值所在下标  → 取答案 O(1)
 *   - 队尾 = 最新且"最有潜力"的候选者 → 插入 O(1) 摊还
 *
 * @return res[i] = 窗口 [i, i+k-1] 的最大值，长度为 n-k+1
 */
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();          // 存下标

    for (int i = 0; i < n; i++) {
        // ① 队首出队：下标已经滑出窗口左边界（i - k 及更左的都不要了）
        while (!dq.isEmpty() && dq.peekFirst() <= i - k) {
            dq.pollFirst();
        }

        // ② 队尾出队：队尾对应的值不比 nums[i] 大，那它永远当不上最大值
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) {
            dq.pollLast();
        }

        dq.offerLast(i);                             // ③ 当前元素入队

        // ④ 窗口第一次形成（i >= k-1）之后，队首就是答案
        if (i >= k - 1) {
            res[i - k + 1] = nums[dq.peekFirst()];
        }
    }
    return res;
}
```

### 关键点逐条解释

#### ① 为什么用 `Deque`（`ArrayDeque`）而不是 `Queue`？

因为单调队列**两端都要操作**：队尾要 `pollLast`（淘汰矮个子），队首既要 `pollFirst`（淘汰过期元素）又要 `peekFirst`（取答案）。

| 需要的操作 | `Queue` 接口能提供吗 | `Deque` |
| --- | --- | --- |
| 队尾插入 | ✅ `offer` | ✅ `offerLast` |
| 队首弹出 | ✅ `poll` | ✅ `pollFirst` |
| 队首查看 | ✅ `peek` | ✅ `peekFirst` |
| **队尾弹出** | ❌ **没有** | ✅ `pollLast` |
| **队尾查看** | ❌ **没有** | ✅ `peekLast` |

**这就是必须用 `Deque` 的唯一原因**：只有 `Deque` 能在 `O(1)` 内从队尾删除。`LinkedList` 也实现了 `Deque`，但每个节点是一次堆分配，常数比 `ArrayDeque` 大不少，刷题用 `ArrayDeque`。

#### ② 步骤 ① 和 ② 谁先谁后？有区别吗？

**有区别，而且必须先 ① 后 ②。**

考虑 `nums = [1, 3, -1, -3, 5, 3, 6, 7]`，`k = 3`，在 `i = 4`（`nums[4] = 5`）时：

```
处理前：dq = [1, 3]         （值 3, -1，下标 1 和 3）
i=4，i-k = 1

先 ① 再 ②：
  ① dq.peekFirst()=1 <= 1 → pollFirst → dq = [3]
  ② nums[3]=-1 <= 5 → pollLast → dq = []
  ③ offerLast(4) → dq = [4]                          答案 = nums[4] = 5 ✅

先 ② 再 ①（错误示范）：
  ② nums[3]=-1 <= 5 → pollLast → dq = [1]
     nums[1]=3 <= 5 → pollLast → dq = []
  ① dq 空了，什么都不做
  ③ offerLast(4) → dq = [4]                          结果巧合一样
```

再看一个能暴露差别的例子：`nums = [5, 1, 2]`，`k = 2`，`i = 2`：

```
dq = [0, 1]（值 5, 1），i=2，i-k=0

先 ① 后 ②：① peekFirst()=0 <= 0 → pollFirst → dq=[1]
            ② nums[1]=1 <= 2 → pollLast → dq=[]
            ③ dq=[2]                              答案 = 2 ✅

先 ② 再 ①：② nums[1]=1 <= 2 → pollLast → dq=[0]
            ② nums[0]=5 <= 2? 否，停           dq=[0]
            ① peekFirst()=0 <= 0 → pollFirst → dq=[]
            ③ dq=[2]                              答案 = 2 ✅
```

两个都对了。**那到底有没有区别？**

真正的区别在于：如果先做 ②，可能会把"其实已经过期"的元素拿来比较，虽然不影响最终单调性，但会让"过期元素"短暂地影响弹出决策。更严重的是**如果先做 ② 再 ①，而队列里只剩一个过期元素且它比 `nums[i]` 小**，它被 ② 弹掉了，① 什么也没做 —— 结果一样，但**代码的因果逻辑反了**（① 的职责是"确保窗口内的元素都在范围内"，必须是第一步）。

**所以固定顺序：① 过期出队 → ② 单调性出队 → ③ 入队 → ④ 取答案。** 记住这个 4 步口诀，不会错。

#### ③ 为什么步骤 ② 用 `<=` 而不是 `<`？

用 `<=` 会把**相等**的旧元素也弹掉，保留新的。

```
nums = [3, 3, 3], k = 2

用 <= ：i=0: dq=[0]
        i=1: nums[0]=3 <= nums[1]=3 → pollLast → dq=[] → offer(1) → dq=[1]
             窗口 [0,1] 最大值 = nums[1] = 3 ✅
        i=2: peekFirst()=1 <= 0? 否 → 不弹
             nums[1]=3 <= nums[2]=3 → pollLast → dq=[] → offer(2) → dq=[2]
             窗口 [1,2] 最大值 = nums[2] = 3 ✅

用 < ： i=0: dq=[0]
        i=1: nums[0]=3 < 3? 否 → 不弹 → dq=[0,1]
             窗口 [0,1] 最大值 = nums[0] = 3 ✅
        i=2: peekFirst()=0 <= 0 → pollFirst → dq=[1]
             nums[1]=3 < 3? 否 → dq=[1,2]
             窗口 [1,2] 最大值 = nums[1] = 3 ✅
```

两种都能过。但 `<=` **更好**：它让队列里的下标尽量新，减少"过期元素还占着队首"的概率，常数更小。

> ⚠️ 但如果你是在做"**窗口内第一个更大元素**"这类需要保留等值位置的题，就要用 `<`。**同一道题内部保持一致即可。**

#### ④ 为什么 `if (i >= k - 1)` 才能取答案？

因为前 `k - 1` 个元素构不成一个完整窗口。

```
k = 3, n = 8
i:        0    1    2    3    4    5    6    7
窗口:     └────┘
          └─────────┘
               └─────────┘
                    └─────────┘
                         └─────────┘
                              └─────────┘
res 下标:                    0    1    2    3    4    5
         （i >= 2 才开始记录，共 n-k+1 = 6 个）
```

`res` 的长度是 `n - k + 1`，和 `i - k + 1` 的取值范围正好对齐。

#### ⑤ 空窗口 / `k` 越界怎么办？

- `k == 0`：题面一般不允许。若允许，`n - k + 1 = n + 1` 会多算一个，需特判。
- `k > n`：没有完整窗口，`new int[n - k + 1]` 会抛 `NegativeArraySizeException`。**面试时主动提一句"我会先判断 `k > n` 直接返回空"，是加分的。**
- `nums` 为空：`n = 0`，`k > 0` 时 `n - k + 1 <= 0`，同样要早退。

### 为什么均摊是 `O(n)`（而不是 `O(n·k)`）

> **每个下标最多被 `offerLast` 一次，因此也最多被 `pollFirst` 或 `pollLast` 一次。**

三段 `while` 的总执行次数 = 总的 `poll` 次数 ≤ `n`（因为 `poll` 的前提是之前 `offer` 过）。所以：

```
总代价 = n（offer）+ ≤ n（pollFirst）+ ≤ n（pollLast）= O(n)
```

**如果换成"对每个窗口重新扫 k 个元素求最大"，就是 `O(n·k)`。** 单调队列消掉的冗余是：**两个相邻窗口有 `k-1` 个元素是重叠的，没必要重新扫。**

```
窗口重叠示意（k = 4）：
窗口 [0..3]  ▮▮▮▮
窗口 [1..4]   ▮▮▮▮     ← 中间 3 个是重复的
窗口 [2..5]    ▮▮▮▮
暴力做法每次都 O(k)；单调队列让每个元素一生只被处理一次
```

## 三、典型例题

### 3.1 LeetCode 239. 滑动窗口最大值

**题意**：给整数数组 `nums` 和窗口大小 `k`，窗口从最左滑到最右，返回每个窗口里的最大值。

**思路（先暴力再优化）**：

| 解法 | 做法 | 时间 | 空间 |
| --- | --- | --- | --- |
| 暴力 | 每个窗口扫一遍 | `O(n·k)`，`n = 10^5, k = 10^5` 时必超时 | `O(1)` |
| 优先队列 | 堆里放 `(值, 下标)`，懒删除过期元素 | `O(n log n)` | `O(n)` |
| **单调队列** | 队首即答案，队尾淘汰矮个子 | `O(n)` | `O(k)` |

代码就是上面的[通用模板](#二java-通用模板滑动窗口最大值)。这里补一份**优先队列版本**用于对比：

```java
import java.util.PriorityQueue;

public int[] maxSlidingWindow2(int[] nums, int k) {
    int n = nums.length;
    int[] res = new int[n - k + 1];
    // 大顶堆，按值降序；值相同时按下标降序（让新的排前面，减少过期判断）
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) ->
            a[0] != b[0] ? b[0] - a[0] : b[1] - a[1]);

    for (int i = 0; i < n; i++) {
        pq.offer(new int[]{nums[i], i});
        if (i >= k - 1) {
            // ★ 懒删除：堆顶如果已经滑出窗口，就扔掉，直到堆顶在窗口内
            while (pq.peek()[1] <= i - k) {
                pq.poll();
            }
            res[i - k + 1] = pq.peek()[0];
        }
    }
    return res;
}
```

**为什么堆反而更慢？** 因为堆里存了所有还没被懒删除的元素，最多可能有 `n` 个；每次 `offer` 和 `poll` 都是 `O(log n)`。单调队列的队列长度最多 `k`，且插入/删除都是摊还 `O(1)`。

**为什么 `PriorityQueue` 的比较器里要注意溢出？** `b[0] - a[0]` 在 `nums[i]` 接近 `Integer.MIN_VALUE`/`MAX_VALUE` 时会溢出。安全写法是 `Integer.compare(b[0], a[0])`。上面为了简洁用了减法，**面试写 `Integer.compare` 更稳。**

> 参考实现：**仓库中没有本题实现（已用 `grep -r maxSlidingWindow src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：单调队列 `O(n)` 时间 / `O(k)` 空间；优先队列 `O(n log n)` 时间 / `O(n)` 空间。

*滑动窗口最大值是【单调队列】的模板，关键突破点是【队尾弹掉"永远当不上最大值"的元素，队首弹掉"已过期"的元素，队列的单调性让队首恒为答案】，边界是【k > n 要早退，取答案要等 i >= k-1，队首过期判断用 <= i-k】。*

### 3.2 LeetCode 1438. 绝对差不超过限制的最长连续子数组

**题意**：求最长的连续子数组，使得其中**任意两个元素之差 ≤ limit**（等价于 `max - min ≤ limit`）。

**思路（先暴力再优化）**：

- 暴力：枚举所有子数组，每个求 max/min，`O(n^2)` 或 `O(n^3)`。
- 优化：**这是一个滑动窗口题**（窗口越大越容易违反 `max - min ≤ limit`，满足单调性）。窗口合法性判断需要**同时拿到窗口的 max 和 min**——`O(1)` 做到这件事，正是单调队列。

**为什么用两个单调队列？** 一个维护窗口最大值（队首到队尾递减），一个维护窗口最小值（队首到队尾递增）。它们共享同一个窗口 `[left, right]`。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int longestSubarray(int[] nums, int limit) {
    // 单调递减队列：队首是窗口最大值
    Deque<Integer> maxDq = new ArrayDeque<>();
    // 单调递增队列：队首是窗口最小值
    Deque<Integer> minDq = new ArrayDeque<>();
    int left = 0;
    int ans = 0;

    for (int right = 0; right < nums.length; right++) {
        // ① 把 nums[right] 纳入两个队列
        while (!maxDq.isEmpty() && nums[maxDq.peekLast()] <= nums[right]) {
            maxDq.pollLast();
        }
        maxDq.offerLast(right);

        while (!minDq.isEmpty() && nums[minDq.peekLast()] >= nums[right]) {
            minDq.pollLast();
        }
        minDq.offerLast(right);

        // ② 窗口不合法就收缩左边界，直到 max - min <= limit
        while (nums[maxDq.peekFirst()] - nums[minDq.peekFirst()] > limit) {
            // ★ 只有队首正好是 left 时，才需要把它移出队列
            if (maxDq.peekFirst() == left) {
                maxDq.pollFirst();
            }
            if (minDq.peekFirst() == left) {
                minDq.pollFirst();
            }
            left++;
        }

        // ③ 此刻窗口合法，更新答案
        ans = Math.max(ans, right - left + 1);
    }
    return ans;
}
```

**为什么收缩窗口时**不**直接 `maxDq.clear()` 而是判断队首是否等于 `left`？**

因为窗口收缩一格只移除了**一个**元素（下标 `left`）。队列里其它元素（下标 `> left`）仍然在窗口内，不能删。

```
nums = [8, 2, 4, 7], limit = 4

right=0: maxDq=[0] minDq=[0]              窗口 [0,0] max-min=0 ≤ 4   ans=1
right=1: nums[1]=2
         maxDq: 8<=2? 否 → maxDq=[0,1]
         minDq: 8>=2 ✓ → pollLast → minDq=[] → minDq=[1]
         窗口 [0,1] max-min = 8-2 = 6 > 4 → 收缩
           maxDq.peekFirst()=0 == left=0 → pollFirst → maxDq=[1]
           minDq.peekFirst()=1 != 0 → 不动
           left=1
         现在 maxDq=[1] minDq=[1] → max-min=0 ≤ 4  ans=2
right=2: nums[2]=4
         maxDq: 2<=4 ✓ → pollLast → maxDq=[] → maxDq=[2]
         minDq: 2>=4? 否 → minDq=[1,2]
         窗口 [1,2] max-min = 4-2 = 2 ≤ 4  ans=3
right=3: nums[3]=7
         maxDq: 4<=7 ✓ → pollLast → maxDq=[3]
         minDq: 4>=7? 否 → minDq=[1,2,3]
         窗口 [1,3] max-min = 7-2 = 5 > 4 → 收缩
           maxDq.peekFirst()=3 != 1 → 不动
           minDq.peekFirst()=1 == 1 → pollFirst → minDq=[2,3]
           left=2
         maxDq=[3] minDq=[2,3] → max-min = 7-4 = 3 ≤ 4  ans = max(3, 3-2+1=2) = 3
返回 3 ✅（[8,2,4] 或 [2,4,7]）
```

**`right` 进队时为什么不检查"过期"？** 因为窗口的 `left` 只会因为别的原因（合法性）而移动，而**每次 `left` 移动时已经同步清掉了队首的过期元素**。所以 `right` 进队时队列里不会有已经小于 `left` 的下标。这是和 239 的一个差别 —— **239 的窗口左边界是"自动"固定的（`i - k`），所以要显式过期；这里左边界是"显式"移动的，过期和收缩合并了。**

> 参考实现：**仓库中没有本题实现（已用 `grep -r longestSubarray src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：时间 `O(n)`（每个下标最多进/出每个队列一次，总共 `2n` 级别）；空间 `O(n)`（两个队列最坏各装 `n` 个下标，但实际约为 `min(n, 窗口长度)`）。

*绝对差不超过限制的最长连续子数组是【双单调队列 + 滑动窗口】的模板，关键突破点是【用一升一降两个队列同时 O(1) 拿到窗口 max 与 min，把窗口合法性判断降到 O(1)】，边界是【收缩时只删队首中恰好等于 left 的那个下标，且两个队列要分别判断】。*

### 3.3 剑指 Offer 59 - II. 队列的最大值（MaxQueue 设计题）

**题意**：设计一个队列，支持 `push_back`、`pop_front`、`max_value`（返回当前队列最大值），要求 `max_value` 的均摊复杂度 `O(1)`。

**思路（先暴力再优化）**：暴力做法是 `max_value` 时遍历整个队列，`O(n)`；或者在 `pop_front` 弹出最大值时重新扫描（仓库 `listTable/MaxQueue.java` 就是这个思路，`pop_front` 是 `O(n)`）。

优化点是：**用一个"辅助单调队列"提前记好"未来会当最大值的候选者"，主队列只负责存数据。**

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.LinkedList;
import java.util.Queue;

class MaxQueue {
    private final Queue<Integer> data = new LinkedList<>();   // 主队列：存全部数据
    private final Deque<Integer> maxDq = new ArrayDeque<>();  // 辅助队列：单调递减，队首是最大值

    public MaxQueue() { }

    public int max_value() {
        return maxDq.isEmpty() ? -1 : maxDq.peekFirst();
    }

    public void push_back(int value) {
        data.offer(value);
        // ★ 所有"比 value 小或相等"的候选者都不可能是未来的最大值了，弹掉
        while (!maxDq.isEmpty() && maxDq.peekLast() < value) {
            maxDq.pollLast();
        }
        maxDq.offerLast(value);
    }

    public int pop_front() {
        if (data.isEmpty()) {
            return -1;
        }
        int front = data.poll();
        // ★ 只有弹出的正好是当前最大值，辅助队列的队首才需要同步弹出
        if (!maxDq.isEmpty() && maxDq.peekFirst() == front) {
            maxDq.pollFirst();
        }
        return front;
    }
}
```

**为什么 `maxDq` 里可以存"值"而不是下标？**

因为 `pop_front` 时我们只关心"弹出的值是不是当前最大值"。由于辅助队列是**严格递减**的（用了 `<`，等值会被挤掉），同一个值不会在队列里出现两次，所以用值比较就够了。**如果用了 `<=`（保留等值），就必须存下标，否则弹出时无法区分是哪一份副本。** 这是一个很细的坑。

**为什么 `push_back` 用 `< ` 而不是 `<=`？** 用 `<` 保证 `maxDq` 里值严格递减。若用 `<=`，等值会被挤掉，队列里值也严格递减 —— 但那样 `pop_front` 的值比较仍然安全（因为唯一）。两种都可以，**关键是和 `pop_front` 的比较方式配套**。

**均摊 `O(1)` 的证明**：每个元素最多被 `data.offer` 一次、`data.poll` 一次、`maxDq.offerLast` 一次、`maxDq.pollLast/pollFirst` 一次。总操作数 `O(1)` 每次摊还。

> 参考实现：[src/listTable/MaxQueue2.java](../src/listTable/MaxQueue2.java)（**仓库版本**：用 `Queue` + `Deque` 的双结构，注释写得很到位——"当一个元素进入队列的时候，它前面所有比它小的元素就不会再对答案产生影响了"，与上面写法一致；只是 `pop_front` 用了 `d.getFirst()`，**空栈时会抛 `NoSuchElementException`**，建议改成 `peekFirst()`）、[src/listTable/MaxQueue.java](../src/listTable/MaxQueue.java)（**仓库版本是暴力版**：`pop_front` 在弹出最大值时重新 `for` 扫一遍求 `max`，单次 `O(n)`，作为"先暴力再优化"的对照很有价值）

**复杂度**：`max_value` `O(1)`；`push_back` 均摊 `O(1)`；`pop_front` `O(1)`。空间 `O(n)`。

*队列的最大值是【主结构 + 辅助单调队列】的模板，关键突破点是【入队时把"永远追不上新元素"的旧候选从队尾弹掉，出队时只在弹出的恰是最大值时同步弹队首】，边界是【空队列 `max_value` 返回 -1；`pop_front` 比较队首前必须判空】。*

### 3.4 LeetCode 1425. 带限制的子序列和

**题意**：给数组 `nums` 和整数 `k`，求一个**非空**子序列，使得任意两个相邻被选元素的下标差 `≤ k`，且元素和最大。

**思路（先暴力再优化）**：

- 暴力 DP：`dp[i] = 以 i 结尾的最大子序列和`，转移 `dp[i] = nums[i] + max(0, dp[j])`，其中 `i - k ≤ j < i`。要枚举 `j`，`O(n·k)`。
- 优化：转移需要的是**下标窗口 `[i-k, i-1]` 内 `dp` 的最大值**——这正是单调队列的标准形态。`dp[i] = nums[i] + max(0, 窗口内 dp 最大值)`。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int constrainedSubsetSum(int[] nums, int k) {
    int n = nums.length;
    int[] dp = new int[n];
    Deque<Integer> dq = new ArrayDeque<>();     // 存下标，对应 dp 值单调递减
    int ans = Integer.MIN_VALUE;

    for (int i = 0; i < n; i++) {
        // ① 队首出队：下标必须落在 [i-k, i-1] 内
        while (!dq.isEmpty() && dq.peekFirst() < i - k) {
            dq.pollFirst();
        }

        // ② 计算 dp[i]：接上一个最优前驱，或者自己单起一段
        int best = dq.isEmpty() ? 0 : Math.max(0, dp[dq.peekFirst()]);
        dp[i] = best + nums[i];

        // ③ 用 dp[i] 维护单调性（注意：这里比较的是 dp 值，不是 nums 值！）
        while (!dq.isEmpty() && dp[dq.peekLast()] <= dp[i]) {
            dq.pollLast();
        }
        dq.offerLast(i);

        ans = Math.max(ans, dp[i]);
    }
    return ans;
}
```

**为什么 `best` 要 `Math.max(0, ...)`？**

因为子序列可以**从 `i` 重新开始**（不接任何前驱），此时贡献是 0。如果窗口内所有 `dp` 都是负数，硬接上去反而更差。

```
nums = [-1, -2, -3], k = 2

i=0: dq 空 → best = 0 → dp[0] = -1          dq=[0]        ans=-1
i=1: 0 >= -2 ✓ 不弹；best = max(0, dp[0]=-1) = 0
     dp[1] = -2                              dp[0]=-1 <= dp[1]=-2? 否 → dq=[0,1]  ans=-1
i=2: peekFirst()=0 < 0? 否；best = max(0, dp[0]=-1) = 0
     dp[2] = -3                              dp[1]=-2 <= -3? 否 → dq=[0,1,2]      ans=-1
返回 -1 ✅（必须非空，所以是最大的负数，不是 0）
```

**这就是为什么答案初值必须是 `Integer.MIN_VALUE` 而不是 0**：题目要求子序列**非空**，如果全为负数，答案应该是最大的那个负数。

**为什么 ③ 里比较的是 `dp` 值？** 因为转移需要的是 `dp` 的最大值，不是 `nums` 的最大值。**这是本题最容易写错的地方**——很多人顺手写成 `nums[dq.peekLast()] <= nums[i]`，那就完全错了。

**边界**：
- 空数组：LeetCode 保证 `n ≥ 1`；本地跑空数组会返回 `Integer.MIN_VALUE`，最好特判。
- `k ≥ n`：窗口覆盖整个前缀，`dq.peekFirst() < i - k` 永远为假，退化成"最大子数组和"的 DP。
- `k == 0`：窗口为空，`dp[i] = nums[i]`，答案 = 最大单元素。代码里 `dq.peekFirst() < i` 会把所有旧元素弹掉 ✅

> 参考实现：**仓库中没有本题实现（已用 `grep -r constrainedSubsetSum src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：时间 `O(n)`（每个下标最多进/出队一次）；空间 `O(n)`（`dp` 数组 + 队列）。

*带限制的子序列和是【DP + 单调队列优化】的模板，关键突破点是【把转移里的"枚举前 k 个前驱"换成"窗口内 dp 最大值"，用单调队列 O(1) 取出】，边界是【best 要 max(0,...) 表示可以重新开始；答案初值用 MIN_VALUE 因为要求非空；单调性比较的是 dp 不是 nums】。*

## 四、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 用 `Queue` 而不是 `Deque` | 没有 `pollLast`，队尾淘汰写不出来 | 用 `Deque` + `ArrayDeque` |
| 步骤顺序写成"先单调性后过期" | 逻辑因果颠倒，边界条件下容易出错 | 固定：① 过期 → ② 单调 → ③ 入队 → ④ 取答案 |
| 队首过期判断写成 `< i - k` | 恰好滑出边界的元素没被删，取到过期最大值 | `<= i - k`（下标 `i-k` 已经不在窗口里） |
| `while` 写成 `if` | 队尾可能有多个矮个子，一个 `if` 清不完 | 两处都用 `while` |
| 忘了 `if (i >= k - 1)` 就取答案 | 前 `k-1` 轮取到"残缺窗口"的最大值 | 等窗口形成再记录 |
| `res` 长度写成 `n` 或 `n - k` | 越界或多出无效位 | `n - k + 1` |
| `k > n` 时不早退 | `NegativeArraySizeException` | 开头 `if (k > n) return new int[0];` |
| 队列里存值但需要处理重复值 | 无法区分哪一份副本该弹出 | 存下标；或在严格递减（无重复）时存值 |
| 1438 收缩时直接 `pollFirst` 两个队列 | 删掉了仍在窗口内的元素 | 只在 `peekFirst() == left` 时删 |
| 1425 单调性按 `nums` 比较 | DP 转移取错前驱，答案错误 | 比较 `dp` 值 |
| 1425 答案初值用 0 | 全负数时错误输出 0 | 用 `Integer.MIN_VALUE` |
| `PriorityQueue` 比较器写 `a - b` | 大数溢出，排序错乱 | 用 `Integer.compare(a, b)` |
