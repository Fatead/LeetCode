# 02 单调栈

> **一句话理解**：单调栈是"**用栈维护一个单调序列，每来一个新元素就把所有被它'淘汰'的元素一次性结清**"——每个元素只入栈一次、出栈一次，所以是 `O(n)`，专门解决**"下一个更大 / 更小元素"**这一类问题。

---

## 一、什么时候能用单调栈

### 判定标准

单调栈的适用条件只有一条，但要看得很准：

> **每个元素都在等一个"首次出现的、能满足比较关系的后来者"，而且"等待者"之间天然有序。**

具体信号：

| 题目字眼 | 该用哪种栈 | 举例 |
| --- | --- | --- |
| 下一个更大元素 / 更高气温 | 单调**递减**栈（栈底大、栈顶小） | 739、496、503、1019 |
| 下一个更小元素 | 单调**递增**栈 | 907、2104 |
| 左边/右边第一个比它大（小）的 | 单调栈 + 记录边界 | 84、42、85 |
| "不能出现某个大小关系"（132、231） | 单调栈维护"被淘汰过的最大值" | 456 |
| 字典序最小 / 去掉 k 位数字 | 单调栈 + 贪心（"比我大又还能再出现"就弹掉） | 316、402、1081 |
| 柱状图 / 凹槽 / 面积 / 接水 | 单调栈求左右边界 | 42、84、85、1504 |

### 什么时候**不能**用

| 场景 | 为什么不行 |
| --- | --- |
| 求"下一个更大元素"但数组会**动态修改** | 单调栈只支持"只增不减"的静态扫描，动态要线段树 |
| 求"任意区间的最小值"（无顺序要求） | 这是 RMQ，用稀疏表/线段树 |
| 求"前 k 个最大元素" | 用优先队列（堆），单调栈不关心全局大小 |
| 判等 / 配对（括号） | 那是普通栈，不需要单调性 |
| 求"滑动窗口最值" | 那是[单调队列](03-单调队列.md)，两端都会动 |

## 二、Java 通用模板（求下一个更大元素）

```java
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

/**
 * 单调栈模板：求每个元素的"下一个更大元素"（Next Greater Element）
 *
 * 栈里存【下标】，不存值 —— 因为答案通常要按下标回填。
 * 栈对应的 nums 值从栈底到栈顶【单调递减】（严格递减或非递增按题意定）。
 *
 * @return res[i] = nums[i] 右边第一个 > nums[i] 的元素下标；不存在填 -1
 */
public int[] nextGreaterIndex(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);                       // ① 先默认"不存在"
    Deque<Integer> stack = new ArrayDeque<>();  // 栈里放下标

    for (int i = 0; i < n; i++) {
        // ② 当前值比栈顶对应的值大 → 栈顶元素"等到了它的答案"
        while (!stack.isEmpty() && nums[i] > nums[stack.peek()]) {
            res[stack.pop()] = i;               // 弹出并结清
        }
        stack.push(i);                          // ③ 自己也进栈，继续等
    }
    return res;                                 // ④ 循环结束时栈里剩下的都是"永远等不到"的
}
```

### 关键点逐条解释

#### ① 为什么先 `Arrays.fill(res, -1)`？

因为"等不到更大元素"的元素会一直留在栈里，直到循环结束都没被结清。把 -1 作为默认值，就不用再写"循环结束后把栈里剩下的都赋值 -1"这一步。**注意：如果题目要求填 0（如 1019），就 `fill(res, 0)`。**

#### ② 为什么用 `while` 而不是 `if`？

因为**一个元素可能同时是多个人的答案**。

```
nums = [1, 2, 3]
i=0: 栈空 → push 0          stack=[0]        （值 1）
i=1: nums[1]=2 > nums[0]=1 → res[0]=1, pop   stack=[]  → push 1   （值 2）
i=2: nums[2]=3 > nums[1]=2 → res[1]=2, pop   stack=[]  → push 2   （值 3）

这里每次只弹一个，看不出差别。换一个例子：

nums = [5, 1, 2, 6]
i=0: push 0                      stack=[0]            （值 5）
i=1: 1 < 5，不弹 → push 1         stack=[0,1]          （值 5,1）
i=2: 2 > 1 → res[1]=2, pop        stack=[0]  ← 还有！2 也 > 5 吗？不，2 < 5，停
     → push 2                      stack=[0,2]          （值 5,2）
i=3: 6 > 2 → res[2]=3, pop        stack=[0]  ← 6 > 5，继续！
     6 > 5 → res[0]=3, pop        stack=[]    ← 一次 i=3 结清了两个人
     → push 3
```

如果写成 `if`，`i=3` 时只会结清 `stack` 顶部的 `2`，`5` 就被永久压住了 —— **答案会漏**。

#### ③ 为什么要 `push(i)` 放在 `while` 之后？

因为必须先让新元素**结清所有比它小的老元素**，它自己才有资格进栈。如果先 `push`，新元素会被自己"淘汰"掉（`nums[i] > nums[i]` 为假，倒也还好），但更重要的是：栈里出现"先大后小"的顺序就破坏了单调性。**顺序是"先结算，再入栈"。**

#### ④ 循环结束时栈里剩下什么？

一定是**从栈底到栈顶递减**的一段序列，它们的共同点是"右边没有更大的了"。这正是 `Arrays.fill(res, -1)` 的用处。

### 循环不变量（正确性论证）

> 在 for 循环的**每一次迭代开始前**，栈中存放的下标 `i₁ < i₂ < ... < iₖ`（从栈底到栈顶）满足：
> 1. `nums[i₁] > nums[i₂] > ... > nums[iₖ]`（严格单调递减）；
> 2. 对所有还在栈中的 `iⱼ`，`nums[iⱼ]` 在 `(iⱼ, i)` 区间内没有更大的元素，即它们**仍在等待**；
> 3. 所有不在栈中的下标，其 `res` 值**已经**被正确填写。

**归纳**：
- **初始**：栈空，三条都平凡成立。
- **保持**：处理 `nums[i]` 时，`while` 把所有 `nums[stack.peek()] < nums[i]` 的栈顶弹出。对每个被弹出的 `j`：`(j, i)` 内没有更大的（由不变量 2），而 `nums[i]` 更大，所以 `i` 正是 `j` 的下一个更大元素，`res[j] = i` 正确（不变量 3 得到维持）。弹出后栈顶的 `nums` 值一定 `≥ nums[i]`，再 `push(i)`，单调性（不变量 1）保持。
- **终止**：循环结束时，栈中每个 `j` 的右侧都没有更大元素，`res[j] = -1` 正确。

### 为什么均摊是 `O(n)`（而不是 `O(n^2)`）

外层 `for` 走 `n` 次，内层 `while` 看起来可能很长，但用**摊还分析**看：

> **每个下标最多被 `push` 一次，因此也最多被 `pop` 一次。**

`while` 的总执行次数 = 所有 `pop` 的总次数 ≤ `n`。所以：

```
总代价 = n（push）+ ≤ n（pop）= O(n)
```

**这和滑动窗口的"每个元素最多进出窗口一次"是同一个论证。**

```
摊销示意（n = 6）：
push 次数: ▮▮▮▮▮▮  = 6
pop  次数: ▮▮▮▮▮   ≤ 6
────────────────────────
合计 ≤ 2n  →  O(n)
```

> ⚠️ 但注意：如果你在 `while` 里对**栈内每个元素**做 `O(1)` 之外的额外工作（比如再遍历一次栈），摊还分析就失效了。单调栈的每次 `pop` 必须只做常数级工作。

## 三、四种变体速查

| 变体 | `while` 条件 | 栈内单调性 | 回填的答案 |
| --- | --- | --- | --- |
| 下一个**更大**元素 | `nums[peek] < nums[i]` | 从底到顶**递减** | `res[pop] = nums[i]` |
| 下一个**更小**元素 | `nums[peek] > nums[i]` | 从底到顶**递增** | `res[pop] = nums[i]` |
| 左边第一个更大（从左往右扫完，栈里比它小的都弹掉后，栈顶就是左边第一个更大的） | `nums[peek] <= nums[i]` | 递减 | 弹完后 `res[i] = peek` |
| 前面**更小**元素的边界（柱状图） | `h[peek] >= h[i]` | 递增 | 弹完后 `left[i] = peek` |

> **取 `<` 还是 `<=`？** 这是最阴险的细节。求"严格更大"用 `<`；求"非严格更大（大于等于也算）"用 `<=`。柱状图/接雨水这类"求左右第一个严格矮于自己的柱子"的题，用 `>=` 弹出（相等时也弹，宽度由左边界重新算），保证不漏。

## 四、典型例题

### 4.1 LeetCode 739. 每日温度

**题意**：`temperatures[i]` 是第 `i` 天的气温，返回 `answer[i]` = 下一个更高气温出现在几天后，没有则 0。

**思路（先暴力再优化）**：暴力对每个 `i` 向右扫第一个更大的，最坏 `O(n^2)`（气温递减时会扫到末尾）。**冗余在于"每个 i 都在重复扫描同一段后面的数据"**。单调栈把这层重复去掉：当第 `i` 天的气温结清了前面若干天时，那几天**再也不需要被扫描**了。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] res = new int[n];                      // 默认 0，正好对应"没有更高气温"
    Deque<Integer> stack = new ArrayDeque<>();   // 存下标，对应气温单调不增

    for (int i = 0; i < n; i++) {
        // ★ 严格大于才结清：气温相等不算"更高"
        while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
            int prev = stack.pop();
            res[prev] = i - prev;                // 天数差就是"等了几天"
        }
        stack.push(i);
    }
    return res;                                  // 剩下的自动是 0，不用补
}
```

**边界**：
- `n == 0`：`new int[0]`，循环不执行，返回空数组 ✅
- `n == 1`：push 0 后结束，`res = [0]` ✅
- 气温全部相等：`>` 永远为假，最后 `res` 全 0 ✅

> 参考实现：[src/stack/DailyTemperatures.java](../src/stack/DailyTemperatures.java)（**仓库版本**：`dailyTemperatures` 是暴力 `O(n^2)`，`dailyTemperatures2` 是标准单调栈，与上面写法一致，注释明确写了"单调栈中放的是数组中的序号"）

**复杂度**：时间 `O(n)`，摊还（每个下标进出栈各一次）；空间 `O(n)`（栈最坏装下全部下标）。

*每日温度是【单调栈·下一个更大】的模板，关键突破点是【把"向右找第一个更大"变成"入栈等待 + 被更大者结清"，均摊 O(n)】，边界是【严格大于才结清；剩余在栈里的元素答案天然是 0】。*

### 4.2 LeetCode 496 / 503. 下一个更大元素 I / II

**题意**：
- **496**：`nums1` 是 `nums2` 的子集，对每个 `nums1[i]` 找它在 `nums2` 里的下一个更大元素。
- **503**：数组是**循环**的（末尾后面接开头），找每个元素的下一个更大元素。

**思路（先暴力再优化）**：
- 496 的暴力是双重循环 + 内层再扫，`O(n·m)`。优化点是：**"nums2 里每个元素的下一个更大元素"和 nums1 无关，可以预先整体算一次，用哈希表存下来。**
- 503 的暴力是"从 `i+1` 出发绕一圈"，`O(n^2)`。优化点是：**把数组"接长"成两倍，用同一个单调栈跑，取模即可。**

#### 496 的代码：先算 nums2，再查表

```java
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.HashMap;
import java.util.Map;

public int[] nextGreaterElement(int[] nums1, int[] nums2) {
    // ① 用单调栈一次性求出 nums2 里每个元素的"下一个更大值"
    Map<Integer, Integer> nextGreater = new HashMap<>();
    Deque<Integer> stack = new ArrayDeque<>();     // 存值（因为答案要按值查表）

    for (int x : nums2) {
        while (!stack.isEmpty() && stack.peek() < x) {
            nextGreater.put(stack.pop(), x);       // 栈顶等到了它的答案 x
        }
        stack.push(x);
    }
    // ② 栈里剩下的元素没有下一个更大值
    while (!stack.isEmpty()) {
        nextGreater.put(stack.pop(), -1);
    }
    // ③ 按 nums1 查表
    int[] res = new int[nums1.length];
    for (int i = 0; i < nums1.length; i++) {
        res[i] = nextGreater.getOrDefault(nums1[i], -1);
    }
    return res;
}
```

**为什么这里栈可以存"值"而不是下标？** 因为 `nums2` 元素互不相同（题目保证），值本身就能当唯一标识；而答案是**值**不是下标，所以直接存值更省事。**这是"栈里存值还是存下标"的判断标准：下一步要按下标回填就存下标，要按值查表就存值。**

#### 503 的代码：取模遍历两轮

```java
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Deque;

public int[] nextGreaterElements(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    Arrays.fill(res, -1);
    Deque<Integer> stack = new ArrayDeque<>();     // 存下标

    // ★ 遍历 2n-1 次：最多只需要绕一圈就能确定"有没有更大的"
    for (int i = 0; i < 2 * n - 1; i++) {
        int cur = nums[i % n];                     // 取模实现"循环"
        while (!stack.isEmpty() && nums[stack.peek()] < cur) {
            res[stack.pop()] = cur;
        }
        if (i < n) {
            stack.push(i);                         // ★ 只在第一轮入栈，避免重复入栈
        }
    }
    return res;
}
```

**为什么是 `2n - 1` 次而不是 `2n` 次？**

```
n = 3, nums = [1,2,1]
索引:   0    1    2    3(=0)  4(=1)   5(=2) ← 这个不需要
值:     1    2    1    1      2
        └──── 第一轮 ────┘└── 第二轮 ──┘

对每个 i，最远只需要看它后面的 n-1 个元素。
i = 0 要看 1,2；i = 1 要看 2,0；i = 2 要看 0,1。
把下标展开成 0..2n-2（共 2n-1 个），每个 i 的"窗口 [i, i+n-1]"都在其中。
多跑一次（到 2n-1）会重复处理 i=0，结果不变但白费 —— 所以取 2n-1。
```

**为什么第二轮不能 `push`？** 因为第二轮的 `i % n` 已经在栈里了。重复入栈会让同一个下标在栈中出现两次，虽然通常不会算错（第二次弹出时 `res` 已被赋值或本来就该是 -1），但会让摊还分析失效、栈深度翻倍。**加一行 `if (i < n)` 是标准写法。**

> 参考实现：[src/stack/NextGreaterElement.java](../src/stack/NextGreaterElement.java)（**仓库版本**：`nextGreaterElement` 是三重暴力，`nextGreaterElement2` 是单调栈 + `HashMap`，思路与上面 496 解法一致）、[src/stack/NextGreaterElement2.java](../src/stack/NextGreaterElement2.java)（**仓库版本是 O(n²) 暴力**：用 `while (j != i)` + `j % n` 逐格找，**没有用单调栈**，n 大时会超时；建议用上面 503 的取模双轮写法）

**复杂度**：
- 496：时间 `O(n + m)`；空间 `O(m)`（哈希表 + 栈）。
- 503：时间 `O(n)`（`2n-1` 次迭代，摊还）；空间 `O(n)`。

*下一个更大元素是【单调栈 + 哈希/取模】的模板，关键突破点是【496 把"多次询问"变成"一次预处理 + 查表"，503 把"循环数组"变成"取模跑两轮"】，边界是【503 只在第一轮入栈、循环上界是 2n-1】。*

### 4.3 LeetCode 42. 接雨水

**题意**：`height[i]` 是宽度为 1 的柱子高度，求下雨后能接多少单位的雨水。

**题意转化**：位置 `i` 上方的水量 = `min(左边最高, 右边最高) - height[i]`（若为负则取 0）。

**思路（先暴力再优化）**：

| 解法 | 做法 | 时间 | 空间 |
| --- | --- | --- | --- |
| 暴力 | 对每个 `i` 向左向右各扫一遍求 `leftMax`、`rightMax` | `O(n^2)` | `O(1)` |
| 预处理数组 | 提前算好 `leftMax[]` 和 `rightMax[]` | `O(n)` | `O(n)` |
| **单调栈** | 按"行"横向累加，一层层填凹槽 | `O(n)` | `O(n)` |
| **双指针** | 两端向中间夹，谁矮结算谁 | `O(n)` | `O(1)` |

暴力的冗余是"每个位置都重扫一遍找两侧最大值"。

#### 解法一：单调栈（按"层"累加）

**为什么单调栈能做接雨水？** 因为每形成一个"凹槽"（左高、中低、右高），就能立刻算出这一层的面积，而单调栈正好在"新柱子比栈顶高"时识别出凹槽。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int trap(int[] height) {
    Deque<Integer> stack = new ArrayDeque<>();   // 存下标，对应高度【单调不增】
    int water = 0;

    for (int i = 0; i < height.length; i++) {
        while (!stack.isEmpty() && height[i] > height[stack.peek()]) {
            int bottom = stack.pop();            // 凹槽的底部
            if (stack.isEmpty()) {
                break;                           // ★ 左边没有墙了，这一层接不住水
            }
            int left = stack.peek();             // 左边第一面比 bottom 高的墙
            int h = Math.min(height[left], height[i]) - height[bottom];  // 水层高度
            int w = i - left - 1;                // 水层宽度（不含两端墙体）
            water += h * w;
        }
        stack.push(i);
    }
    return water;
}
```

**`if (stack.isEmpty()) break;` 为什么是必须的？**

```
height = [3, 1, 2]          想接水但没有左墙

i=0: push 0                 stack=[0]            （高 3）
i=1: 1 < 3，不弹 → push 1    stack=[0,1]          （高 3,1）
i=2: 2 > 1 → bottom = pop(1)  stack=[0]  ← 非空，有左墙！
     left = 0, h = min(3,2) - 1 = 1, w = 2-0-1 = 1 → water += 1
     stack=[0]；2 < 3 不继续弹 → push 2

而 height = [1, 2]：
i=1: 2 > 1 → bottom = pop(0)  stack=[]  ← 空了！说明 1 的左边没有墙
     break（否则 height[stack.peek()] 会越界 / 逻辑错误）
```

**不加这句会怎样？** `stack.peek()` 在空栈上会抛 `NoSuchElementException`（`ArrayDeque.peek()` 返回 `null`，拆箱成 `int` 时 NPE）。就算不崩，逻辑上"左边没有墙"也不该累加水量。

**为什么宽度是 `i - left - 1`？** 因为水只存在两根墙**之间**，两端的墙本身不装水。

```
height = [0,1,0,2,1,0,1,3,2,1,2,1]

i=0: push 0
i=1: 1>0 → bottom=0, 弹后栈空 → break；push 1
i=2: 0<1 → push 2                      stack=[1,2]
i=3: 2>0 → bottom=2, left=1, h=min(1,2)-0=1, w=3-1-1=1 → water=1
     2>1 → bottom=1, 弹后栈空 → break；push 3
...
最终 water = 6
```

#### 解法二：双指针（`O(1)` 额外空间）

**核心洞察**：`i` 处的水量只取决于 `min(leftMax, rightMax)`。如果我们知道 `leftMax < rightMax`，那么 `i` 处的水量**就已经确定**为 `leftMax - height[i]`，因为右边的墙实际多高都不影响这个 `min`。

```java
public int trap2(int[] height) {
    int left = 0, right = height.length - 1;
    int leftMax = 0, rightMax = 0;
    int water = 0;

    while (left < right) {
        leftMax = Math.max(leftMax, height[left]);    // 更新左指针见过的最大值
        rightMax = Math.max(rightMax, height[right]); // 更新右指针见过的最大值

        if (leftMax < rightMax) {
            // ★ 左侧最大值更小 → 答案由 leftMax 决定，left 位置可以结算了
            water += leftMax - height[left];
            left++;
        } else {
            water += rightMax - height[right];
            right--;
        }
    }
    return water;
}
```

**为什么 `leftMax < rightMax` 时 `left` 位置的水量一定确定？**

因为我们维护的 `rightMax` 是"`right` 及其右边所有元素的最大值"，所以真实右侧最大值 `realRightMax ≥ rightMax > leftMax`。因此 `min(leftMax, realRightMax) = leftMax` —— 与右边到底是什么无关。**这就是双指针能正确工作的关键：只结算"矮的那一侧"。**

**边界**：`n <= 1` 时 `while` 不执行，返回 0 ✅；`left == right` 时不必处理，因为该位置 `leftMax - height[left] == 0`。

> 参考实现：[src/stack/RainPool.java](../src/stack/RainPool.java)（**仓库版本**是标准的单调栈解法，变量名 `h / dis / min`，与上面写法等价；**仓库里没有双指针版本**）

**复杂度**：单调栈 `O(n)` 时间 / `O(n)` 空间；双指针 `O(n)` 时间 / `O(1)` 空间。

*接雨水是【单调栈按层累加 / 双指针只结算矮侧】的模板，关键突破点是【把"每个位置两侧最高"转化成"凹槽逐层填"或"只结算确定的一侧"】，边界是【单调栈弹出后栈空必须 break；双指针循环用 left < right 且最后一个位置贡献为 0】。*

### 4.4 LeetCode 84. 柱状图中最大的矩形

**题意**：给定柱状图高度数组，求其中能勾勒出的最大矩形面积。

**思路（先暴力再优化）**：暴力枚举"以 `i` 为高的矩形向左向右各能延伸多远"，`O(n^2)`。单调栈的优化点在于：**`i` 的左右边界（第一个比它矮的柱子）可以在弹栈时一并确定**。

**关键转化**：对每根柱子 `i`，以 `height[i]` 为高的最大矩形宽度 = `右边界 - 左边界 - 1`。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public int largestRectangleArea(int[] heights) {
    int n = heights.length;
    // ★ 哨兵技巧：首尾各加一个高度 0
    int[] h = new int[n + 2];
    System.arraycopy(heights, 0, h, 1, n);

    Deque<Integer> stack = new ArrayDeque<>();   // 存下标，对应高度【单调递增】
    int maxArea = 0;

    for (int i = 0; i < h.length; i++) {
        while (!stack.isEmpty() && h[stack.peek()] > h[i]) {  // 相等不弹（见下）
            int height = h[stack.pop()];
            // ★ 弹出后新的栈顶就是"左边第一个比 height 矮的柱子"（哨兵保证非空）
            int width = i - stack.peek() - 1;
            maxArea = Math.max(maxArea, height * width);
        }
        stack.push(i);
    }
    return maxArea;
}
```

**哨兵为什么这么重要？**

| 哨兵 | 位置 | 作用 |
| --- | --- | --- |
| 头部 `h[0] = 0` | 数组最左 | 保证**任何柱子弹出后栈都不会空**，`stack.peek()` 一定合法，省掉 `if (stack.isEmpty())` 分支 |
| 尾部 `h[n+1] = 0` | 数组最右 | 强制**所有柱子都在最后被弹出结算**，省掉"循环结束后再清栈"的收尾代码 |

```
heights = [2, 1, 5, 6, 2, 3]
h       = [0, 2, 1, 5, 6, 2, 3, 0]
i:        0  1  2  3  4  5  6  7

i=0: push 0                         stack=[0]
i=1: h[1]=2 > h[0]=0 → push 1        stack=[0,1]      （0,2）
i=2: h[2]=1 < h[1]=2 → height=2, pop(1), width=2-0-1=1, area=2
     h[2]=1 不 < h[0]=0 → push 2     stack=[0,2]      （0,1）
i=3: push 3                         stack=[0,2,3]    （0,1,5）
i=4: push 4                         stack=[0,2,3,4]  （0,1,5,6）
i=5: h[5]=2 < h[4]=6 → height=6, pop(4), width=5-3-1=1, area=6
     h[5]=2 < h[3]=5 → height=5, pop(3), width=5-2-1=2, area=10  ← 最大 10
     h[5]=2 不 < h[2]=1 → push 5
i=6: h[6]=3 > h[5]=2 → push 6        stack=[0,2,5,6]
i=7: h[7]=0 → 全部弹出结算
     height=3,pop(6),width=7-5-1=1 → 3
     height=2,pop(5),width=7-2-1=4 → 8
     height=1,pop(2),width=7-0-1=6 → 6
     最后 h[0]=0 不 > 0 → 结束（哨兵 0 留在栈里）
maxArea = 10 ✅
```

**为什么用 `>` 而不是 `>=`？**

用 `>=` 也能得到正确答案（相等时提前弹掉，右边的同高柱子会算出更宽的宽度），但 `>` 更标准：**让相同高度的柱子尽量延后结算，最后一个同高柱子会算出包含全部同高柱子的最大宽度**。两种都能过，但**全篇要一致**，不要一半 `>` 一半 `>=`。

**边界**：
- `heights` 为空：`n = 0`，`h = [0, 0]`，`i=0` push，`i=1` 时 `h[1]=0` 不 `> h[0]=0`，直接 push 结束，`maxArea = 0` ✅
- 全是 0：`maxArea = 0` ✅
- 单调递增：所有柱子都在尾部哨兵处被弹出，宽度正确 ✅

> 参考实现：**仓库中没有本题实现（已用 `grep -r largestRectangleArea src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：时间 `O(n)`（每个下标进出栈各一次）；空间 `O(n)`（栈 + 哨兵数组）。

*柱状图最大矩形是【单调栈求左右边界 + 哨兵】的模板，关键突破点是【弹出时新栈顶就是左边界，`i` 就是右边界，宽度一次算完；首尾哨兵省掉所有边界判断】，边界是【空数组、全 0、单调递增都要能过；`>` 与 `>=` 全篇统一】。*

### 4.5 LeetCode 456. 132 模式

**题意**：判断是否存在下标 `i < j < k` 使得 `nums[i] < nums[k] < nums[j]`（即 1-3-2 的大小关系）。

**思路（先暴力再优化）**：暴力枚举三元组 `O(n^3)`；固定 `j` 再向两边找 `O(n^2)`。优化点在于：**从右往左扫，用单调栈维护"可以作为 3 的候选者"，同时记录被淘汰的 3 中的最小值 `maxK`。**

**为什么 `maxK` 是"被淘汰的 3 的最小值"？** 因为我们从右往左扫，`nums[i]` 是最后的 1。我们希望存在某个 `k > i` 且 `nums[k] < nums[j]`。在单调栈里，凡是"被 `nums[i]` 弹出去的"都是曾经当过 3 的候选者，它们的值就是候选的 `nums[k]`。为了让 `< maxK` 更容易成立（更容易找到 1），我们要 `maxK` **尽可能大** —— 但又要保证 `maxK < 3 的值`。所以取"被弹出的所有元素里的**最大值**"（弹出时不断更新，等价于取最大）。仓库注释里叫 `maxK`，是"当前能拿到的最大 k 值"。

```java
import java.util.ArrayDeque;
import java.util.Deque;

public boolean find132pattern(int[] nums) {
    int n = nums.length;
    if (n < 3) {
        return false;                             // ★ 少于 3 个元素不可能构成 132
    }
    Deque<Integer> stack = new ArrayDeque<>();    // 存候选的"3"（值），从底到顶递增
    stack.push(nums[n - 1]);                      // 最右边的元素先当候选
    int maxK = Integer.MIN_VALUE;                 // 已被淘汰的候选"3"里的最大值 = 最佳的"2"

    for (int i = n - 2; i >= 0; i--) {
        if (nums[i] < maxK) {
            return true;                          // ★ 找到了 1：nums[i] < maxK(=2) < 某个 3
        }
        while (!stack.isEmpty() && nums[i] > stack.peek()) {
            maxK = Math.max(maxK, stack.pop());    // 被 nums[i] 淘汰的候选，转为 2
        }
        stack.push(nums[i]);                      // nums[i] 作为新的候选 3
    }
    return false;
}
```

**正确性论证**：

- 若 `nums[i] < maxK` 成立，则存在一个此前被弹出的值 `v = maxK`，它满足 `nums[i] < v`，且 `v` 是被某个 `nums[j]`（`j > i`，因为是从右往左扫）弹出的，弹出条件是 `nums[j] > v`。于是 `nums[i] < v < nums[j]` 且 `i < j`，同时 `v` 的位置 `k > j > i`。三者下标递增、大小 1<2<3 关系为 `nums[i] < nums[k] < nums[j]` ✅
- `maxK` 的更新是单调不减的，所以先被检查的 `nums[i]`（更靠右）用的是当时已知的最大 `maxK`，这是**最优选择**——如果连最大的 `maxK` 都不满足 `nums[i] < maxK`，更小的更不满足。

**边界**：
- `n < 3`：`[]`、`[1]`、`[1,2]` 都不可能有 132 模式 → 早退。**这是仓库版本缺失的判断**：仓库直接写 `nums[n - 1]`，`n == 0` 时会 `ArrayIndexOutOfBoundsException`（LeetCode 保证 `n ≥ 1`，所以能过，但本地跑空数组会崩）。
- `n == 3` 且 `[1,3,2]`：`stack=[2]`，`maxK=MIN`；`i=1`：`3 < MIN`? no；`3 > 2` → `maxK=2`，pop，push 3；`i=0`：`1 < 2` → `return true` ✅

> 参考实现：[src/stack/Find132Pattern.java](../src/stack/Find132Pattern.java)（**仓库版本**与上面完全一致，用 `LinkedList` 当 `Deque`，变量名 `candidateK / maxK`；**缺少 `n < 3` 的早退判断**，建议补上）

**复杂度**：时间 `O(n)`（每个元素最多进出栈一次）；空间 `O(n)`。

*132 模式是【逆序单调栈 + 被淘汰者记录】的模板，关键突破点是【从右往左扫，把"被更大元素弹出的候选"转化成可用的 2，并只保留其中最大的那个】，边界是【n < 3 必须早退，否则空数组会越界】。*

### 4.6 LeetCode 316. 去除重复字母

**题意**：去掉字符串中重复的字母，使每个字母只出现一次，且结果的**字典序最小**（不能打乱相对顺序）。

**思路（先暴力再优化）**：暴力是枚举所有子序列 + 合法性检查，指数级。优化点在于：**逐字符贪心——只要"栈顶字符比当前字符大"且"栈顶字符后面还会再出现"，就把它弹掉，让更小的字符顶上来。**

```java
import java.util.ArrayDeque;
import java.util.Deque;

public String removeDuplicateLetters(String s) {
    int[] last = new int[26];                       // 每个字母最后出现的位置
    for (int i = 0; i < s.length(); i++) {
        last[s.charAt(i) - 'a'] = i;
    }
    boolean[] used = new boolean[26];               // 是否已在结果栈里
    Deque<Character> stack = new ArrayDeque<>();

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (used[c - 'a']) {
            continue;                               // ★ 已在栈里，跳过（否则会重复）
        }
        // ★ 弹栈的两个条件必须同时成立，缺一不可
        while (!stack.isEmpty()
                && stack.peek() > c                 // ① 栈顶更大，弹掉能让字典序更小
                && last[stack.peek() - 'a'] > i) {  // ② 栈顶后面还会再出现，弹掉不会丢它
            used[stack.pop() - 'a'] = false;        // 弹掉后要"解除标记"
        }
        stack.push(c);
        used[c - 'a'] = true;
    }

    StringBuilder sb = new StringBuilder();
    while (!stack.isEmpty()) {
        sb.append(stack.pop());
    }
    return sb.reverse().toString();                 // 栈是倒序的，要翻转
}
```

**为什么两个条件缺一不可？**

```
s = "bcabc"

      条件① 栈顶更大    条件② 栈顶后面还有    动作
i=0 b: —                              push b      stack=[b]
i=1 c: b < c → ①不成立                push c      stack=[b,c]
i=2 a: c > a ✓ ; last[c]=3 > 2 ✓     pop c       stack=[b]
       b > a ✓ ; last[b]=1 > 2 ✗     停          ← 关键！b 后面没有了，弹了就丢
                                     push a      stack=[b,a]
i=3 b: used[b] → skip                             stack=[b,a]
i=4 c: b < c? 栈顶是 a，a < c → ①不成立 push c      stack=[b,a,c]
结果：栈底→栈顶 = b,a,c → 反转 → "cab"  ✅（字典序最小）
```

如果少了条件②，`i=2` 时会把 `b` 也弹掉，结果变成 `"abc"` —— 但 `b` 在 `"bcabc"` 里只在位置 1 出现过，丢了就不合法。

**为什么必须先 `used` 判重？** 因为 `"bbca"` 这类输入里同一个字母会出现多次，第二次遇到时它已经在栈里了，再 push 就会重复。

**`used[x] = false` 为什么必须在 `pop` 的同时做？** 因为 `used` 的语义是"当前在栈里"，弹出后就不在了，必须同步复位，否则后续再也无法把这个字母放回栈。

**边界**：
- 空串：循环不执行，`sb` 为空，`reverse` 后返回 `""` ✅
- 全相同 `"aaaa"`：`i=0` push a；`i=1..3` 都 `used` → skip；返回 `"a"` ✅
- `last[stack.peek() - 'a'] > i` 用的是 `>` 而不是 `>=`：因为 `i` 位置上就是 `c` 自己，`last == i` 只在当前字符上成立，`>` 更严谨（实际上 `>=` 也等价，因为当前字符不可能在栈顶，已 `used` 判过）。

> 参考实现：**仓库中没有本题实现（已用 `grep -r removeDuplicateLetters src/` 确认无匹配）**，上面是推荐版本。

**复杂度**：时间 `O(n)`（每个字符最多进出栈一次，`last` 预处理 `O(n)`）；空间 `O(1)`（`last`/`used` 固定 26 大小 + 栈最多 26）。

*去除重复字母是【单调栈 + 贪心（后面还有就敢弹）】的模板，关键突破点是【"栈顶更大"且"栈顶后面还会出现"两个条件同时满足才弹，保证既最小又不丢字符】，边界是【已入栈的要 skip，弹出时必须复位 used，最后要 reverse】。*

## 五、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| `while` 写成 `if` | 一次只结清一个等待者，答案漏 | 必须用 `while` |
| `push(i)` 写在 `while` 之前 | 破坏栈的单调性，弹出逻辑全乱 | 先结算，再入栈 |
| 忘记 `Arrays.fill(res, -1)` | 栈里剩的元素是 0，而题目要 -1 | 按题目默认值初始化为 -1 或 0 |
| 求"严格更大"却用 `>=` | 相等元素被错误结清 / 被错误保留 | 严格用 `<`/`>`，非严格用 `<=`/`>=`，全篇统一 |
| 栈里存值却又想按下标回填 | 遇到重复值无法区分 | 要下标就存下标，要按值查表才存值 |
| 503 忘写 `if (i < n)` | 同一位置重复入栈，栈深度翻倍 | 只在第一轮 `push` |
| 503 循环写成 `2 * n` | 白跑一轮，结果不变但效率差 | 上界取 `2 * n - 1` |
| 接雨水弹出后不判 `stack.isEmpty()` | `ArrayDeque.peek()` 拆箱 NPE | 空栈时 `break`（左边没墙，接不住水） |
| 柱状图宽度写成 `i - left` | 把墙自己算进宽度，答案偏大 | `i - left - 1` |
| 柱状图不加哨兵 | 需要一堆 `isEmpty` 分支和收尾清栈，易错 | 首尾各加一个高度 0 |
| 132 模式不判 `n < 3` | 空数组越界 | 开头 `if (n < 3) return false;` |
| 316 弹出时忘记 `used[x] = false` | 该字母再也回不来 | `pop` 与复位成对出现 |
| 用 `ArrayDeque` 存 `null` | 抛 `NullPointerException` | 存哨兵值如 `-1` 或用 `LinkedList` |
