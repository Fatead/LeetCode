# 01 递归思维与三要素

> **一句话理解**：递归就是**把"规模为 n 的问题"变成"规模更小的同类问题"**。
> 写递归时只需要回答三个问题：① 最小规模怎么办？② 怎么变成更小的规模？③ 下一层的答案怎么用回来？
> 这三件事就是**递归三要素**。剩下的交给数学归纳法——**你不需要在脑子里展开整个递归栈**。

---

## 一、什么时候能用递归 / 什么时候不能用

| 判定项 | 能用递归 | 不能用递归 |
| --- | --- | --- |
| 问题结构 | 能拆成"结构相同、规模更小"的子问题 | 子问题变成了**另一个问题**（结构不同） |
| 子问题独立性 | 子问题之间互不影响，各自可独立求解 | 子问题互相依赖、必须一起看全局最优 |
| 终止条件 | 存在明确的"最小规模"，且能直接求解 | 规模无法收敛到最小（参数不变或变大） |
| 递归深度 | 深度 `≤ 10^4`（链式递归尤其要注意） | 深度随 `n` 线性增长且 `n ≥ 10^5` |
| 状态表达 | 状态能完全由"参数 + 返回值"表达 | 大量共享可变状态且无法回退（那是迭代/DP 的活） |

**三句口诀**：

1. **能拆成同类小问题** → 递归
2. **每层只有一个子问题（链式递归）** → 直接用循环，别递归（白白多占 `O(n)` 栈）
3. **子问题重叠** → 递归 + 记忆化（见 [03 记忆化与递归优化](03-记忆化与递归优化.md)）；**子问题不重叠** → 纯分治（见 [02 分治算法](02-分治算法.md)）

## 二、递归三要素 + Java 通用模板

```java
/**
 * 递归三要素模板
 *
 * 【要素 0】函数语义：dfs(x) 返回的到底是什么？
 *            —— 这一行不写在代码里，但必须先想清楚，否则后面全错
 * 【要素 1】终止条件（base case）：最小规模的问题，直接给答案
 * 【要素 2】本层逻辑：把问题拆小，并决定"往下传什么状态"
 * 【要素 3】合并：拿到子结果后，算出本层答案并"往上传什么"
 *
 * 写之前先用注释把这三行填好，再写代码——这是避免递归写错最有效的手段。
 */
private int dfs(状态参数) {
    // ---------- 要素 1：终止条件（必须先写，且枚举所有边界） ----------
    if (到达最小规模) {
        return 最小规模的答案;
    }

    // ---------- 要素 2：本层逻辑（拆子问题 + 传状态） ----------
    子结果 = dfs(规模更小的状态);

    // ---------- 要素 3：合并（用子结果算本层答案） ----------
    return 合并(本层信息, 子结果);
}
```

### 2.1 要素 1：终止条件的三种常见形态

| 形态 | 触发条件 | 典型写法 |
| --- | --- | --- |
| 空结构 | 参数为 `null` / 长度为 0 | `if (root == null) return 0;` |
| 单元素 | 区间 / 链表只剩一个元素 | `if (lo == hi) return nums[lo];`、`if (head.next == null) return head;` |
| 空区间 | 左边界越过了右边界 | `if (lo > hi) { res.add(null); return res; }` |

**终止条件写错的两种后果**：

| 错误 | 后果 |
| --- | --- |
| 写少了（漏 `null` / 漏空区间） | 无限递归 → `StackOverflowError`，或直接 `NullPointerException` |
| 写多了 / 写错了 | 少算一层，答案偏小（二叉树最小深度就是最经典的例子，见例题 6） |

### 2.2 要素 2：规模必须**严格变小**

这是递归能终止的**唯一保证**。检查方法：把参数列出来，看每一层是不是朝"必然终止"的方向移动。

| 参数形式 | 怎么变小 | 陷阱 |
| --- | --- | --- |
| 区间 `[lo, hi]` | `mid = lo + (hi - lo) / 2`，递归 `[lo, mid]` 和 `[mid + 1, hi]` | 写成 `[lo, mid]` + `[mid, hi]` → 区间永远不缩小 → 死循环 |
| 整数 `n` | `n / 2`、`n - 1` | 出现 `n + 1` 时必须配合别的缩小动作 |
| 链表节点 | `node.next` | 传 `node` 自己 → 死循环 |
| 树节点 | `node.left` / `node.right` | 树上天然收敛，安全 |
| 区间长度 | `hi - lo + 1` 每层减半 | 归并排序、快速选择都靠这个 |

**自检口诀**：*参数里有没有哪个"没变小"？*

### 2.3 要素 3：合并的两种时机（前序 / 后序）

```
前序（自顶向下）：先处理本层，再递归
    doSomething(本层);
    子结果 = dfs(更小的状态);
    —— 典型：把 depth 往下带，dfs(node, depth + 1)

后序（自底向上）：先递归，拿到子结果再处理本层
    子结果1 = dfs(左);  子结果2 = dfs(右);
    return combine(本层, 子结果1, 子结果2);
    —— 典型：Math.max(left, right) + 1、合并两个有序链表
```

> **绝大多数"返回答案"的递归都是后序**。前序通常用于"往下传一个累积量"或"路径回溯"。

## 三、如何相信递归：数学归纳法视角

初学者的最大障碍是"想在脑子里把递归栈展开五层"，一展开就晕。正确的思维工具是**数学归纳法**：

```
要证明"对任意 n，dfs(n) 都返回正确答案"，只需证明两件事：
  ① 基础情形：n 取最小规模时，dfs 返回正确答案   （= 终止条件写对了）
  ② 归纳步骤：假设 dfs(k) 对一切 k < n 都返回正确答案，
              那么 dfs(n) 也能返回正确答案        （= 合并逻辑写对了）
```

**推论（写代码时的实际操作）**：

> 写递归时**只考虑本层**，不要去追子问题是怎么算出来的。
> 直接**假设 `dfs(更小的参数)` 已经返回了正确答案**（这叫"递归的信仰"），
> 然后只做一件事：**用这个正确答案，凑出本层的正确答案**。

```
❌ 错误思维："dfs(root.left) 会先算 root.left.left……然后……"
   → 一展开就崩，而且对写代码毫无帮助

✅ 正确思维："假设 dfs(root.left) 已经给了我『左子树的最大深度』，
              那本层的答案就是 max(它, 右子树深度) + 1"
   → 只关心语义，不关心过程
```

这也解释了为什么**"要素 0（函数语义）"最重要**：只有语义明确，"假设子问题已解决"才有意义。

## 四、写递归的四个步骤（可直接照做的 checklist）

| 步骤 | 做什么 | 检查点 |
| --- | --- | --- |
| 1 | 一句话写下函数语义："`dfs(x)` 返回的是……" | 不看代码能说出来吗？说不出来 → 语义没定清 |
| 2 | 枚举并写出终止条件 | 空输入 / 单元素 / 空区间，三种都想过没有？ |
| 3 | 假设子问题已解决，写本层逻辑 | 有没有"往下追递归"？追了就是错的 |
| 4 | 检查参数是否每层都变小 | 有没有死循环的可能？ |

**完整示范**（用 206 反转链表走一遍四步）：

```
第 1 步 语义：reverse(head) 返回"以 head 为头的那条链表反转后的新头"
第 2 步 终止：head == null（空链表）或 head.next == null（单节点，反转后就是自己）
第 3 步 本层：假设 reverse(head.next) 已返回反转后的新头 newHead，
             那么 head.next 现在是反转段的【尾节点】→ 让它指向 head；
             同时必须把 head.next 置空，否则 head 和后继互指 → 成环
第 4 步 变小：head.next 严格比 head 短，收敛 ✓
```

## 五、递归树与时间复杂度分析

**核心方法：画递归树，算"节点数 × 每个节点的非递归工作量"。**

```
总时间 = 递归树的节点数 × 每个节点自己的工作量（不含递归调用）
```

### 5.1 六个必须记住的递推式

| 递推式 | 递归树形状 | 复杂度 | 例子 |
| --- | --- | --- | --- |
| `T(n) = T(n-1) + O(1)` | 一条链，n 个节点 | `O(n)` | 阶乘、求 1+2+…+n |
| `T(n) = T(n-1) + O(n)` | 一条链，第 k 层做 `O(k)` | `O(n^2)` | 递归版冒泡/选择排序 |
| `T(n) = 2T(n-1) + O(1)` | 满二叉树，`2^n` 个节点 | `O(2^n)` | 汉诺塔、子集枚举 |
| `T(n) = T(n-1) + T(n-2) + O(1)` | 二叉树，节点数 ≈ `1.618^n` | `O(2^n)` | 纯递归斐波那契 |
| `T(n) = 2T(n/2) + O(n)` | 二叉树，每层 `O(n)`，共 `log n` 层 | `O(n log n)` | 归并排序 |
| `T(n) = T(n/2) + O(1)` | 一条链，`log n` 个节点 | `O(log n)` | 二分查找、快速幂 |

### 5.2 阶乘：链式递归树

```java
/** 阶乘：fact(n) 返回 n! */
public long fact(int n) {
    if (n <= 1) return 1;              // 要素 1：0! = 1! = 1（注意 0 也要覆盖）
    return (long) n * fact(n - 1);     // 要素 3：n * (n-1)!
}
```

```
fact(5)
  └─ 5 * fact(4)
        └─ 4 * fact(3)
              └─ 3 * fact(2)
                    └─ 2 * fact(1)
                          └─ 1              ← 终止条件
节点数 = 5  →  T(n) = T(n-1) + O(1) = O(n)
栈深度 = n  →  n 大时会爆栈（这就是"链式递归不该用递归"的原因）
```

> ⚠️ 仓库里没有阶乘的实现文件。

### 5.3 斐波那契：最经典的"指数级递归树"

```java
/** 纯递归斐波那契 —— 逻辑对，但性能是灾难 */
public int fib(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fib(n - 1) + fib(n - 2);
}
```

```
fib(5)
├── fib(4)
│   ├── fib(3)
│   │   ├── fib(2) ──┬── fib(1)
│   │   │            └── fib(0)
│   │   └── fib(1)
│   └── fib(2) ──────┬── fib(1)      ← 整棵子树重复！
│                    └── fib(0)
└── fib(3) ──────────┬── fib(2)      ← 整棵子树重复！
                     └── fib(1)

fib(3) 被算了 2 次，fib(2) 被算了 3 次，n 越大重复越离谱
节点数 ≈ 1.618^n  →  O(2^n)
```

**这就是"重叠子问题"**，正是 [03 记忆化与递归优化](03-记忆化与递归优化.md) 要解决的问题。先记住结论：

| n | 递归调用次数（约） | 纯递归耗时 | 记忆化 / 迭代耗时 |
| --- | --- | --- | --- |
| 20 | `2 × 10^4` | < 1 ms | < 1 ms |
| 30 | `2.7 × 10^6` | ~10 ms | < 1 ms |
| 40 | `3.3 × 10^8` | ~1 s | < 1 ms |
| 45 | `3.6 × 10^9` | ~10 s（LeetCode 必超时） | < 1 ms |

### 5.4 汉诺塔：满二叉树的递归树

**问题**：三根柱子 A/B/C，A 上有 `n` 个大小不同的盘子（大的在下），每次只能移动一个盘子且不能把大盘放在小盘上，求把 `n` 个盘子从 A 移到 C 的最少步数并输出过程。

**三要素拆解**：

| 要素 | 内容 |
| --- | --- |
| 语义 | `hanoi(n, from, to, via)`：把 `n` 个盘子从 `from` 借助 `via` 移到 `to` |
| 终止 | `n == 0` 时无事可做（没有盘子可移） |
| 本层 | ① 上面 `n-1` 个：`from → via`；② 最大的一个：`from → to`；③ 上面 `n-1` 个：`via → to` |
| 变小 | 参数 `n-1` 严格变小 ✓ |

```java
/**
 * 汉诺塔：把 n 个盘子从 from 借助 via 移到 to，返回总步数
 */
public long hanoi(int n, char from, char to, char via) {
    if (n == 0) return 0;                        // 要素 1：没有盘子可移
    long steps = 0;
    steps += hanoi(n - 1, from, via, to);        // ① 上面 n-1 个：from → via
    System.out.println(from + " -> " + to);      // ② 最大的一个：from → to
    steps += 1;
    steps += hanoi(n - 1, via, to, from);        // ③ 上面 n-1 个：via → to
    return steps;
}
```

```
n = 3 的递归树（每个节点 = 一次 hanoi 调用）

                    hanoi(3, A, C, B)
        ┌───────────────────┼───────────────────┐
hanoi(2,A,B,C)          移动 A→C          hanoi(2,B,C,A)
   ┌────┴────┐                              ┌────┴────┐
h(1)      移 A→B  h(1)                 h(1)        移 B→C   h(1)
 │                                      │
移 A→C                                 移 B→A

节点数 = 2^n - 1   →   T(n) = 2T(n-1) + O(1) = O(2^n)
最少步数 = 2^n - 1（n = 64 时是 1.8 × 10^19，这就是汉诺塔传说的"世界末日"）
```

**为什么这样拆不会漏解？** 关键在"最大的盘子在两次 `hanoi(n-1)` 递归中从未被碰过"：最大的盘子最终必须落在 `to` 的**底部**，而它一旦移动就必然是从 `from` 直接到 `to`（否则会被小盘挡住）。所以"先把上面 `n-1` 个挪开"是**必须要做的事**，不是一种选择——这就是三要素拆解的正确性依据。

## 六、递归转迭代

### 6.1 三种转法

| 转法 | 适用场景 | 做法 |
| --- | --- | --- |
| 直接改循环 | **链式递归**（函数体里只出现一次自己的调用） | 用 `while` 累加，把"传下去的累积量"变成变量 |
| 显式栈 | 树/图遍历，且递归深度会爆栈 | 自己维护 `Deque`（见章 README 第五节） |
| 转递推 + 数组 | 有重叠子问题的递归 | 就是 DP（见 [03 记忆化与递归优化](03-记忆化与递归优化.md)） |

### 6.2 链式递归 → 循环（阶乘的例子）

```java
// 递归版：O(n) 时间，O(n) 栈空间，n = 10^5 时爆栈
public long fact(int n) {
    if (n <= 1) return 1;
    return (long) n * fact(n - 1);
}

// 迭代版：O(n) 时间，O(1) 空间——链式递归根本没有递归的必要
public long factIter(int n) {
    long res = 1;
    for (int i = 2; i <= n; i++) res *= i;
    return res;
}
```

**链式递归的识别方法**：递归函数体里**只出现一次自己的调用**。只要只有一次，就能机械地改成循环——这是最省事、收益最直接的递归优化。

## 七、典型例题

### 剑指 Offer 64. 求 1+2+…+n

**题意**：求 `1+2+...+n`，要求不能使用乘除法、`for`、`while`、`if`、`else`、`switch`、`case` 等关键字及条件判断语句。

**思路**：既然不能用 `if`，就用 `&&` 的**短路特性**当条件判断。

```java
public int sumNums(int n) {
    // n > 0 为假时，&& 右边根本不执行 → 等价于 if (n > 0) { n += sumNums(n - 1); }
    boolean flag = n > 0 && (n += sumNums(n - 1)) > 0;
    return n;
}
```

**三要素对照**：

| 要素 | 内容 |
| --- | --- |
| 语义 | `sumNums(n)` 返回 `1+...+n`，并把结果留在参数 `n` 里 |
| 终止 | `n == 0` 时短路，`n` 保持 0，返回 0 |
| 合并 | `n += sumNums(n-1)`，即 `n + (1+...+n-1)` |

**为什么 `flag` 这个变量必须存在？** 因为 `n > 0 && ...;` 不是合法的独立语句（Java 只允许"赋值 / 调用 / 自增"等少数据表达式当语句），必须赋值给一个变量。

**轨迹演示（n = 3）**：

```
sumNums(3) → 3>0 ✓ → 3 += sumNums(2) → 3 += 3 = 6 → 6>0 ✓ → 返回 6
sumNums(2) → 2>0 ✓ → 2 += sumNums(1) → 2 += 1 = 3 → 3>0 ✓ → 返回 3
sumNums(1) → 1>0 ✓ → 1 += sumNums(0) → 1 += 0 = 1 → 1>0 ✓ → 返回 1
sumNums(0) → 0>0 ✗ → 短路，返回 0
```

> 参考实现：[src/number/SumN.java](../src/number/SumN.java)

**复杂度**：时间 `O(n)`（每层一次调用），空间 `O(n)`（递归栈深度 `n`，`n ≤ 10^4` 以内安全）。

*求 1+2+…+n 是【递归 + 短路运算】，关键突破点是拿 `&&` 的短路当 `if` 用，边界是 `n == 0` 时不能再往下递归。*

### 509. 斐波那契数

**题意**：`F(0) = 0`，`F(1) = 1`，`F(n) = F(n-1) + F(n-2)`，求 `F(n)`，`0 ≤ n ≤ 30`。

**暴力（纯递归）**：

```java
public int fib(int N) {
    if (N == 0) return 0;
    if (N == 1) return 1;
    return fib(N - 1) + fib(N - 2);   // 递归树是二叉树，节点数 ≈ 1.618^n
}
```

**优化的那一步消除了什么冗余？** `fib(n-2)` 被 `fib(n-1)` 和 `fib(n)` 各算了一遍——**重叠子问题**。把算过的值存起来，`O(2^n)` 直接降到 `O(n)`：

```java
/** 记忆化：把"指数级的递归树"压成"n 个节点的一条链" */
private int[] memo;

public int fibMemo(int n) {
    memo = new int[n + 1];
    return dfs(n);
}

private int dfs(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    if (memo[n] != 0) return memo[n];        // 查表
    memo[n] = dfs(n - 1) + dfs(n - 2);       // 写表
    return memo[n];
}

/** 迭代（推荐）：只保留前两项，O(n) 时间 O(1) 空间 */
public int fibIter(int n) {
    if (n < 2) return n;
    int prev = 0, cur = 1;
    for (int i = 2; i <= n; i++) {
        int next = prev + cur;
        prev = cur;
        cur = next;
    }
    return cur;
}
```

**三种写法对比**：

| 写法 | 时间 | 空间 | `n = 45` 时 | 面试建议 |
| --- | --- | --- | --- | --- |
| 纯递归 | `O(2^n)` | `O(n)` 栈 | 约 10 秒，必超时 | 只用来讲"重叠子问题" |
| 记忆化 | `O(n)` | `O(n)` | < 1 ms | 讲 DP 的入口 |
| 迭代 | `O(n)` | `O(1)` | < 1 ms | ✅ 首选 |

**为什么这里的 `memo[n] != 0` 判空是安全的？** 因为 `n ≥ 1` 时 `fib(n) ≥ 1`，**答案永远不为 0**，所以 `0` 可以当"未计算"标记。如果答案可能是 0，这个写法会退化成纯递归（见 [03](03-记忆化与递归优化.md) 的 `Integer[]` + `null` 写法）。

> 参考实现：[src/number/Fib.java](../src/number/Fib.java)（纯递归版）、[src/number/Fiber.java](../src/number/Fiber.java)（用 `HashMap` 递推的版本）

**关于 `Fiber.java`（仓库版本）**：它用 `Map<Integer,Integer>` 从 `i = 2` 推到 `n`，是**递推**而不是记忆化搜索（没有递归）。逻辑正确，但空间 `O(n)`，且 `Map` 的装箱 / 哈希开销远大于数组。**推荐版本**是上面的 `fibIter`。

*斐波那契是【递归树 → 记忆化】的教科书例子，关键突破点是发现"同一子问题被反复求解"，边界是 `n == 0` 和 `n == 1` 两个基础情形。*

### 206. 反转链表

**题意**：反转单链表，返回新的头节点。

**先写迭代版（直觉最清晰）**：

```java
public ListNode reverseList(ListNode head) {
    ListNode pre = null, cur = head;
    while (cur != null) {
        ListNode next = cur.next;   // ① 先存后继，别丢了
        cur.next = pre;             // ② 反转指针
        pre = cur;                  // ③ 两个指针一起前进
        cur = next;
    }
    return pre;                     // 循环结束时 cur == null，pre 就是新头
}
```

**递归版（按四步 checklist 走一遍）**：

```java
public ListNode reverseList(ListNode head) {
    // 要素 1：空链表，或只剩一个节点（反转后还是自己）
    if (head == null || head.next == null) return head;

    // 要素 2：假设 reverseList(head.next) 已返回"后半段反转后的新头"
    ListNode newHead = reverseList(head.next);

    // 要素 3：合并
    head.next.next = head;   // 原来的后继现在成了反转段的尾节点 → 让它指向 head
    head.next = null;        // 必须置空，否则 head 和后继互指 → 成环
    return newHead;          // 新头始终是"后半段的新头"，不随本层改变
}
```

**逐层轨迹（`1 → 2 → 3`）**：

```
reverse(1)
 └─ reverse(2)                     这一层返回的 newHead = 3
     └─ reverse(3)                 终止：head.next == null → 返回 3
     ↑ 回到 reverse(2)，head = 2：
        2.next.next = 2   →   3.next = 2
        2.next = null     →   3 → 2
        return 3
 ↑ 回到 reverse(1)，head = 1：
    1.next.next = 1       →   2.next = 1
    1.next = null         →   3 → 2 → 1
    return 3
```

**两个最容易错的地方**：

1. **`head.next = null` 不能漏**。漏了会变成 `2 → 1 → 2 → 1 …` 的环，LeetCode 上报"超出时间限制"或"链表中存在环"。
2. **返回的是 `newHead` 而不是 `head`**。`head` 反转后变成了**尾节点**；新头始终是最后一层传上来的那个节点。

> 参考实现：[src/listTable/ReverseList3.java](../src/listTable/ReverseList3.java)（`reverseList` 是迭代版，`reverseList2` 是递归版）

**复杂度**：时间 `O(n)`（每个节点进一次、出一次），空间 `O(n)`（递归栈深度 `n`；迭代版是 `O(1)`）。

> ⚠️ **工程提醒**：递归版在 `n = 10^4` 以上有爆栈风险。面试时**建议先给迭代版**，再补一句"递归版更简洁，但受 JVM 栈深度限制"。

*反转链表是【后序递归】，关键突破点是"假设后半段已经反转好、只把本层的头接到反转段的尾部"，边界是 `head == null || head.next == null`，以及千万不要忘记 `head.next = null`。*

### 104. 二叉树的最大深度

**题意**：返回二叉树的最大深度（根到最远叶子节点的**节点数**）。

**思路**：后序递归，语义是"`maxDepth(root)` 返回以 root 为根的子树的最大深度"。

```java
public int maxDepth(TreeNode root) {
    if (root == null) return 0;                                  // 要素 1：空树深度为 0
    int leftHeight = maxDepth(root.left);                        // 要素 2：交给左右子树
    int rightHeight = maxDepth(root.right);
    return Math.max(leftHeight, rightHeight) + 1;                // 要素 3：取大的，加上自己
}
```

**另一种写法（前序 + 全局变量）**——用于体会"返回值语义"的差别：

```java
int maxDepth = 0;

private void dfs(TreeNode node, int depth) {
    if (node == null) {
        maxDepth = Math.max(maxDepth, depth);   // 用全局变量收集答案，返回值是 void
        return;
    }
    dfs(node.left, depth + 1);                  // 状态（depth）靠参数往下传
    dfs(node.right, depth + 1);
}

public int maxDepth(TreeNode root) {
    dfs(root, 0);
    return maxDepth;
}
```

**两种写法对比**：

| 维度 | 返回值版 | 全局变量版 |
| --- | --- | --- |
| 递归语义 | "返回子树深度" | "把深度传下去，答案记在成员变量" |
| 是否纯函数 | 是（同一输入必得同一输出） | 否（依赖外部状态） |
| 多测用例 | 安全 | **必须在入口重置 `maxDepth = 0`**，否则状态污染 |
| 面试推荐 | ✅ 推荐 | 仅在需要"带路径信息"时使用 |

> 参考实现：[src/tree/MaxDepth.java](../src/tree/MaxDepth.java)（`maxDepth` 是 BFS 版，`maxDepth2` 是递归版）、[src/tree/MaxDepthTree.java](../src/tree/MaxDepthTree.java)（全局变量版）

**复杂度**：时间 `O(n)`（每个节点访问一次），空间 `O(h)`（`h` 为树高；最坏退化成链时 `h = n`，此时有爆栈风险）。

*二叉树最大深度是【后序递归】，关键突破点是"子树深度取 max 再加 1"，边界是 `root == null` 返回 0。*

### 21. 合并两个有序链表

**题意**：把两个升序链表合并成一条升序链表。

**递归版（核心只有三行）**：

```java
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    // 要素 1：任一条为空，另一条整条接上（这同时也是全部边界）
    if (l1 == null) return l2;
    if (l2 == null) return l1;

    // 要素 2 + 3：谁的头小，谁当本层的新头，剩下的交给递归
    if (l1.val <= l2.val) {
        l1.next = mergeTwoLists(l1.next, l2);
        return l1;
    } else {
        l2.next = mergeTwoLists(l1, l2.next);
        return l2;
    }
}
```

**为什么这样不会漏元素？** 两个链表头部的较小者 `x` 一定是合并后链表的头（因为两条链表都有序，其余所有元素都 ≥ `x`）。把这个头摘掉后，问题变成"合并剩下的两条链表"——**规模严格变小，问题结构完全相同**，正好是递归三要素。

**迭代版（仓库版本，用哑结点免去头节点特判）**：

```java
public ListNode mergeTwoLists(ListNode l1, ListNode l2) {
    ListNode head = new ListNode(0);      // 哑结点：合并后的头可能来自 l1 也可能来自 l2
    ListNode pt = head;
    while (l1 != null && l2 != null) {
        if (l1.val < l2.val) {
            pt.next = l1;
            l1 = l1.next;
        } else {
            pt.next = l2;
            l2 = l2.next;
        }
        pt = pt.next;
    }
    pt.next = (l1 != null) ? l1 : l2;     // 剩下的一段整条接上，不用逐个接
    return head.next;
}
```

**递归 vs 迭代**：

| 维度 | 递归版 | 迭代版（哑结点） |
| --- | --- | --- |
| 代码量 | 10 行 | 16 行 |
| 空间 | `O(n + m)` 栈 | `O(1)` |
| 链表被修改 | 复用原节点 | 复用原节点 |
| 面试建议 | 先写这个，简洁 | 面试官要求"不用递归"时写这个 |

> 参考实现：[src/listTable/MergeLists.java](../src/listTable/MergeLists.java)、[src/listTable/MergeList.java](../src/listTable/MergeList.java)、[src/listTable/MergeTwoList.java](../src/listTable/MergeTwoList.java)（三个都是迭代版，写法略有差异；`MergeList.java` 会 `new` 新节点，浪费空间，不推荐）

**复杂度**：时间 `O(n + m)`，空间 `O(n + m)`（递归栈）/ `O(1)`（迭代）。

*合并两个有序链表是【后序递归 + 哑结点迭代】，关键突破点是"较小者当新头"，边界是任一条链表为空时直接返回另一条。*

### 111. 二叉树的最小深度

**题意**：返回二叉树的最小深度（根到**最近的叶子节点**的节点数）。

**这题的坑**：把 104 题的 `Math.max` 直接改成 `Math.min` 是**错的**。

```
       1
        \
         2
        /
       3

朴素 min 写法：minDepth(1) = min(minDepth(null), minDepth(2)) + 1 = 0 + 1 = 1   ❌
正确答案是 3，因为 1 的右孩子 2 不是叶子（它有左孩子 3）
"左子树为空"被算成了"深度 0 的一条路径"，但那条路径【不是叶子路径】
```

**正确解法**：特判"只有一个孩子"的情况——此时唯一的孩子是**必经之路**，不能参与取 `min`。

```java
public int minDepth(TreeNode root) {
    if (root == null) return 0;                       // ① 空树
    // ② 只有右孩子：只能走右边，不能拿"空的左孩子"当最短路径
    if (root.left == null) return minDepth(root.right) + 1;
    // ③ 只有左孩子：同理
    if (root.right == null) return minDepth(root.left) + 1;
    // ④ 两个孩子都在：这才是真正的"取较小"
    return Math.min(minDepth(root.left), minDepth(root.right)) + 1;
}
```

> 参考实现：[src/tree/MinDepth.java](../src/tree/MinDepth.java)（`minDepth` 就是上面的正确写法；同文件里的 `min(root)` 只是把第 ④ 步抽成了一个方法，但它在内部又调了一次 `minDepth`，属于冗余封装，可以内联掉）

**为什么 `if (root.left == null)` 必须写在 `Math.min` 之前？** 因为"叶子节点"的定义是"**没有孩子**"，而不是"某一侧没有孩子"。上图中节点 2 有左孩子，所以它不是叶子，`1 → 2 → 3` 才是唯一的叶子路径。

**复杂度**：时间 `O(n)`，空间 `O(h)`。

*二叉树的最小深度是【后序递归 + 叶子特判】，关键突破点是"单侧为空时不能取 min"，边界是空树返回 0、单孩子节点必须沿着那个孩子继续往下走。*

## 八、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 终止条件写少（漏 `null` / 漏空区间） | 无限递归 → `StackOverflowError`，或 NPE | 先枚举"空输入 / 单元素 / 空区间"三种边界再动手 |
| 递归参数没有变小 | 死循环（表现也是 `StackOverflowError`） | 每层检查参数是否朝终止方向移动 |
| 区间写成 `[lo, mid]` + `[mid, hi]` | 区间不缩小，死循环 | 写成 `[lo, mid]` + `[mid + 1, hi]` |
| 反转链表忘记 `head.next = null` | 链表成环，超时或报错 | 递归版在接完头之后必须置空 |
| 反转链表返回了 `head` | 返回的是尾节点，只有单元素用例碰巧对 | 返回最后一层传上来的 `newHead` |
| 最小深度用 `Math.min(left, right) + 1` | 单侧为空时答案偏小 | 先特判 `left == null` / `right == null` |
| 用全局变量收集答案但忘记重置 | 多测用例互相污染（本地对、提交 WA） | 要么用返回值，要么在入口重置全局变量 |
| 递归深度达到 `n`（`n ≥ 10^4`） | `StackOverflowError` | 改成迭代或显式栈 |
| 以为 Java 有尾递归优化 | 按尾递归写完照样爆栈 | Java 没有 TCO，必须显式栈改写 |
| 链式递归（每层只调一次自己）还写递归 | 白白多占 `O(n)` 栈空间 | 直接改成 `for` 循环 |
