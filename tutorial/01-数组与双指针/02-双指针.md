# 02 双指针

> **一句话理解**：双指针就是"用两个下标代替两重循环"，把 `O(n^2)` 的暴力枚举压缩到 `O(n)`。

---

## 一、什么时候能用双指针

双指针能成立的**唯一理由**：两个指针的移动方向具有**单调性**——即"如果某个位置不满足条件，那么它某一侧的所有位置都不满足"。

三句口诀：

1. **有序 → 对撞双指针**（left 从左往右，right 从右往左）
2. **原地删除 / 去重 → 快慢双指针**（slow 指向已处理区末尾，fast 探索）
3. **求最值 / 最优 → 双指针 + 贪心移动**（每次移动最不可能成为答案的那个）

---

## 二、类型一：对撞双指针（左右夹逼）

### 2.1 模板

```java
/**
 * 对撞双指针通用模板
 * 适用：有序数组上寻找满足某种关系的两个元素
 */
public int[] twoPointer(int[] nums, int target) {
    int left = 0, right = nums.length - 1;
    while (left < right) {                    // 注意：不是 <=，因为不能取同一个元素
        int sum = nums[left] + nums[right];
        if (sum == target) {
            return new int[]{left, right};    // 找到答案
        } else if (sum < target) {
            left++;                           // 和太小，左指针右移让和变大
        } else {
            right--;                          // 和太大，右指针左移让和变小
        }
    }
    return new int[]{-1, -1};
}
```

### 2.2 为什么可以跳过大量情况？（关键证明）

以"有序数组中找两数之和等于 target"为例，为什么 `sum < target` 时可以直接 `left++`，而不需要考虑 `nums[right]` 与其他元素的组合？

```
假设 nums[left] + nums[right] < target。
因为数组升序，对于任意 j < right，都有 nums[j] <= nums[right]，
所以 nums[left] + nums[j] <= nums[left] + nums[right] < target。

结论：nums[left] 和任何 j < right 的组合都不可能等于 target。
      → 可以把 left 这一整行"划掉"，直接 left++。
```

这就是双指针的**正确性证明**。面试时被问"为什么这样不会漏解"，就答这一段。

### 2.3 例题：11. 盛最多水的容器

**题意**：给定 `height[]`，选两条线，与 x 轴围成容器，求最大水量。

**暴力**：枚举所有 `(i, j)` 组合，`O(n^2)`。

**双指针思路**：面积 = `min(height[left], height[right]) * (right - left)`。

- 宽度 `right - left` 随着指针内移**必然变小**
- 面积只可能在**高度**上提升，所以每次移动**较矮的那根柱子**（移动高的那根只会让高度上限更低，不可能变优）

```java
public int maxArea(int[] height) {
    int left = 0, right = height.length - 1;
    int max = 0;
    while (left < right) {
        int h = Math.min(height[left], height[right]);
        max = Math.max(max, h * (right - left));
        // 关键：移动较矮的一侧
        if (height[left] < height[right]) {
            left++;
        } else {
            right--;
        }
    }
    return max;
}
```

> 参考实现：[src/array/Container.java](../src/array/Container.java)

**复杂度**：时间 `O(n)`，空间 `O(1)`。

**一句话总结**：*盛水容器是【对撞双指针 + 贪心】，关键突破点是每次移动较矮的柱子，边界是 `left < right`。*

### 2.4 例题：15. 三数之和（排序 + 双指针的典范）

**题意**：找出所有和为 0 的三元组，要求不重复。

**思路演进**：

```
暴力三重循环 O(n^3)
  ↓ 先排序，固定第一个数 nums[i]，问题降维成"在 i+1..n-1 中找两数之和 = -nums[i]"
排序 + 固定 + 双指针 O(n^2)
```

```java
public List<List<Integer>> threeSum(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    if (nums == null || nums.length < 3) return result;
    Arrays.sort(nums);                                   // 第一步：排序，为双指针和去重做准备

    for (int i = 0; i < nums.length; i++) {
        if (nums[i] > 0) break;                          // 剪枝：最小的数都 > 0，后面不可能凑出 0
        if (i > 0 && nums[i] == nums[i - 1]) continue;   // 去重①：跳过重复的第一个数

        int left = i + 1, right = nums.length - 1;
        while (left < right) {
            int sum = nums[i] + nums[left] + nums[right];
            if (sum == 0) {
                result.add(Arrays.asList(nums[i], nums[left], nums[right]));
                // 去重②：跳过重复的第二、第三个数
                while (left < right && nums[left + 1] == nums[left]) left++;
                while (left < right && nums[right - 1] == nums[right]) right--;
                left++;
                right--;
            } else if (sum < 0) {
                left++;                                  // 和太小
            } else {
                right--;                                 // 和太大
            }
        }
    }
    return result;
}
```

> 参考实现（含暴力对照版本 `threeSum2`）：[src/array/ThreeNum.java](../src/array/ThreeNum.java)、[src/array/ThreePartsEqualSum.java](../src/array/ThreePartsEqualSum.java)

**复杂度**：排序 `O(n log n)`，双指针部分 `O(n^2)`，总计 `O(n^2)`；空间 `O(log n)`（排序栈）或 `O(1)`（不计结果数组）。

**三个去重细节必须记住**：

| 去重位置 | 写法 | 为什么要 |
| --- | --- | --- |
| 第一个数 | `if (i > 0 && nums[i] == nums[i-1]) continue;` | 否则会出现 `[-1,0,1]` 重复多次 |
| 第二个数 | `while (left < right && nums[left+1] == nums[left]) left++;` | 跳过相等的候选 |
| 第三个数 | `while (left < right && nums[right-1] == nums[right]) right--;` | 同上 |

> ⚠️ **最容易错的点**：`while` 里的 `left < right` 判断不能省，否则会数组越界。

**同类扩展**：四数之和 = 外面再套一层循环 → `O(n^3)`
> 参考实现：[src/array/FourNum.java](../src/array/FourNum.java)

### 2.5 例题：977. 有序数组的平方

**题意**：升序数组（可能含负数），返回每个数平方后的升序数组。

**关键观察**：平方后的最大值一定出现在**两端**（最小值和最大值处）。

```java
public int[] sortedSquares(int[] nums) {
    int n = nums.length;
    int[] res = new int[n];
    int left = 0, right = n - 1;
    int pos = n - 1;                       // 从结果数组的末尾往前填
    while (left <= right) {                // 注意这里是 <=，因为要处理最后一个元素
        int l = nums[left] * nums[left];
        int r = nums[right] * nums[right];
        if (l > r) {
            res[pos--] = l;
            left++;
        } else {
            res[pos--] = r;
            right--;
        }
    }
    return res;
}
```

> 参考实现：[src/array/SortedSquares.java](../src/array/SortedSquares.java)

**注意**：这里 `while` 条件用 `<=`，因为两个指针可以相遇（每个元素都必须被处理一次）。这和 2.1 模板的 `<` 形成对比——**判断边界用 `<` 还是 `<=`，取决于"指针相遇时还剩不剩元素要处理"**。

## 三、类型二：快慢双指针（同向）

### 3.1 模板

```java
/**
 * 快慢指针通用模板（原地删除 / 去重）
 * slow：指向"已处理好的区间"的最后一个位置的下一个空位
 * fast：遍历指针，负责探索
 */
public int removeElement(int[] nums, int val) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != val) {          // 保留条件
            nums[slow] = nums[fast];
            slow++;
        }
    }
    return slow;                          // slow 就是新数组的长度
}
```

**核心心法**：把数组想象成两块区域：

```
[0, slow)    已处理完成，是答案的一部分
[slow, fast) 已废弃（被删除的元素）
[fast, n)    待处理
```

### 3.2 例题：26. 删除有序数组中的重复项

```java
public int removeDuplicates(int[] nums) {
    if (nums.length == 0) return 0;
    int slow = 0;                         // nums[0] 一定保留
    for (int fast = 1; fast < nums.length; fast++) {
        if (nums[fast] != nums[slow]) {   // 与"已保留的最后一个"比较
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow + 1;                      // 长度 = 下标 + 1
}
```

> 参考实现：[src/array/RemoveDuplicates.java](../src/array/RemoveDuplicates.java)、[src/string/RemoveDuplicates.java](../src/string/RemoveDuplicates.java)

**易错点**：
- 比较对象是 `nums[slow]`（已保留的最后一个），**不是** `nums[fast-1]`。两者在这题里恰好等价，但改成"每个元素最多保留 k 个"时就不等价了。
- 返回值是**长度**不是下标。

### 3.3 例题：27. 移除元素 & 283. 移动零

```java
// 27. 移除元素
public int removeElement2(int[] nums, int val) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != val) {
            nums[slow++] = nums[fast];
        }
    }
    return slow;
}

// 283. 移动零：把 0 移到末尾，非零元素保持相对顺序
public void moveZeroes(int[] nums) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        if (nums[fast] != 0) {
            swap(nums, slow, fast);       // 与"移除元素"的唯一区别：用交换代替覆盖
            slow++;
        }
    }
}
```

> 参考实现：[src/array/RemoveE.java](../src/array/RemoveE.java)、[src/array/MoveZeros.java](../src/array/MoveZeros.java)、[src/array/MoveZero.java](../src/array/MoveZero.java)

**"移动零"为什么用 swap？** 因为要求非零元素的相对顺序不变、且 0 全部挪到末尾。如果只做覆盖，末尾会残留旧值。用交换则天然把 0 换到后面。

### 3.4 例题：80. 删除有序数组中的重复项 II（保留 k 个的通用解法）

```java
/**
 * 通用模板：有序数组，每个元素最多保留 k 个
 * 关键：把"与已保留的最后一个比较"改成"与已保留区倒数第 k 个比较"
 */
public int removeDuplicates(int[] nums, int k) {
    int slow = 0;
    for (int fast = 0; fast < nums.length; fast++) {
        // 已保留元素不足 k 个，或当前元素 != 已保留区倒数第 k 个 → 可以保留
        if (slow < k || nums[fast] != nums[slow - k]) {
            nums[slow] = nums[fast];
            slow++;
        }
    }
    return slow;
}
```

> 参考实现：[src/array/RemoveDuplicates.java](../src/array/RemoveDuplicates.java)（仓库中的 `removeDuplicates2` 即 k=2 版本）

**这个模板值得背下来**，它一次性解决了 26 题（k=1）、80 题（k=2）以及所有同类变体。

### 3.5 例题：443. 压缩字符串（快慢指针 + 原地写）

```java
public int compress(char[] chars) {
    int slow = 0;                 // 写指针
    int fast = 0;                 // 读指针
    while (fast < chars.length) {
        char cur = chars[fast];
        int count = 0;
        // 数出连续相同字符的个数
        while (fast < chars.length && chars[fast] == cur) {
            fast++;
            count++;
        }
        chars[slow++] = cur;                       // 写入字符
        if (count > 1) {                           // 个数 > 1 才写数字
            for (char c : String.valueOf(count).toCharArray()) {
                chars[slow++] = c;
            }
        }
    }
    return slow;
}
```

> 参考实现：[src/array/CompressChars.java](../src/array/CompressChars.java)

**易错点**：`count == 1` 时不写数字；`count >= 10` 时要逐位写（不能只写一个字符）。

## 四、类型三：三指针 / 多指针分区

### 4.1 例题：75. 颜色分类（荷兰国旗问题）

**题意**：数组只含 0、1、2，原地排序，一趟扫描。

**三指针**：`p0` 指向 0 区末尾的下一个位置，`p2` 指向 2 区开头的前一个位置，`i` 遍历。

```java
public void sortColors(int[] nums) {
    int p0 = 0;                        // [0, p0) 全是 0
    int i = 0;                         // [p0, i) 全是 1
    int p2 = nums.length - 1;          // (p2, n-1] 全是 2

    while (i <= p2) {
        if (nums[i] == 0) {
            swap(nums, i, p0);
            p0++;
            i++;
        } else if (nums[i] == 2) {
            swap(nums, i, p2);
            p2--;
            // 注意：这里 i 不自增！因为从 p2 换过来的元素还没检查
        } else {
            i++;
        }
    }
}
```

> 参考实现：[src/sort/SortColor.java](../src/sort/SortColor.java)

**最容易错的点**：`nums[i] == 2` 时交换后**不能 `i++`**，因为换过来的元素是未检查的。

**循环不变量**（面试时可以讲）：

```
[0, p0)    → 0
[p0, i)    → 1
(i, p2]    → 2
[p2+1, n)  → 已确认的 2
```

public int[] sortArrayByParity(int[] nums) {

### 4.3 例题：88. 合并两个有序数组（从后往前三指针）

**思路**：如果从前往后合并，会覆盖 `nums1` 中未处理的元素。**从后往前**就没这个问题。

```java
public void merge(int[] nums1, int m, int[] nums2, int n) {
    int i = m - 1;            // nums1 有效部分的末尾
    int j = n - 1;            // nums2 的末尾
    int k = m + n - 1;        // 合并后数组的末尾（写指针）
    while (j >= 0) {          // nums2 还有剩余就必须继续
        if (i >= 0 && nums1[i] > nums2[j]) {
            nums1[k--] = nums1[i--];
        } else {
            nums1[k--] = nums2[j--];
        }
    }
}
```

> 参考实现：[src/array/MergeInters.java](../src/array/MergeInters.java)、[src/listTable/MergeLists.java](../src/listTable/MergeLists.java)

**为什么循环条件是 `j >= 0` 而不是 `i >= 0 && j >= 0`？**
因为 `nums1` 剩下的元素本来就在正确位置，无需搬运；只有 `nums2` 剩余时必须继续搬。

## 五、双指针 vs 哈希表：怎么选

两者都能解决"两数之和"类问题，选择依据：

| 维度 | 双指针 | 哈希表 |
| --- | --- | --- |
| 前提 | 数组**有序** | 无要求 |
| 时间 | `O(n)`（排序另算 `O(n log n)`） | `O(n)` |
| 空间 | `O(1)` | `O(n)` |
| 返回什么 | 值 or 下标（**排序后下标会丢**） | 下标 |
| 3 数之和 | ✅ 推荐，天然好去重 | ❌ 需要额外 Set 去重，很麻烦 |

**决策**：

- 要**下标** → 哈希表（排序会打乱下标）
- 要**所有不重复的组合**（三数、四数之和）→ 排序 + 双指针
- 只要**布尔值/最值** → 双指针（省空间）

## 六、易错点清单

| 易错点 | 说明 | 正确做法 |
| --- | --- | --- |
| 循环条件 `<` vs `<=` | 取决于指针相遇时是否还有元素要处理 | 求两数和用 `<`；遍历所有元素用 `<=` |
| 去重时漏写 `left < right` | 数组越界 | `while (left < right && nums[left+1] == nums[left])` |
| 先移动指针再处理 | 漏掉元素 | 先处理 `nums[i]`，再决定怎么移动 |
| "移动元素"用覆盖而非交换 | 末尾残留脏数据 | 需要"挪到末尾"用 swap |
| 三指针交换后忘了 `i++` 的取舍 | 漏检元素 | 从"未检查区"换来的元素不能 `i++` |
| 排序后还想返回原下标 | 结果错误 | 存 `(值, 原下标)` 二元组一起排序 |
