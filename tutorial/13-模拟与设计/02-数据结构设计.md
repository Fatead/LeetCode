# 02 数据结构设计

> **一句话理解**：设计题的难点在**选对底层结构**，而不是写得多复杂。循环队列用"数组 + 头尾指针取模"，栈模拟队列用"两个栈倒腾"，迭代器用"懒加载"，随机集合用"数组 + 哈希"。

---

## 一、设计循环队列（622 题）

**题目**：用固定容量实现队列，队尾满了能循环利用队头腾出的空间。

**正确做法：数组 + 头尾指针取模**。用 `front` 指向队首、`rear` 指向下一个入队位置，所有移动都对容量取模实现"循环"。为了区分队空和队满，**数组多开一格**（留一个空位）。

```java
class MyCircularQueue {
    int[] data;
    int front, rear, capacity;

    public MyCircularQueue(int k) {
        capacity = k + 1;              // ★ 多开一格区分空/满
        data = new int[capacity];
        front = rear = 0;
    }
    public boolean enQueue(int value) {
        if (isFull()) return false;
        data[rear] = value;
        rear = (rear + 1) % capacity;  // 循环前进
        return true;
    }
    public boolean deQueue() {
        if (isEmpty()) return false;
        front = (front + 1) % capacity;
        return true;
    }
    public int Front()   { return isEmpty() ? -1 : data[front]; }
    public int Rear()    { return isEmpty() ? -1 : data[(rear - 1 + capacity) % capacity]; }
    public boolean isEmpty() { return front == rear; }
    public boolean isFull()  { return (rear + 1) % capacity == front; }
}
```

**空/满判定的经典技巧**：`front == rear` 为空，`(rear+1)%capacity == front` 为满。多留一格空位，就能用指针位置区分这两种本来会撞车的状态。

> 参考实现：[src/queue/MyCircularQueue.java](../../src/queue/MyCircularQueue.java)。
>
> ⚠️ **仓库版本的问题**：它用 `List` + `list.remove(0)` 实现出队——`remove(0)` 是 `O(n)` 操作（要搬移所有元素），**失去了循环队列 `O(1)` 的核心优势**。正确做法是上面的"数组 + 取模"，所有操作都是 `O(1)`。这是一个很好的"能过但不对"的反例。

*设计循环队列是【数组 + 头尾指针取模】，关键突破点是【多开一格用指针位置区分空/满，出队只移指针不搬数据】，边界是【`Rear()` 要 `(rear-1+capacity)%capacity` 防止下标为负】。*

**循环双端队列（641 题）** 只是多了"从队头入队/从队尾出队"，`front` 可以向前移（`(front-1+cap)%cap`）。见 [src/queue/MyCircularDeque.java](../../src/queue/MyCircularDeque.java)。

## 二、用栈实现队列（232 题）

**题目**：只用两个栈实现队列的 FIFO。

**核心：两个栈倒腾**。`in` 栈负责入队，`out` 栈负责出队。出队时若 `out` 空，就把 `in` 的元素**全部倒进** `out`（顺序正好反过来，变成 FIFO）。

```java
class MyQueue {
    Deque<Integer> in = new ArrayDeque<>();
    Deque<Integer> out = new ArrayDeque<>();

    public void push(int x) { in.push(x); }

    public int pop() {
        transfer();
        return out.pop();
    }
    public int peek() {
        transfer();
        return out.peek();
    }
    public boolean empty() { return in.isEmpty() && out.isEmpty(); }

    private void transfer() {
        if (out.isEmpty())                 // ★ 只在 out 空时才倒，否则会打乱顺序
            while (!in.isEmpty()) out.push(in.pop());
    }
}
```

**为什么倒一次就变 FIFO？** 栈是 LIFO，把 `in` 倒进 `out` 时元素顺序翻转一次，`out` 的出栈顺序就和 `in` 的入栈顺序一致了。**关键是只在 `out` 空时才倒**，否则会把新旧元素顺序搅乱。

> 参考实现：[src/queue/CQueue.java](../../src/queue/CQueue.java)（剑指 09，双栈实现队列）

*用栈实现队列是【双栈倒腾】，关键突破点是【in 栈入队、out 栈出队，out 空时才把 in 整体倒过去翻转顺序】，边界是【两栈都空才算队列空】。*

## 三、迭代器设计

### 3.1 扁平化嵌套列表迭代器（341 题）

**题目**：嵌套的整数列表（元素可能是数或列表），实现一个把它拉平的迭代器。

**两种思路**：
- **预处理展开**：构造时用 DFS 把所有整数拉平到一个列表，迭代时顺序取。简单直接。
- **懒加载**（用栈）：构造时把列表逆序压栈，`hasNext` 时若栈顶是列表就展开再压回，保证栈顶永远是整数。省内存，但代码复杂。

> 参考实现：[src/listTable/NestedIterator.java](../../src/listTable/NestedIterator.java)

### 3.2 窥视迭代器（284 题）

**题目**：给迭代器加一个 `peek()`，能看下一个元素但不移动指针。

**技巧：缓存一个元素**。用一个变量 `nextElem` 预存"下一个元素"，`peek` 返回它但不前进，`next` 返回它并刷新缓存。

> 参考实现：[src/listTable/PeekingIterator.java](../../src/listTable/PeekingIterator.java)

**迭代器设计的通用套路**：要么**预处理**（构造时算好所有结果），要么**懒加载 + 缓存**（用时才算、缓存下一个）。

## 四、数据流的中位数（295 题）：对顶双堆

**题目**：动态加入数字，随时求中位数。

**神来之笔：一个大顶堆放较小的一半，一个小顶堆放较大的一半**。保持两堆大小平衡，中位数就在两个堆顶。

```java
class MedianFinder {
    PriorityQueue<Integer> small = new PriorityQueue<>((a, b) -> b - a);  // 大顶堆，存较小一半
    PriorityQueue<Integer> large = new PriorityQueue<>();                 // 小顶堆，存较大一半

    public void addNum(int num) {
        small.offer(num);
        large.offer(small.poll());           // 先过一遍 small，再把 small 最大的给 large
        if (large.size() > small.size())     // 保持 small.size() >= large.size()
            small.offer(large.poll());
    }
    public double findMedian() {
        if (small.size() > large.size()) return small.peek();     // 奇数个，中位数在 small 堆顶
        return (small.peek() + large.peek()) / 2.0;               // 偶数个，取两堆顶平均
    }
}
```

**对顶堆的平衡逻辑**：每次加数先经 `small`、再把 `small` 顶吐给 `large`，然后若 `large` 更大就吐回来——这保证了"`small` 装较小一半且不少于 `large`"的不变量，中位数永远在堆顶拿。

> 参考实现：[src/listTable/MedianFinder.java](../../src/listTable/MedianFinder.java)、[src/listTable/MedianFinder2.java](../../src/listTable/MedianFinder2.java)

*数据流中位数是【对顶双堆】，关键突破点是【大顶堆存小的一半、小顶堆存大的一半，保持大小差 ≤ 1，中位数在堆顶】，边界是【奇数个时取较大堆的堆顶】。*

## 五、随机化设计

### 5.1 按随机下标返回目标（398 题，水塘抽样）

**题目**：数组里 `target` 可能出现多次，等概率随机返回它的一个下标。

**水塘抽样**：遍历所有等于 `target` 的位置，第 `k` 个以 `1/k` 的概率替换当前答案。遍历结束后，每个位置被选中的概率都是 `1/总数`，且**只需 `O(1)` 额外空间**（不用先存所有下标）。

```java
public int pick(int target) {
    int res = -1, count = 0;
    for (int i = 0; i < nums.length; i++) {
        if (nums[i] == target) {
            count++;
            if (random.nextInt(count) == 0) res = i;   // 以 1/count 概率选中第 count 个
        }
    }
    return res;
}
```

> 参考实现：[src/random/RandomIndex.java](../../src/random/RandomIndex.java)（仓库用哈希表预存所有下标 + 水塘抽样，两种思路结合）、[src/random/RandomNode.java](../../src/random/RandomNode.java)（链表随机节点，382 题）

**水塘抽样的精髓**：**不需要预先知道总数**，就能对数据流做等概率抽样。这是流式处理的经典技巧。

### 5.2 O(1) 插入删除随机访问（380 题）

**哈希表（值→下标）+ 动态数组**：插入 `O(1)`、删除时把要删的和末尾元素交换再删末尾（`O(1)`）、随机访问直接取数组随机下标。详见 [02 哈希表/04 设计数据结构](../02-哈希表/README.md)。
