# 03 并发编程

> **一句话理解**：并发题的本质是**让多个线程按规定顺序交替执行**。核心是选对"同步原语"——`synchronized + wait/notify`、`ReentrantLock + Condition`、`Semaphore`、`CountDownLatch`，用它们控制"谁该跑、谁该等"。

---

## 一、并发题的通用模型

LeetCode 并发题几乎都是同一个套路：**N 个线程要按某种顺序交替做事**（打印、生产、消费）。解题三步：

1. **确定"轮次/状态"**：现在该哪个线程动？用一个共享变量记录状态
2. **选同步原语**：让不该动的线程阻塞等待
3. **唤醒下一个**：当前线程做完后，唤醒该动的那个

---

## 二、Java 的四种同步武器

| 原语 | 适用场景 | 核心方法 |
| --- | --- | --- |
| `synchronized` + `wait/notifyAll` | 最基础，任何同步场景 | `wait()` 释放锁并等待，`notifyAll()` 唤醒 |
| `ReentrantLock` + `Condition` | 需要多个等待队列（精准唤醒） | `await()` / `signal()` |
| `Semaphore`（信号量） | 控制"许可证"数量，交替执行 | `acquire()` 拿许可，`release()` 放许可 |
| `CountDownLatch` | 等待某些事件完成（一次性） | `await()` 等待，`countDown()` 计数减一 |

**选型直觉**：
- 两三个线程简单交替 → `synchronized + wait/notifyAll`
- 需要"精准唤醒某个线程" → `ReentrantLock` 的多个 `Condition`
- "A 必须等 B 做完" → `Semaphore` 或 `CountDownLatch`

## 三、按序打印（1114 题）

**题目**：三个线程分别调用 `first/second/third`，保证按 `first → second → third` 顺序执行。

**最简单的武器：两个 `CountDownLatch` 当"门闩"**。`second` 要等 `first` 开门，`third` 要等 `second` 开门。

```java
class Foo {
    private CountDownLatch latch12 = new CountDownLatch(1);  // first→second 的门
    private CountDownLatch latch23 = new CountDownLatch(1);  // second→third 的门

    public void first(Runnable printFirst) throws InterruptedException {
        printFirst.run();
        latch12.countDown();        // 开 first→second 的门
    }
    public void second(Runnable printSecond) throws InterruptedException {
        latch12.await();            // 等 first 开门
        printSecond.run();
        latch23.countDown();        // 开 second→third 的门
    }
    public void third(Runnable printThird) throws InterruptedException {
        latch23.await();            // 等 second 开门
        printThird.run();
    }
}
```

**`CountDownLatch` 像一道门闩**：初始计数 1，`await()` 的线程会阻塞直到 `countDown()` 把计数减到 0。它天然适合"A 做完 B 才能开始"的一次性顺序控制。

> 参考实现：[src/concurrency/PrintInOrder.java](../../src/concurrency/PrintInOrder.java)、[PrintInOrder2.java](../../src/concurrency/PrintInOrder2.java)、[PrintInOrder3.java](../../src/concurrency/PrintInOrder3.java)（仓库给了三种同步原语的实现，正好可对比学习）

*按序打印是【顺序控制 / CountDownLatch 门闩】，关键突破点是【用计数为 1 的闩锁串起"前一步 countDown、后一步 await"】，边界是【第一个线程无需等待】。*

## 四、交替打印 FooBar（1115 题）

**题目**：两个线程交替打印 `foo` 和 `bar`，输出 `foobarfoobar...` n 次。

**用 `Semaphore` 两张许可券互相传递**：`foo` 做完给 `bar` 发券，`bar` 做完给 `foo` 发券。

```java
class FooBar {
    private int n;
    private Semaphore fooLock = new Semaphore(1);   // foo 初始有 1 张券
    private Semaphore barLock = new Semaphore(0);   // bar 初始没券，要等

    public FooBar(int n) { this.n = n; }

    public void foo(Runnable printFoo) throws InterruptedException {
        for (int i = 0; i < n; i++) {
            fooLock.acquire();      // 拿 foo 券
            printFoo.run();
            barLock.release();      // 给 bar 发券
        }
    }
    public void bar(Runnable printBar) throws InterruptedException {
        for (int i = 0; i < n; i++) {
            barLock.acquire();      // 拿 bar 券（初始没有，先阻塞等 foo）
            printBar.run();
            fooLock.release();      // 给 foo 发券
        }
    }
}
```

**`Semaphore` 像令牌传递**：谁拿到令牌谁才能跑，跑完把令牌交给对方。初始只给 `foo` 一张令牌，就保证了 `foo` 先跑、两者严格交替。

> 参考实现：[src/concurrency/FooBar.java](../../src/concurrency/FooBar.java)、[FooBar2.java](../../src/concurrency/FooBar2.java)、[FooBar3.java](../../src/concurrency/FooBar3.java)

*交替打印是【信号量令牌传递】，关键突破点是【两个 Semaphore 初始许可一个为 1 一个为 0，互相 release 实现交替】，边界是【循环 n 次、初始只有一方有许可】。*

## 五、生产者消费者（经典模型）

**题目**：生产者往缓冲区放数据、消费者取数据，缓冲区满则生产者等、空则消费者等。

**用 `synchronized + wait/notifyAll`**：

```java
// 核心逻辑（缓冲区容量 cap）
public synchronized void produce(int item) throws InterruptedException {
    while (queue.size() == cap) wait();      // ★ 满了就等（必须 while 不是 if）
    queue.offer(item);
    notifyAll();                             // 唤醒可能在等的消费者
}
public synchronized int consume() throws InterruptedException {
    while (queue.isEmpty()) wait();          // 空了就等
    int item = queue.poll();
    notifyAll();                             // 唤醒可能在等的生产者
    return item;
}
```

**两个致命要点**：
1. **`wait` 必须放在 `while` 循环里，不能用 `if`**——被唤醒后要**重新检查条件**（防止"虚假唤醒"和多消费者竞争导致条件已变）。这是并发编程的头号经典 bug。
2. **用 `notifyAll` 而不是 `notify`**——`notify` 只随机唤醒一个，可能唤醒了"不该醒的"线程导致死锁。

> 参考实现：[src/concurrency/ProduceAndConsume.java](../../src/concurrency/ProduceAndConsume.java)、[ProduceAndConsume2.java](../../src/concurrency/ProduceAndConsume2.java)

*生产者消费者是【wait/notify 条件等待】，关键突破点是【`wait` 必须在 while 里重检条件、用 notifyAll 唤醒】，边界是【满/空时阻塞对应角色】。*

## 六、打印零与奇偶数（1116 题）

**题目**：三个线程，`zero` 打印 0，`even` 打印偶数，`odd` 打印奇数，输出 `0102030405...`。

**用 `Semaphore` 三券接力**：`zero` 打完 0 后，根据当前数字的奇偶把券发给 `odd` 或 `even`；`odd`/`even` 打完数字再把券还给 `zero`。详见 [src/concurrency/ZeroEvenOdd.java](../../src/concurrency/ZeroEvenOdd.java)。

## 七、并发易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| `wait` 用 `if` 判断条件 | 虚假唤醒导致逻辑错 | 永远用 `while` 重检条件 |
| 用 `notify` 而非 `notifyAll` | 唤醒错线程，可能死锁 | 不确定就用 `notifyAll` |
| `wait/notify` 不在 `synchronized` 块里 | 抛 `IllegalMonitorStateException` | 必须持有锁才能调用 |
| `Semaphore` 初始许可数设错 | 第一个该跑的线程跑不起来 | 想清楚"谁该先动"再定初值 |
| 忘记处理 `InterruptedException` | 编译报错 | 方法签名 `throws` 或 try-catch |
| 共享变量没加 `volatile`/同步 | 可见性问题，读到旧值 | 共享状态要有同步保护 |
