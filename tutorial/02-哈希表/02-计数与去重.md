# 02 计数与去重

> **一句话理解**：计数题的通用动作只有两个——**用哈希表数出现次数**、**用 `Set` 判断有没有重复**；
> 而"分组"题的难点从来不是哈希，而是**怎么把一个元素规范化成一个稳定的 key**。

---

### 1.3 什么时候**不能**用计数哈希

| 情况 | 原因 | 更好的做法 |
| --- | --- | --- |
| 只需要"有没有重复" | 多存了次数，浪费空间 | 用 `Set`，不需要 `Map` |
| 字符集只有小写字母 | `Map` 有装箱/哈希开销 | `int[26]` 计数数组 |
| 需要按 key 有序输出 | `HashMap` 顺序不可预测 | `TreeMap` 或者"取出 key 后排序" |
| 需要保留"第一次出现的顺序" | `HashMap` 会打乱顺序 | `LinkedHashMap` |
| 频次比较只需"够不够" | 完整计数表不必需 | 边遍历边相减，提前 `return false` |

> **计数 vs 去重的一句话判据**：只关心"有没有"→ `Set`；关心"有几个"或"够不够用"→ `Map` / 计数数组。

## 二、Java 通用模板

### 2.1 模板 A：频次统计（三选一，按 key 空间选）

```java
import java.util.*;

public class FrequencyTemplate {

    // ---------- 场景 1：key 是任意对象 → HashMap ----------
    /** 返回出现次数最多的元素（题目保证非空） */
    public int mostFrequent(int[] nums) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : nums) {
            cnt.merge(x, 1, Integer::sum);        // 不存在放 1，存在则 +1
        }
        int best = nums[0], max = 0;
        for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
            if (e.getValue() > max) {             // 严格大于 → 并列取任意一个
                max = e.getValue();
                best = e.getKey();
            }
        }
        return best;
    }

    // ---------- 场景 2：key 是小写字母 → int[26] ----------
    /** a 和 b 是否互为字母异位词 */
    public boolean isAnagram(String a, String b) {
        if (a.length() != b.length()) return false;
        int[] cnt = new int[26];
        for (int i = 0; i < a.length(); i++) {
            cnt[a.charAt(i) - 'a']++;             // 一个加、一个减：最后全 0 即异位词
            cnt[b.charAt(i) - 'a']--;
        }
        for (int c : cnt) if (c != 0) return false;
        return true;
    }

    // ---------- 场景 3：key 是 [1, n] 的整数 → int[n + 1] ----------
    /** 1..n 中哪个数重复、哪个数丢失 */
    public int[] findErrorNums(int[] nums) {
        int n = nums.length;
        int[] cnt = new int[n + 1];               // 下标就是 key，浪费 0 号位换语义清晰
        for (int x : nums) cnt[x]++;
        int dup = 0, miss = 0;
        for (int v = 1; v <= n; v++) {
            if (cnt[v] == 2) dup = v;
            else if (cnt[v] == 0) miss = v;
        }
        return new int[]{dup, miss};
    }
}
```

**为什么 `merge` 比 `put + getOrDefault` 好？** 两者等价，但 `merge` 把"默认值"和"合并规则"一次表达完，长度更短，也不会出现"默认值类型和 value 类型不匹配"的问题。

**`int[n + 1]` 那个 `+1` 是干什么的？** 题目的值是 `1..n`，如果开 `int[n]` 就得写 `cnt[x - 1]++`，然后读的时候再 `+1` 还原，一来一回极易写错。多花一个 `int` 换"下标 = 值"的直白语义，**非常划算**——这是本仓库 [ErrorNums.java](../src/hashTable/ErrorNums.java) 的做法（它写的是 `cnt[i - 1]++`，读时 `i + 1`，能过但绕）。

### 2.2 模板 B：去重 + 找重复

```java
public class DedupTemplate {

    // 惯用 1：用 add 的返回值当"重复"信号，只遍历一遍
    public boolean containsDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) if (!seen.add(x)) return true;
        return false;
    }

    // 惯用 2：返回第一个重复出现的元素（剑指 Offer 03）
    public int findRepeatNumber(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) if (!seen.add(x)) return x;
        return -1;
    }

    // 惯用 3：找"唯一"的元素 —— 计数为 1
    public int singleNumber(int[] nums) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : nums) cnt.merge(x, 1, Integer::sum);
        for (int x : nums) if (cnt.get(x) == 1) return x;   // 注意是 == 1，不是 != 2
        return -1;
    }

    // 惯用 4：两个数组求交集 —— 结果去重用 Set，保留次数用 Map
    public int[] intersection(int[] a, int[] b) {
        Set<Integer> sa = new HashSet<>();
        for (int x : a) sa.add(x);
        Set<Integer> res = new LinkedHashSet<>();   // LinkedHashSet 保留遍历顺序，方便调试
        for (int x : b) if (sa.contains(x)) res.add(x);
        int[] out = new int[res.size()];
        int i = 0;
        for (int x : res) out[i++] = x;
        return out;
    }

    // 惯用 5：保留重复次数的交集（350 题）—— 用 Map 取 min
    public int[] intersect(int[] a, int[] b) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : a) cnt.merge(x, 1, Integer::sum);
        List<Integer> res = new ArrayList<>();
        for (int x : b) {
            int c = cnt.getOrDefault(x, 0);
            if (c > 0) {
                res.add(x);
                cnt.put(x, c - 1);      // 用掉一次配额，保证不会多取
            }
        }
        return res.stream().mapToInt(Integer::intValue).toArray();
    }
}
```

**`cnt.get(x) == 1` 里的 `==` 安全吗？** 安全——`cnt.get(x)` 是 `Integer`，与字面量 `int` 比较时 Java 会**自动拆箱**成 `int` 再做数值比较。危险的是 `cnt.get(x) == cnt2.get(y)` 这种**两个 `Integer` 对象的引用比较**。

### 2.3 模板 C：分组 —— key 设计才是重点

```java
public class GroupKeyTemplate {

    // key 设计 1：把元素"规范化"成同组唯一的形式 —— 排序
    // 适用：组内元素可以任意重排（字母异位词、字母异位词分组的各种变体）
    public List<List<String>> groupBySorted(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String s : strs) {
            char[] cs = s.toCharArray();
            Arrays.sort(cs);
            groups.computeIfAbsent(new String(cs), k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(groups.values());
    }

    // key 设计 2：用"计数"当 key —— 比排序快，但要处理分隔符
    public List<List<String>> groupByCount(String[] strs) {
        Map<String, List<String>> groups = new HashMap<>();
        for (String s : strs) {
            int[] cnt = new int[26];
            for (char c : s.toCharArray()) cnt[c - 'a']++;
            StringBuilder key = new StringBuilder();
            for (int c : cnt) key.append(c).append('#');   // 分隔符不能省！
            groups.computeIfAbsent(key.toString(), k -> new ArrayList<>()).add(s);
        }
        return new ArrayList<>(groups.values());
    }

    // key 设计 3：只需"出现的字符集合"当 key —— 用 bitmask
    // 适用：只关心字符有没有出现，不关心次数
    public int countGroupsByMask(String[] words) {
        Set<Integer> masks = new HashSet<>();
        for (String w : words) {
            int mask = 0;
            for (char c : w.toCharArray()) mask |= 1 << (c - 'a');   // 第 i 位为 1 表示含该字母
            masks.add(mask);
        }
        return masks.size();
    }
}
```

**三种 key 的对比**：

| key 形式 | 时间复杂度（每个词长 k） | 能否区分次数 | 典型题 |
| --- | --- | --- | --- |
| 排序后的字符串 | `O(k log k)` | ✅ | 49 字母异位词分组 |
| 计数 + 分隔符 | `O(k + 26)` | ✅ | 49 变体、[893 特殊等价字符串组](../src/hashTable/NumSpecialEquivGroups.java) |
| 字符 bitmask（`int`） | `O(k)` | ❌ 只知道有没有 | 含唯一字符的题、状态压缩 |

> ⚠️ **分隔符是必须的**：`cnt = [1, 11, 0, ...]` 与 `cnt = [11, 1, 0, ...]` 如果直接首尾相接连成字符串，都会得到 `"1110..."`——**不同的计数表撞成同一个 key**，分组就错了。加一个 `'#'` 或者按固定宽度补零（`String.format("%03d", c)`）都能解决。

**为什么用 `int` 做 bitmask 的 key 可以省分隔符？** 因为每个字母固定占一位，位与位之间不会串味——**定长编码天然没有歧义**，这是上一条坑的通用解法。

## 三、典型例题

### 1. 有效的字母异位词

**题意一句话**：判断 `t` 是不是 `s` 的字母重排。

**思路**：暴力是"把 `s` 和 `t` 分别排序再比较"，`O(k log k)`。优化的那一步消除了什么冗余？——**排序是在为比较服务，而比较只需要"每个字母的个数相同"**。用计数数组就能在 `O(k)` 内完成，还省掉了排序的空间。

```java
// 推荐版本：一次遍历，一个加一个减
public boolean isAnagram(String s, String t) {
    if (s.length() != t.length()) return false;     // 早退，省掉后面的全部工作
    int[] cnt = new int[26];
    for (int i = 0; i < s.length(); i++) {
        cnt[s.charAt(i) - 'a']++;
        cnt[t.charAt(i) - 'a']--;                   // 关键：共用一个数组，抵消
    }
    for (int c : cnt) if (c != 0) return false;
    return true;
}

// 变体：字符串含任意字符（含空格、大写）→ 用 int[128] 或 Map
public boolean isAnagramGeneral(String s, String t) {
    if (s.length() != t.length()) return false;
    Map<Character, Integer> cnt = new HashMap<>();
    for (char c : s.toCharArray()) cnt.merge(c, 1, Integer::sum);
    for (char c : t.toCharArray()) {
        int c2 = cnt.getOrDefault(c, 0);
        if (c2 == 0) return false;                  // t 里多了字符
        cnt.put(c, c2 - 1);
    }
    return true;
}
```

> 参考实现：[src/hashTable/RansomMagazine.java](../src/hashTable/RansomMagazine.java)（同模板，由"相等"变成"够用"）

**复杂度**：时间 `O(k)`（k 为串长），空间 `O(1)`（26 个桶是常数）。

> **一句可以推广的判据**：凡是要判断"两个多重集是否相等"，都可以用**一个加、一个减，最后检查是否全零**。凡是要判断"能不能凑出来"（子集关系），就只能**单向相减，检查是否会减成负数**——写题时先想清楚是"相等"还是"够用"。

*有效的字母异位词是【计数数组相等判定】，关键突破点是"一个加一个减，最后看是否全零"，边界是【长度不等直接 false、区分相等与够用两种语义】。*

### 2. 字母异位词分组

**题意一句话**：把互为字母重排的字符串放到同一个组里。

**思路**：暴力两两比较是 `O(n^2 k)`。优化的关键一步是：**给每个词算一个"同组词完全相同"的 key，让哈希来做分组**。此时"比较"这件事被彻底消除了——同一个 key 天然进同一个桶。

```java
// 写法一：排序 key —— 代码最短，适合面试白板
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String s : strs) {
        char[] cs = s.toCharArray();
        Arrays.sort(cs);
        groups.computeIfAbsent(new String(cs), k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(groups.values());
}

// 写法二：计数 key —— 更快，适合 k 很大的用例
public List<List<String>> groupAnagrams2(String[] strs) {
    Map<String, List<String>> groups = new HashMap<>();
    for (String s : strs) {
        int[] cnt = new int[26];
        for (char c : s.toCharArray()) cnt[c - 'a']++;
        StringBuilder key = new StringBuilder();
        for (int c : cnt) key.append(c).append('#');
        groups.computeIfAbsent(key.toString(), k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(groups.values());
}
```

**用一个小样例跑一遍（`strs = ["eat","tea","tan","ate","nat","bat"]`）**：

```
"eat" → 排序 "aet" → {aet: [eat]}
"tea" → 排序 "aet" → {aet: [eat, tea]}
"tan" → 排序 "ant" → {aet: [eat, tea], ant: [tan]}
"ate" → 排序 "aet" → {aet: [eat, tea, ate], ant: [tan]}
"nat" → 排序 "ant" → {aet: [...], ant: [tan, nat]}
"bat" → 排序 "abt" → {... , abt: [bat]}
最终 values = [[eat,tea,ate], [tan,nat], [bat]]     ← 组的顺序不可预测！
```

> 参考实现：[src/hashTable/GroupAna.java](../src/hashTable/GroupAna.java)

**复杂度**：时间 `O(n · k log k)`（排序版）/ `O(n · k)`（计数版）；空间 `O(n · k)` 存储全部字符串作为 key。

> ⚠️ **仓库版本说明**：`GroupAna.java` 的思路（排序做 key）是对的，但有两处可以改进：（1）它把排序后的字符串取 `hashCode()` 压成一个 `int` 当 key，理论上存在哈希冲突把不同组混在一起的风险；（2）分组靠"先收集所有 key，再对每个 key 扫一遍全部词"，退化成 `O(n^2)`。**推荐版本**直接用 `String` 做 key 并用 `computeIfAbsent` 一次分组。
>
> **一个真实存在的输出顺序坑**：题目对组的顺序和组内顺序都不作要求，所以 `[[bat],[tan,nat],[eat,tea,ate]]` 也是合法答案。**不要为了让输出顺序和示例一致而去排序**，那是无用功。

*字母异位词分组是【规范化 key + 哈希分组】，关键突破点是"设计一个同组词完全相同的 key，让哈希代替比较"，边界是【空串也要进组、计数 key 必须加分隔符、输出顺序不要求】。*

### 3. 只出现一次的数字

**题意一句话**：除一个数只出现一次外，其余都出现两次，找出它。

**思路**：哈希计数是通用解，`O(n)` 时间 `O(n)` 空间。但**"其余都出现恰好两次"这个条件太强了**——它不是"计数"问题，而是"奇偶性"问题，于是可以用异或把空间压到 `O(1)`。

```java
// 解法一：哈希计数 —— 通用，能处理"其余出现三次"等变体
public int singleNumber(int[] nums) {
    Map<Integer, Integer> cnt = new HashMap<>();
    for (int x : nums) cnt.merge(x, 1, Integer::sum);
    for (int x : nums) if (cnt.get(x) == 1) return x;
    return -1;
}

// 解法二：异或 —— 最优，O(1) 空间
public int singleNumber2(int[] nums) {
    int res = 0;                      // 初值必须是 0：0 ^ x = x
    for (int x : nums) res ^= x;      // 成对的数互相抵消
    return res;
}
```

**代入演算（`nums = [4, 1, 2, 1, 2]`）**：

```
res = 0
res = 0 ^ 4 = 4
res = 4 ^ 1 = 5
res = 5 ^ 2 = 7
res = 7 ^ 1 = 6
res = 6 ^ 2 = 4    ← 1 和 2 各抵消一次，只剩 4 ✅
```

> 参考实现：[src/hashTable/SingleNum.java](../src/hashTable/SingleNum.java)

| 解法 | 时间 | 空间 | 适用条件 |
| --- | --- | --- | --- |
| 哈希计数 | `O(n)` | `O(n)` | 任意变体（出现 1 次 / 3 次 / 找两个只出现一次的） |
| 排序后相邻比较 | `O(n log n)` | `O(1)` | 会修改原数组 |
| **异或** | `O(n)` | `O(1)` | 仅当"其余元素出现偶数次" |

*只出现一次的数字是【计数哈希与位运算的分界点】，关键突破点是"识别出重复次数是偶数 → 用异或"，边界是【异或初值必须为 0、单元素数组直接返回它】。*

### 4. 同构字符串

**题意一句话**：`s` 能否通过"每个字符稳定替换成另一个字符"变成 `t`。

**思路**：暴力是枚举所有映射（阶乘级）。真正的关键洞察是：**映射必须是双射（一一对应）**，所以只需要两张表，边遍历边登记边校验，`O(n)` 搞定。

```
s = "badc"   t = "baba"

i=0: s->t: b→b ✅    t->s: b→b ✅
i=1: s->t: a→a ✅    t->s: a→a ✅
i=2: s->t: d→b ✅    t->s: b 已经映射到 b，现在要映射到 d ❌ → false
```

```java
public boolean isIsomorphic(String s, String t) {
    if (s.length() != t.length()) return false;
    Map<Character, Character> s2t = new HashMap<>();
    Map<Character, Character> t2s = new HashMap<>();
    for (int i = 0; i < s.length(); i++) {
        char a = s.charAt(i), b = t.charAt(i);
        // 注意用 containsKey 而不是 get != null：'a' 这类合法值不能和"未登记"混淆
        if (s2t.containsKey(a) && s2t.get(a) != b) return false;
        if (t2s.containsKey(b) && t2s.get(b) != a) return false;
        s2t.put(a, b);
        t2s.put(b, a);
    }
    return true;
}
```

> 参考实现：[src/hashTable/IsomorphicStr.java](../src/hashTable/IsomorphicStr.java)

**这里的 `!=` 能直接比较 `char` 吗？** 能——`s2t.get(a)` 是 `Character`，与 `char` 比较时会**自动拆箱成 `char` 做数值比较**（这是 JLS 规定的拆箱规则），不是引用比较。写成 `!s2t.get(a).equals(b)` 也正确，但这里 `char` 版本更直观。

> ⚠️ **仓库版本说明**：`IsomorphicStr.java` 的单向表 + 最后检查 `map.values()` 有无重复，逻辑上确实等价于"单射性检查"，但有两个小问题：（1）需要额外构造 `ArrayList` 和 `HashSet` 来比较，空间和代码都变多；（2）不能提前退出，即使在第 2 个字符就发现冲突也要把整串走完。**推荐版本**用反向表边遍历边拦截。

*同构字符串是【双向哈希映射】，关键突破点是"映射必须是一一对应，所以要维护两张互为反向的表"，边界是【长度不等直接 false、字符映射到自身是合法的】。*

### 5. 单词规律

**题意一句话**：`pattern` 里的每个字符和 `str` 里按空格切出的每个单词，能否一一对应。

**思路**：把上一题从"字符 ↔ 字符"升级成"字符 ↔ 单词"，**结构完全一样**，只是 `t2s` 的值类型从 `Character` 变成 `String`。这类"换了个壳的同一道题"是刷题中最值得留意的模式。

```java
public boolean wordPattern(String pattern, String s) {
    String[] words = s.split(" ");
    char[] p = pattern.toCharArray();
    if (p.length != words.length) return false;          // 数量对不上，直接 false
    Map<Character, String> p2w = new HashMap<>();
    Map<String, Character> w2p = new HashMap<>();
    for (int i = 0; i < p.length; i++) {
        // 用 getOrDefault 不行！合法的映射值可能是任何字符串，必须用 containsKey 区分"未登记"
        if (p2w.containsKey(p[i]) && !p2w.get(p[i]).equals(words[i])) return false;
        if (w2p.containsKey(words[i]) && w2p.get(words[i]) != p[i]) return false;
        p2w.put(p[i], words[i]);
        w2p.put(words[i], p[i]);
    }
    return true;
}
```

> 参考实现：[src/hashTable/WordPattern.java](../src/hashTable/WordPattern.java)

**两个易错点**：

1. `s.split(" ")` 对**连续空格**会产生空串元素。本题保证单词间只有单个空格，所以安全；但生产代码里应该用 `s.split("\\s+")`。
2. 字符串比较必须用 `equals`，`p2w.get(p[i]) != words[i]` 比的是引用，**会静默出错**。

> ⚠️ **仓库版本说明**：`WordPattern.java` 的 `else` 分支在"两个表都没登记"时也会走 `!words[i].equals(wordMap.get(chars[i]))`——此时 `wordMap.get` 返回 `null`，`equals(null)` 返回 `false`，`!false = true` 就直接 `return false` 了。这**恰好**让"字符和单词都是新的"这种情况被误判为不匹配。它能过测试是因为后面还有一次 `containsValue` 检查兜底，但逻辑已经绕成了一团。**推荐版本**用两个独立的 `containsKey` 判断，语义清晰。

*单词规律是【双向哈希映射的字符串版】，关键突破点是"识别出和同构字符串是同一个模板"，边界是【切词后数量不等直接 false、字符串比较用 equals】。*

### 6. 最常见的单词

**题意一句话**：按非字母字符切词、统一小写、剔除 `banned`，返回出现次数最多的词。

**思路**：这题一半是**切词模拟**，一半是**计数取最大**。切词的冗余在于"每个位置都要判断是不是分隔符"，用 `StringBuilder` 缓冲一个词，遇到分隔符就结算。

```java
public String mostCommonWord(String paragraph, String[] banned) {
    Set<String> bannedSet = new HashSet<>(Arrays.asList(banned));
    paragraph += " ";                             // 关键技巧：补一个分隔符，统一处理结尾
    Map<String, Integer> cnt = new HashMap<>();
    StringBuilder sb = new StringBuilder();

    for (char c : paragraph.toCharArray()) {
        if (Character.isLetter(c)) {
            sb.append(Character.toLowerCase(c));
        } else if (sb.length() > 0) {             // 只有缓冲区非空才结算，跳过连续分隔符
            String w = sb.toString();
            sb.setLength(0);                      // 复用 StringBuilder，避免反复 new
            if (!bannedSet.contains(w)) cnt.merge(w, 1, Integer::sum);
        }
    }

    String best = "";
    int max = 0;
    for (Map.Entry<String, Integer> e : cnt.entrySet()) {
        if (e.getValue() > max) {                 // 严格大于；并列时取任意一个
            max = e.getValue();
            best = e.getKey();
        }
    }
    return best;
}
```

> 参考实现：[src/hashTable/MostCommonWord.java](../src/hashTable/MostCommonWord.java)

**复杂度**：时间 `O(L + B)`（L 为段落长度，B 为 banned 总长）；空间 `O(L)`（最坏情况整段没有分隔符，一个词占了整个 `StringBuilder`）。

> **把 `paragraph += " "` 去掉会怎样？** 最后一个词后面没有分隔符，永远不会进入 `else if` 分支，于是被漏掉——如果它是最高频词，答案就错了。这个"补哨兵"的技巧在切词题里几乎总是值得的。

*最常见的单词是【切词 + 频次哈希】，关键突破点是"在末尾补一个分隔符统一边界处理"，边界是【连续分隔符不产生空词、banned 词不计数、全无字母时返回空串】。*

## 四、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 计数 key 拼接不加分隔符 | `[1,11]` 和 `[11,1]` 撞成同一个 key，分组错乱 | 用 `'#'` 分隔或按固定宽度补零 |
| 用 `map.get(k) == map2.get(k2)` 比较 | 两个 `Integer` 的引用比较，超 127 静默出错 | 先拆箱给 `int` 变量再比 |
| 分组写 `getOrDefault(k, new ArrayList<>())` | 新 List 没放回 map，分组全空 | `computeIfAbsent(k, x -> new ArrayList<>())` |
| 判断"够用"时用了"相等"的写法 | 子集类题目答案错误 | 子集要检查是否减成负数，不能只看最后是否全零 |
| `split(" ")` 处理多个连续空格 | 产生空字符串元素，多算一个"词" | `split("\\s+")` 或手工扫字符 |
| 字符串用 `==` 比较 | 引用比较，内容相同也可能 false | 用 `equals` |
| 期望 `HashSet` / `HashMap` 遍历顺序稳定 | 结果随机，调试困难 | 需要顺序用 `LinkedHashSet`/`LinkedHashMap`，或取出后排序 |
| 遍历 `Map` 时 `remove` | `ConcurrentModificationException` | 先收集 key，再批量删；或 `removeIf` |
| `int[26]` 计数后忘了检查"是否有负数" | 只能发现"少了"，发现不了"多了" | 两个方向都要查，或者写 `if (c != 0) return false` |
| 只出现一次的数字用 `!= 2` 判断 | 元素出现 3 次时误判为答案 | 明确写 `== 1` |
