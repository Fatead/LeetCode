# 03 映射与查找

> **一句话理解**：哈希表在这一节扮演的是"**备忘录**"——把"我见过什么"记下来，从而把"回头找一遍"变成"直接问一次"。
> 这一节最值钱的两个模板是：**两数之和的"先查后存"** 和 **前缀和 + 哈希的"查历史前缀"**。

---

## 一、判定标准

### 1.1 什么时候用哈希做查找

| 题目信号 | 哈希在记什么 | 优化掉的冗余 | 典型题 |
| --- | --- | --- | --- |
| "找两个数满足某关系" | 走过的数（或它的下标） | 内层 `O(n)` 的回扫 | [1 两数之和](../src/hashTable/TwoSum.java) |
| "子数组的和/积满足条件" | **历史前缀和**及其出现次数 | 枚举左右端点的 `O(n^2)` | [560 和为 K 的子数组](../src/array/SubArraySum.java) |
| "在序列里找连续的链" | 所有元素（用于 `O(1)` 判断邻居） | 排序的 `O(n log n)` | [128 最长连续序列](../src/UnionFind/LongestConsecutive.java) |
| "查找某个东西对应的信息" | "值 → 下标/编号"的映射表 | 每次都要遍历原数组找位置 | [599 两个列表的最小索引总和](../src/hashTable/FindRestaurant.java) |
| "判断某条链会不会回到起点" | 走过的状态 | 无脑循环的无限迭代 | [202 快乐数](../src/hashTable/HappyNumber.java) |
| "同一行/列/宫内不能重复" | 每行、每列、每宫已出现的数字 | 三重循环两两比较 | [36 有效数独](../src/hashTable/ValidSudoku.java) |

### 1.2 什么时候**不**该用哈希

| 情况 | 为什么 | 更好的做法 |
| --- | --- | --- |
| 数组已排序，要找两个数 | 双指针 `O(n)` 且空间 `O(1)`，比哈希更省 | 左右指针（[TwoSum.java](../src/hashTable/TwoSum.java) 的 `twoSum2`） |
| 每个元素只需和"**固定窗口内**"的历史比 | 哈希会把过期元素也算进去 | 哈希 + 滑动窗口（窗口移出时要删除） |
| 要找"最长的连续链"但**允许排序** | 排序法是 `O(n log n)` 且代码更短 | 排序后一次扫描 |
| 前缀和的值域很小且已知 | 数组比 `HashMap` 快 | `int[]` 计数（例如 mod k 的结果） |
| 需要找"和最大的子数组" | 哈希只能回答"有没有"，回答不了"最大" | 前缀和 + 维护最小值（[MaxSubArray](../src/array/MaxSubArray.java)） |

> **一句话判据**：哈希擅长"**存在性问题**"（有没有、有几个）。
> 一旦问题变成"**最优性问题**"（最大、最小、最长），哈希只能作为**辅助**，主算法还得是别的（双指针、DP、排序）。

### 1.3 "空间换时间"到底换了多少

| 题 | 暴力 | 哈希优化后 | 换来的空间 |
| --- | --- | --- | --- |
| 1 两数之和 | `O(n^2)` | `O(n)` | `O(n)` |
| 560 和为 K 的子数组 | `O(n^2)` | `O(n)` | `O(n)` |
| 128 最长连续序列 | `O(n log n)`（排序） | `O(n)` | `O(n)` |
| 202 快乐数 | 可能死循环 | `O(链长)` | `O(链长)` |

**注意最后一列的规律**：优化几乎总是把时间降一维，代价是**同样的 `O(n)` 空间**。面试被问"能不能不用额外空间"时，要看有没有别的有序性可利用（比如排序，或者快慢指针）。

## 二、Java 通用模板

### 2.1 模板 A：两数之和的"先查后存"

这是整个哈希专题里最通用的一个模板，**几乎所有"找一对"的题都是它的变形**。

```java
import java.util.*;

public class TwoSumTemplate {

    /**
     * 在数组中找两个数，使它们的和为 target，返回这两个数的下标。
     * 核心：边遍历边建表；查的时候当前元素还没入表，天然避免"自己配自己"。
     */
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();   // key=数值, value=下标
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) {               // ① 先查
                return new int[]{seen.get(need), i};
            }
            seen.put(nums[i], i);                       // ② 后存
        }
        return new int[0];                              // 题目保证有解，这里兜底
    }

    /**
     * 变形 1：只问"有没有"这样一对（不关心下标）→ 用 Set 更省
     * 适用：数组已排序 / 只需布尔答案
     */
    public boolean hasPairWithSum(int[] nums, int target) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            if (seen.contains(target - x)) return true;
            seen.add(x);
        }
        return false;
    }

    /**
     * 变形 2：找"差值"而不是"和" → 只是 need 的表达式变了
     * 模板不变：need = f(nums[i], target)
     */
    public boolean hasPairWithDiff(int[] nums, int diff) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            // 差为 diff 有两种方向，都要查
            if (seen.contains(x - diff) || seen.contains(x + diff)) return true;
            seen.add(x);
        }
        return false;
    }
}
```

**为什么必须"先查后存"？** 三个好处一次说清：

1. **避免自己配自己**。如果先把 `nums[i]` 存进表，`target = 2 * nums[i]` 时 `need == nums[i]` 会命中自己，返回 `[i, i]` 这种非法答案。
2. **避免处理重复值**。可以先查后存的话，遇到两个相同的值（如 `[3,3], target=6`）也天然正确：第二个 `3` 查到了第一个 `3`。
3. **一趟遍历搞定**。不用先建全表再遍历（那是两趟）。

### 2.2 模板 B：前缀和 + 哈希（本节最重要的模板）

**先看它解决了什么问题**：

```
求 sum(i..j) == k 的子数组个数
暴力：枚举 i、j 两个端点           → O(n^2)
前缀和：预处理 P[i] = sum(0..i-1)  → 仍需枚举两个端点 → 仍是 O(n^2)
关键一步：sum(i..j) = P[j+1] - P[i] == k  ⟺  P[i] == P[j+1] - k
         于是"找一个 i"变成"查一个历史前缀值是否存在" → 哈希 O(1)
```

```java
public class PrefixSumTemplate {

    /**
     * 560. 和为 K 的子数组：统计和恰好为 k 的连续子数组个数
     * 数组可能有负数 —— 这一点很重要，有负数就不能用滑动窗口
     */
    public int subarraySum(int[] nums, int k) {
        // key = 前缀和的值, value = 这个前缀和出现过几次
        Map<Integer, Integer> prefixCount = new HashMap<>();
        prefixCount.put(0, 1);      // ① 空前缀：代表"从数组开头到 j"这一段本身
        int sum = 0, count = 0;
        for (int x : nums) {
            sum += x;                                   // sum = P[j+1]
            // ② 查历史：之前有多少个前缀和等于 sum - k，就有多少个以 j 结尾的合法区间
            count += prefixCount.getOrDefault(sum - k, 0);
            // ③ 后存：先查后存，避免 sum - k == sum（即 k == 0）时把自己算进去
            prefixCount.merge(sum, 1, Integer::sum);
        }
        return count;
    }

    /**
     * 974. 和可被 K 整除的子数组：把"前缀和的值"换成"前缀和的余数"
     * 同余定理：P[j] % k == P[i] % k  ⟺  (P[j] - P[i]) % k == 0
     */
    public int subarraysDivByK(int[] nums, int k) {
        Map<Integer, Integer> cnt = new HashMap<>();
        cnt.put(0, 1);              // 余数 0 的"空前缀"也要记一次
        int sum = 0, res = 0;
        for (int x : nums) {
            sum += x;
            int mod = ((sum % k) + k) % k;              // ④ Java 负数取模仍是负数，必须修正
            int same = cnt.getOrDefault(mod, 0);
            res += same;                                // 与历史同余的前缀两两配对
            cnt.put(mod, same + 1);
        }
        return res;
    }
}
```

**用一个小例子把模板 B 跑一遍（`nums = [1, 1, 1], k = 2`）**：

```
初始：prefixCount = {0: 1}, sum = 0, count = 0

x = 1: sum = 1; 查 sum - k = -1 → 没有         count = 0
       存: {0:1, 1:1}
x = 1: sum = 2; 查 2 - 2 = 0  → 有 1 个       count = 1   ← 区间 [0..1]
       存: {0:1, 1:1, 2:1}
x = 1: sum = 3; 查 3 - 2 = 1  → 有 1 个       count = 2   ← 区间 [1..2]
       存: {0:1, 1:1, 2:1, 3:1}

答案 2 ✅（[1,1] 和 [1,1]）
```

**三个必须记住的细节**：

| 细节 | 为什么 |
| --- | --- |
| `prefixCount.put(0, 1)` 初始化 | 代表"空前缀"，让"从下标 0 开始的区间"能被算上 |
| 先 `count +=` 再 `merge` | 否则 `k == 0` 时当前前缀会配对自己，多算 |
| `((sum % k) + k) % k` | Java 里 `-7 % 5 == -2`，负数余数会让同余判断失效 |

### 2.3 模板 C：用 `Set` 把"链上扩展"变成 `O(1)`

```java
/**
 * 128. 最长连续序列：O(n) 求最长连续递增序列长度（不要求原数组有序）
 *
 * 暴力/排序：O(n log n)
 * 哈希的关键洞察：一个连续段只需要从"没有前驱"的那个数开始扩展，
 *                其他数都是段中间的，跳过即可 → 每个数最多被访问 2 次
 */
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);          // 去重 + O(1) 查询
    int longest = 0;
    for (int x : set) {                     // 注意遍历 set 而不是 nums，天然去重
        if (set.contains(x - 1)) continue;  // ★ 不是段起点，跳过 —— O(n) 的关键
        int cur = x;
        while (set.contains(cur + 1)) cur++; // 从起点向后扩展
        longest = Math.max(longest, cur - x + 1);
    }
    return longest;
}
```

**为什么加了 `if (set.contains(x - 1)) continue;` 就从 `O(n^2)` 变成 `O(n)`？**

```
数组 [1,2,3,4,...,n]：
  不加判断：从 1 扩展 n 步、从 2 扩展 n-1 步、… → O(n^2)
  加了判断：只有 set.contains(i-1) 为 false 的数才会进入 while
           即只有 1（真正的起点）会走完 n 步，其余 2..n 全部在 continue 处 O(1) 跳过
  总代价 = n 次 O(1) 判断 + 1 次 O(n) 扩展 = O(n)   ✅
```

### 2.4 模板 D：判环（哈希 vs 快慢指针）

```java
public class CycleTemplate {

    /**
     * 202. 快乐数：不断把 n 换成"各位数字的平方和"，判断最终能否到 1
     * 若不能到 1，一定会进入环（有限状态 + 确定性转移 = 必有环）
     */
    // 写法一：哈希判环 —— 逻辑最直白
    public boolean isHappyBySet(int n) {
        Set<Integer> seen = new HashSet<>();
        while (n != 1 && seen.add(n)) {      // add 返回 false ⇒ 出现过 ⇒ 有环 ⇒ 不是快乐数
            n = squareSum(n);
        }
        return n == 1;
    }

    // 写法二：快慢指针（Floyd 判圈）判环 —— O(1) 空间
    public boolean isHappyByFloyd(int n) {
        int slow = n, fast = squareSum(n);
        while (fast != 1 && slow != fast) {  // fast 到 1 就提前结束
            slow = squareSum(slow);          // 每次 1 步
            fast = squareSum(squareSum(fast));// 每次 2 步
        }
        return fast == 1;
    }

    private int squareSum(int n) {
        int sum = 0;
        while (n > 0) {
            int d = n % 10;
            sum += d * d;
            n /= 10;
        }
        return sum;
    }
}
```

**两种判环方式的取舍**：

| 维度 | 哈希判环 | 快慢指针（Floyd） |
| --- | --- | --- |
| 时间 | `O(链长)` | `O(链长)`，常数约 2 倍 |
| 空间 | `O(链长)` | **`O(1)`** |
| 能否求环入口 | 能（记录第一次出现的下标） | 能（相遇后重置一个指针） |
| 实现难度 | 极低 | 中等，容易在初始条件上写错 |

## 三、典型例题

### 1. 两数之和

**题意一句话**：找两个数使其和为 `target`，返回下标。

**思路**：暴力的内层循环在问"`target - nums[i]` 在不在数组里"。把"已经走过的数"放进哈希，这个问题变 `O(1)`，`O(n^2) → O(n)`。

```java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);      // 后存：保证不会用到当前元素
    }
    return new int[0];
}
```

> 参考实现：[src/hashTable/TwoSum.java](../src/hashTable/TwoSum.java)

**复杂度**：时间 `O(n)`；空间 `O(n)`。

> ⚠️ **仓库版本说明**：`TwoSum.java` 的 `twoSum` 解的是"**升序数组、返回数值**"的变体，它先把所有数塞进 `Set`，再对每个 `nums[i]` 查 `target - nums[i]`，并为 `target == 2 * nums[i]`（同一个数用两次）专门数了一遍重复次数。这段逻辑能过，但把"两数之和"最精髓的"先查后存"给绕开了。**推荐版本**（上面那段）用一次遍历同时完成"查补数"和"登记自己"，不需要任何特判。仓库里的 `twoSum2` 是排序双指针版，返回的也是数值。

*两数之和是【哈希备忘录】，关键突破点是"先查补数再登记自己"，边界是【空数组返回空、同一元素不能用两次、有重复值也要正确】。*

### 2. 和为 K 的子数组

**题意一句话**：统计和恰好为 `k` 的连续子数组个数（**元素可以是负数**）。

**思路**：暴力枚举左右端点 `O(n^2)`。优化那一步的关键是**把 `sum(i..j) = k` 改写成 `P[j+1] - P[i] = k`**，于是"找一个 `i`"变成"查一个前缀和是否出现过"——这正是哈希的强项。

```java
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> prefix = new HashMap<>();
    prefix.put(0, 1);                       // 空前缀，处理"从 0 开始"的区间
    int sum = 0, count = 0;
    for (int x : nums) {
        sum += x;
        count += prefix.getOrDefault(sum - k, 0);
        prefix.merge(sum, 1, Integer::sum); // 必须先查后存
    }
    return count;
}
```

> 参考实现：[src/array/SubArraySum.java](../src/array/SubArraySum.java)（`subArraySum2` 就是哈希版，`subArraySum` 是前缀和 + 双重循环的 `O(n^2)` 版）、[src/array/SubArraysDiv.java](../src/array/SubArraysDiv.java)（同模板的"整除"变体）、[src/array/SubArraySumK.java](../src/array/SubArraySumK.java)

**复杂度**：时间 `O(n)`；空间 `O(n)`（最坏情况下前缀和互不相同）。

| 解法 | 时间 | 空间 | 能否处理负数 |
| --- | --- | --- | --- |
| 枚举左右端点 | `O(n^2)` | `O(1)` | ✅ |
| 前缀和 + 双重循环 | `O(n^2)` | `O(n)` | ✅（预处理好，但仍要枚举） |
| **前缀和 + 哈希** | `O(n)` | `O(n)` | ✅ |
| 滑动窗口 | `O(n)` | `O(1)` | ❌ **有负数就不行**（窗口和不单调） |

> **为什么有负数就不能滑动窗口？** 因为滑动窗口依赖"窗口和随右指针移动单调变化"。一旦有负数，扩大窗口可能让和变小，收缩窗口可能让和变大，"右移左指针直到和 ≤ k"这种收缩逻辑就不再成立。这是这题最重要的一句话，面试常被追问。

*和为 K 的子数组是【前缀和 + 哈希】，关键突破点是"把区间和改写成两个前缀和之差，从而把'找区间'变成'查历史前缀'"，边界是【必须初始化 `{0: 1}`、必须先查后存、负数取模要修正】。*

### 3. 最长连续序列

**题意一句话**：在**无序**数组里求最长连续整数序列的长度，要求 `O(n)`。

**思路**：排序法 `O(n log n)` 已经不难，但题目要求 `O(n)`。关键洞察是：**每个连续段只从它的起点（没有前驱的那个数）开始扩展**，其他数直接跳过——这样每个数最多被访问两次。

```
nums = [100, 4, 200, 1, 3, 2]   → set = {1,2,3,4,100,200}

遍历 set：
  100: 99 在不在？不在 → 是起点 → 扩展到 100（101 不在）长度 1
  4:   3 在不在？在 → 跳过
  200: 199 不在 → 起点 → 长度 1
  1:   0 不在 → 起点 → 1→2→3→4 扩展 4 步 → 长度 4   ★ 这才是 O(n) 的关键
  3:   2 在 → 跳过
  2:   1 在 → 跳过
答案 4 ✅
```

```java
public int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);
    int longest = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;   // ★ 只从段起点扩展
        int cur = x;
        while (set.contains(cur + 1)) cur++;
        longest = Math.max(longest, cur - x + 1);
    }
    return longest;
}
```

> 参考实现：[src/UnionFind/LongestConsecutive.java](../src/UnionFind/LongestConsecutive.java)

**复杂度**：时间 `O(n)`（每个数最多被当作起点一次，`while` 总步数不超过 n）；空间 `O(n)`。

> ⚠️ **仓库版本说明**：`LongestConsecutive.java` 用的是**排序法**（`Arrays.sort` + 一次扫描，用 `nums[i] != nums[i+1]` 跳过重复），时间是 `O(n log n)`、空间取决于排序实现。它边界覆盖完整（空数组、单元素、全相同），是一个**完全正确的 `O(n log n)` 解**——只是没达到题目 `O(n)` 的要求，而且它放在 `UnionFind` 包里却没用并查集。面试要求 `O(n)` 时，必须用上面的 `Set` + 段起点版本。

*最长连续序列是【Set 做邻近判断 + 只从段起点扩展】，关键突破点是"加一句 `contains(x-1)` 判断，把 `O(n^2)` 摊还成 `O(n)`"，边界是【空数组返回 0、重复元素只算一次、单元素返回 1】。*

### 4. 快乐数

**题意一句话**：反复把 `n` 替换成"各位数字的平方和"，判断能否变成 1。

**思路**：这是一个**确定性状态机**：转移函数固定，状态空间有限（`int` 范围内平方和快速收缩到几百），所以**要么降到 1，要么进入一个环**。问题转化为判环。

```java
// 哈希判环：最直白，推荐面试先用这个讲清楚思路
public boolean isHappy(int n) {
    Set<Integer> seen = new HashSet<>();
    while (n != 1 && seen.add(n)) {   // add=false 说明进环了
        n = squareSum(n);
    }
    return n == 1;
}

// Floyd 快慢指针：把空间降到 O(1)，面试追问时再给
public boolean isHappy2(int n) {
    int slow = n, fast = squareSum(n);
    while (fast != 1 && slow != fast) {
        slow = squareSum(slow);
        fast = squareSum(squareSum(fast));
    }
    return fast == 1;
}

private int squareSum(int n) {
    int sum = 0;
    while (n > 0) { int d = n % 10; sum += d * d; n /= 10; }
    return sum;
}
```

> 参考实现：[src/hashTable/HappyNumber.java](../src/hashTable/HappyNumber.java)

**复杂度**：哈希版时间 `O(链长)`、空间 `O(链长)`；Floyd 版时间 `O(链长)`、空间 `O(1)`。链长是常数级（几百以内），所以实际都非常快。

> ⚠️ **仓库版本说明**：`HappyNumber.java` 把结果写在**成员变量 `isHappyNum`** 里，通过递归 `decide` / `isHappy` 实现。两个真实缺陷：（1）**同一对象调用两次会互相污染**——第一次算出 `true` 后该字段永远是 `true`，第二次传别的数会直接错；（2）判环用的 `intSet` 也是成员变量，跨调用累积。**推荐版本**用方法内局部 `Set`，无副作用、可重复调用。

*快乐数是【哈希判环 vs 快慢指针判环】，关键突破点是"识别出这是确定性状态机，不是快乐就是进环"，边界是【n=1 直接返回 true、必须用局部变量避免多次调用互相污染】。*

### 5. 有效数独

**题意一句话**：判断一个 9×9 数独盘面上已填的数字是否合法（行、列、3×3 宫内都不重复）。

**思路**：暴力要对每行、每列、每宫分别两两比较，代码丑且慢。用哈希后，**每个格子只被检查三次**，`O(1)` 每次判断。

**3×3 宫的下标换算（最容易写错的地方）**：

```
9 个宫的编号 k = 0..8（从左到右、从上到下）
   k=0  k=1  k=2
   k=3  k=4  k=5
   k=6  k=7  k=8

第 k 宫覆盖的行范围: [ (k / 3) * 3 , (k / 3) * 3 + 2 ]
第 k 宫覆盖的列范围: [ (k % 3) * 3 , (k % 3) * 3 + 2 ]
其中 k/3 是"宫在第几行块"，k%3 是"宫在第几列块"
```

```java
public boolean isValidSudoku(char[][] board) {
    // 27 个集合：9 行 + 9 列 + 9 宫。用数组下标代替三重嵌套的 Map
    Set<Character>[] rows = new HashSet[9];
    Set<Character>[] cols = new HashSet[9];
    Set<Character>[] boxes = new HashSet[9];
    for (int i = 0; i < 9; i++) {
        rows[i] = new HashSet<>();
        cols[i] = new HashSet<>();
        boxes[i] = new HashSet<>();
    }

    for (int r = 0; r < 9; r++) {
        for (int c = 0; c < 9; c++) {
            char ch = board[r][c];
            if (ch == '.') continue;                 // 空格跳过
            int b = (r / 3) * 3 + c / 3;             // ★ 宫编号，一行搞定
            // add 返回 false 表示这一行/列/宫里已经有这个数字了
            if (!rows[r].add(ch)) return false;
            if (!cols[c].add(ch)) return false;
            if (!boxes[b].add(ch)) return false;
        }
    }
    return true;
}
```

> 参考实现：[src/hashTable/ValidSudoku.java](../src/hashTable/ValidSudoku.java)

**复杂度**：时间 `O(81)`（常数）；空间 `O(81)`（27 个集合，最多 81 个元素）。

> **为什么用 `Set[]` 数组而不是 `Map<Integer, Set<Character>>`？** 三个维度都是 0..8 的固定小范围，数组下标天然就是"哈希"，比 `Map` 快且不用装箱。这正是"[01](01-哈希表基础与Java工具.md) 数组当哈希表"的思想在**复合 key** 上的应用。

> ⚠️ **仓库版本说明**：`ValidSudoku.java` 确实用了 `HashSet`，但它用"`if (!set.contains(x) && x != '.') set.add(x); else if (x != '.') return false;`"这种 `contains` + `add` 两步写法，每个格子做两次哈希查找；而且 `else if` 的结构在读的时候要非常小心才能确认"空格不会被判成重复"。**推荐版本**用 `if (!set.add(ch)) return false;` 一行替代，逻辑更短也更难写错。

*有效数独是【多组哈希 + 复合 key 的下标映射】，关键突破点是"用 `(r/3)*3 + c/3` 把 3×3 宫编号"，边界是【`.` 必须跳过、只判断已填数字、宫编号 0..8 不能越界】。*

### 6. 回旋镖的数量

**题意一句话**：数出所有满足"`i` 到 `j`、`i` 到 `k` 距离相等且 `i≠j≠k`"的三元组个数（**有序**）。

**思路**：暴力枚举三个点是 `O(n^3)`。关键洞察是：**固定中心点 `i`，把其余点到 `i` 的距离分组**，同一组内任意挑两个点就构成一个回旋镖，而且有序（`j`、`k` 可以互换）。

```
固定 i，若某个距离 d 出现了 m 次：
  从 m 个点里选 1 个当 j、再选 1 个不同的当 k
  = m × (m - 1)      ← 排列数 A(m, 2)，不是组合数 C(m, 2)！
```

```java
public int numberOfBoomerangs(int[][] points) {
    int result = 0;
    for (int i = 0; i < points.length; i++) {
        Map<Integer, Integer> distCount = new HashMap<>();   // 距离 → 出现次数
        for (int j = 0; j < points.length; j++) {
            if (i == j) continue;
            int d = dist2(points[i], points[j]);             // 用平方距离避免开根号丢精度
            distCount.merge(d, 1, Integer::sum);
        }
        for (int m : distCount.values()) {
            result += m * (m - 1);                           // 排列数 A(m, 2)
        }
    }
    return result;
}

private int dist2(int[] a, int[] b) {
    int dx = a[0] - b[0], dy = a[1] - b[1];
    return dx * dx + dy * dy;      // 坐标范围小，平方不会溢出 int
}
```

> 参考实现：[src/hashTable/Boomerangs.java](../src/hashTable/Boomerangs.java)

**复杂度**：时间 `O(n^2)`（枚举中心 n 次、每次扫 n 个点）；空间 `O(n)`（每个中心一个距离表）。

> ⚠️ **溢出提醒**：这题坐标范围是 `[-10^4, 10^4]`，`dx` 最大 `2×10^4`，平方后 `4×10^8`，两个加起来 `8×10^8 < 2^31-1 ≈ 2.1×10^9`，**`int` 安全**。但换成更大的坐标范围就要用 `long`——判断是否溢出时**先看数据范围，再决定用不用 `long`**。

> **为什么是 `m * (m-1)` 而不是 `m * (m-1) / 2`？** 因为 `(i, j, k)` 和 `(i, k, j)` 是两个不同的回旋镖（题目明确说"元组的顺序算不同"）。除以 2 就漏了一半。

*回旋镖的数量是【距离分组 + 排列计数】，关键突破点是"固定中心点分组，组内是排列数 `m*(m-1)`"，边界是【`i != j` 必须排除自身、用平方距离避免浮点误差、坐标大时注意溢出】。*

## 四、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 两数之和"先存后查" | 自己配对自己，返回 `[i, i]` | **先查后存** |
| 前缀和哈希忘了 `put(0, 1)` | 漏掉所有"从下标 0 开始"的区间 | 初始化空前缀 |
| 前缀和哈希"先存后查" | `k == 0` 时多算自己 | 先累加答案再更新计数 |
| `sum % k` 直接用 | Java 负数取模为负，同余判断失效 | `((sum % k) + k) % k` |
| 最长连续序列少了 `contains(x-1)` 判断 | 从段中间也扩展，退化成 `O(n^2)` | 只从没有前驱的段起点扩展 |
| 快乐数把状态写在成员变量里 | 同一对象多次调用互相污染 | 用方法内局部变量 |
| 数独宫编号算错 | 漏检或误判 | `(r / 3) * 3 + c / 3` |
| 数独忘了跳过 `.` | 空格的重复被当成冲突 | `if (ch == '.') continue;` |
| 回旋镖除以 2 | 少算一半（有序对） | 用 `m * (m - 1)` |
| 距离用 `Math.sqrt` 比较 | 浮点精度误差导致错误 | 比较**平方**距离 |
| 有负数时用滑动窗口求子数组和 | 答案错误（和不再单调） | 用前缀和 + 哈希 |
| 频繁取 `map.get` 又 `containsKey` | 两次哈希查找 | 一次 `getOrDefault`，或先拆箱给局部变量 |
