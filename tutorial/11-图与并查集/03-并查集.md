# 03 并查集

> **一句话理解**：并查集（Union-Find）专门解决"**动态连通性**"——两个元素是不是一伙的、合并两伙人。它只有两个操作：`find`（找老大）和 `union`（合并）。配上**路径压缩 + 按秩合并**，单次操作近乎 `O(1)`。

---

## 一、并查集解决什么问题

当题目出现这些信号，几乎必是并查集：

- "有多少个**连通块/朋友圈/省份**"
- "动态地**合并**集合，并随时**查询**两个元素是否在同一集合"
- "判断加某条边后无向图是否**成环**"（两端已连通再加边 = 环）

**它和 DFS/BFS 的区别**：DFS/BFS 适合"一次性遍历静态图"；并查集适合"**边不断加入、随时查询连通性**"的动态场景。

## 二、并查集模板（必须背到默写）

```java
class UnionFind {
    int[] parent;   // parent[i] = i 的父节点
    int[] size;     // size[i] = 以 i 为根的集合大小（用于按秩合并）
    int count;      // 连通分量个数

    public UnionFind(int n) {
        parent = new int[n];
        size = new int[n];
        count = n;
        for (int i = 0; i < n; i++) {
            parent[i] = i;      // 初始每个元素自成一组，父节点是自己
            size[i] = 1;
        }
    }

    // 找根节点（带路径压缩）
    public int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // 路径压缩：让 x 指向爷爷，树变矮
            x = parent[x];
        }
        return x;
    }

    // 合并（带按秩合并：小树挂到大树下）
    public void union(int p, int q) {
        int rootP = find(p), rootQ = find(q);
        if (rootP == rootQ) return;          // 已经在一组，不用合并
        if (size[rootP] < size[rootQ]) {     // 把小的挂到大的下面，保持平衡
            parent[rootP] = rootQ;
            size[rootQ] += size[rootP];
        } else {
            parent[rootQ] = rootP;
            size[rootP] += size[rootQ];
        }
        count--;                             // 合并后连通分量减一
    }

    public boolean connected(int p, int q) {
        return find(p) == find(q);
    }

    public int count() { return count; }
}
```

> 参考实现：[src/UnionFind/UnionFind.java](../../src/UnionFind/UnionFind.java)。
>
> ⚠️ **仓库里有一处笔误**：`UnionFind.java` 的 `union` 方法在小树挂大树的分支里写了 `size[rootQ] += rootP`（应为 `size[rootP]`），把"子树大小"错写成了"根节点编号"。这会让 `size` 统计失真、按秩合并失效（功能仍对，只是退化成普通合并）。**正确写法见上面模板的 `size[rootQ] += size[rootP]`。**

### 两个优化为什么重要

| 优化 | 做法 | 效果 |
| --- | --- | --- |
| **路径压缩** | `find` 时把节点直接挂到更上层 | 树高度趋近于 1，`find` 近 `O(1)` |
| **按秩合并** | 总是把小树挂到大树下 | 避免树退化成链 |

两者结合后，`m` 次操作的总复杂度是 `O(m·α(n))`，`α` 是反阿克曼函数，实际中 `α(n) < 5`，可视为常数。

## 三、省份数量（547 题）：并查集最直接的应用

**题目**：`isConnected[i][j]=1` 表示城市 `i`、`j` 直接相连，求省份（连通块）个数。

```java
public int findCircleNum(int[][] isConnected) {
    int n = isConnected.length;
    UnionFind uf = new UnionFind(n);
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            if (isConnected[i][j] == 1) uf.union(i, j);
    return uf.count();      // 连通分量个数即省份数
}
```

> 参考实现：[src/UnionFind/CircleNum.java](../../src/UnionFind/CircleNum.java)

*省份数量是【并查集数连通块】，关键突破点是【对每对相连城市 union，最后返回 count】，边界是【只需遍历上三角 `j>i`，矩阵对称】。*

## 四、冗余连接（684 题）：并查集判环

**题目**：一棵树加了一条多余的边形成了环，找出这条多余的边（返回最后出现的那条）。

**思路**：依次加边，若某条边的两个端点**在加之前就已经连通**，那它就是导致成环的多余边。

```java
public int[] findRedundantConnection(int[][] edges) {
    int n = edges.length;
    UnionFind uf = new UnionFind(n + 1);     // 节点从 1 编号
    for (int[] e : edges) {
        if (uf.connected(e[0], e[1])) return e;   // 加之前已连通 → 这条边多余
        uf.union(e[0], e[1]);
    }
    return new int[0];
}
```

> 参考实现：[src/UnionFind/FindRedundantConnection.java](../../src/UnionFind/FindRedundantConnection.java)、[src/graph/RedundantConnectionUF.java](../../src/graph/RedundantConnectionUF.java)（并查集版）、[src/graph/RedundantConnection.java](../../src/graph/RedundantConnection.java)（DFS 版）

**并查集判环的本质**：对无向图，`union(u,v)` 前若 `find(u)==find(v)`，说明 `u`、`v` 之间已有路径，再连 `u-v` 必成环。这是并查集的招牌用途。

*冗余连接是【并查集增量判环】，关键突破点是【加边前若两端已连通，这条边就是答案】，边界是【节点从 1 编号，数组开 n+1】。*

## 五、账户合并（721 题）：并查集 + 映射

**题目**：合并属于同一人的账户（通过共享邮箱判断）。这是并查集的"**高级应用**"——把邮箱映射成下标，用并查集合并同人的邮箱。

**三步走**：
1. 给每个邮箱分配一个编号，并记录"邮箱 → 所属账户名"
2. 对**同一账户下的邮箱**两两 `union`（它们属于同一人）
3. 按根节点分组，收集每组的邮箱、排序、拼上名字输出

> 参考实现：[src/UnionFind/MergeAccount.java](../../src/UnionFind/MergeAccount.java)、[src/UnionFind/MergeAccount2.java](../../src/UnionFind/MergeAccount2.java)

**并查集 + 哈希映射** 是处理"元素不是整数下标"（如邮箱、字符串）的通用套路：先用哈希把元素映射成 `0..n-1` 的整数，再用标准并查集。

## 六、最长连续序列（128 题）：并查集的巧用

**题目**：无序数组中最长连续数字序列的长度，要求 `O(n)`。

**并查集解法**：把值 `x` 和 `x+1` 合并（如果 `x+1` 存在），最后找最大的连通块大小。

```java
// 核心：用 Map<值, 并查集下标>，对每个 x 若存在 x+1 就 union
for (int x : nums) {
    if (map.containsKey(x + 1)) uf.union(map.get(x), map.get(x + 1));
}
// 答案 = 最大连通块的 size
```

> 参考实现：[src/UnionFind/LongestConsecutive.java](../../src/UnionFind/LongestConsecutive.java)

> **更优雅的哈希解法**：也可以不用并查集——把所有数放进 `HashSet`，只从"没有前驱 `x-1`"的数开始向后数连续长度，同样 `O(n)`。两种思路都值得掌握。
