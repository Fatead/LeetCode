# 01 图的表示与遍历

> **一句话理解**：图的遍历 = 树的遍历 + `visited` 数组。岛屿类问题是图遍历最高频的考法——**把二维网格看成一张图，相邻的 1 之间有边**。

---

## 一、岛屿数量（200 题）：图遍历的入门王牌

**题目**：`'1'` 是陆地，`'0'` 是水，上下左右相连的陆地算一个岛，求岛屿总数。

### 1.1 DFS 版（最常用）

**核心思想**：遍历网格，每遇到一个未访问的 `'1'`，岛屿数 +1，并用 DFS 把这座岛的所有陆地"淹没"（标记为已访问）。

```java
public int numIslands(char[][] grid) {
    int count = 0;
    for (int i = 0; i < grid.length; i++)
        for (int j = 0; j < grid[0].length; j++)
            if (grid[i][j] == '1') {
                count++;              // 发现新岛
                dfs(grid, i, j);      // 淹没整座岛
            }
    return count;
}
private void dfs(char[][] grid, int i, int j) {
    // 越界 或 遇到水 → 停止
    if (i < 0 || i >= grid.length || j < 0 || j >= grid[0].length || grid[i][j] != '1') return;
    grid[i][j] = '0';                 // 淹没当前格（相当于标记 visited）
    dfs(grid, i - 1, j);              // 上
    dfs(grid, i + 1, j);              // 下
    dfs(grid, i, j - 1);              // 左
    dfs(grid, i, j + 1);              // 右
}
```

**为什么把 `'1'` 改成 `'0'` 就是标记访问？** 因为改成 `'0'` 后，这个格子再也不会被当成陆地触发新 DFS，等价于一个 `visited` 数组，还省了额外空间。

### 1.2 并查集版

把每个陆地格子编号为 `i*col+j`，对相邻的陆地做 `union`，最后统计不同的根的个数。

```java
// 核心逻辑：对每个 '1'，和它右边、下边的 '1' 做 union
for (int i = 0; i < row; i++)
    for (int j = 0; j < col; j++)
        if (grid[i][j] == '1') {
            if (i + 1 < row && grid[i + 1][j] == '1') uf.union(node(i, j), node(i + 1, j));
            if (j + 1 < col && grid[i][j + 1] == '1') uf.union(node(i, j), node(i, j + 1));
        }
// 答案 = 所有 '1' 格子的根节点去重后的个数
```

> 参考实现：[src/UnionFind/NumIslands.java](../../src/UnionFind/NumIslands.java)（仓库是并查集版，用 `HashSet` 收集所有陆地的根来计数）

**DFS 还是并查集？** 岛屿数量两者都行，DFS 更简洁；但如果题目要求"**动态加陆地、随时查岛数**"（如 305 题岛屿数量 II），就只能用并查集。

*岛屿数量是【网格 DFS / 并查集】，关键突破点是【遇到未访问的 1 就 count++ 并淹没整岛】，边界是【DFS 第一行就判越界和是否为陆地】。*

## 二、岛屿系列：换汤不换药

网格 DFS 模板不变，只改"淹没时做什么"：

| 题号 | 题目 | 怎么改 |
| --- | --- | --- |
| 695 | 岛屿的最大面积 | DFS 返回本次淹没的格子数，取最大 |
| 1254 | 统计封闭岛屿 | 先淹掉与边界相连的岛，剩下的才是封闭岛 |
| 130 | 被围绕的区域 | 从边界的 `'O'` 出发标记"不被围"，剩下的 `'O'` 翻成 `'X'` |
| 994 | 腐烂的橘子 | **多源 BFS**（下一节讲），所有烂橘子同时扩散 |
| 417 | 太平洋大西洋水流 | 从两个大洋边界分别 DFS，取交集 |

> 参考实现：被围绕的区域 [src/UnionFind/Solve.java](../../src/UnionFind/Solve.java)、腐烂的橘子 [src/BFS/OrangesRotting.java](../../src/BFS/OrangesRotting.java)

**被围绕的区域（130 题）的巧思**：直接找"被围的 O"很难，**反过来**——先从**边界上的 O** 出发 DFS，凡能连到边界的 O 都标记为安全；遍历结束后，剩下没被标记的 O 就是被围的，翻成 X。这种"正难则反"的思路在网格题里很常见。

## 三、多源 BFS：腐烂的橘子（994 题）

**题目**：每分钟，烂橘子（2）会让上下左右相邻的新鲜橘子（1）也腐烂，求所有橘子腐烂所需分钟数。

**关键是"多源"**：一开始**所有**烂橘子同时入队，一起向外扩散。这和单源 BFS 的唯一区别是初始队列里有多个起点。

```java
public int orangesRotting(int[][] grid) {
    Queue<int[]> queue = new LinkedList<>();
    int fresh = 0;
    for (int i = 0; i < grid.length; i++)
        for (int j = 0; j < grid[0].length; j++) {
            if (grid[i][j] == 2) queue.offer(new int[]{i, j});  // 所有烂橘子入队
            else if (grid[i][j] == 1) fresh++;                  // 统计新鲜橘子
        }
    int minutes = 0;
    int[][] dirs = {{-1,0},{1,0},{0,-1},{0,1}};
    while (!queue.isEmpty() && fresh > 0) {
        minutes++;
        int size = queue.size();                   // ★ 一层 = 一分钟
        for (int k = 0; k < size; k++) {
            int[] cur = queue.poll();
            for (int[] d : dirs) {
                int ni = cur[0] + d[0], nj = cur[1] + d[1];
                if (ni >= 0 && ni < grid.length && nj >= 0 && nj < grid[0].length
                        && grid[ni][nj] == 1) {
                    grid[ni][nj] = 2;              // 腐烂它
                    fresh--;
                    queue.offer(new int[]{ni, nj});
                }
            }
        }
    }
    return fresh == 0 ? minutes : -1;              // 还有新鲜橘子说明腐烂不完
}
```

> 参考实现：[src/BFS/OrangesRotting.java](../../src/BFS/OrangesRotting.java)

**BFS 用 `size` 分层对应"时间推进"**——和树的层序遍历（见 [10 树](../10-树/01-树的遍历与递归思维.md)）是同一个套路。这是 BFS 求"最少步数/最短时间"的通用结构。

*腐烂的橘子是【多源 BFS】，关键突破点是【所有烂橘子同时入队、按层扩散、层数即分钟数】，边界是【最后还有新鲜橘子返回 -1】。*

## 四、克隆图（133 题）

**题目**：深拷贝一张无向图。难点在于**图有环**，拷贝时要避免无限递归，并保证"同一个原节点只建一个克隆"。

**用哈希表 `原节点 → 克隆节点` 做记忆**：

```java
Map<Node, Node> visited = new HashMap<>();
public Node cloneGraph(Node node) {
    if (node == null) return null;
    if (visited.containsKey(node)) return visited.get(node);  // 已克隆过，直接返回
    Node clone = new Node(node.val);
    visited.put(node, clone);                 // ★ 先登记，再递归邻居（防环）
    for (Node neighbor : node.neighbors)
        clone.neighbors.add(cloneGraph(neighbor));
    return clone;
}
```

**最关键的一步**：`visited.put` 必须在递归邻居**之前**。否则遇到环时会反复进入同一节点、无限递归。

> 参考实现：[src/graph/CloneGraph.java](../../src/graph/CloneGraph.java)

*克隆图是【DFS + 哈希记忆】，关键突破点是【用"原→克隆"的 map 防止环导致的重复克隆，建节点后立即登记再递归】，边界是【空图返回 null】。*

## 五、BFS 在"状态图"上的应用

有些题的"图"不是显式给出的，而是**状态构成的隐式图**，照样用 BFS 求最短步数：

- **打开转盘锁（752 题）**：每个 4 位密码是一个节点，拨动一位能到相邻节点，求到 target 的最少步数。见 [src/BFS/OpenLock.java](../../src/BFS/OpenLock.java)。
- **机器人运动范围（剑指 13）**：从 `(0,0)` BFS 能到达的格子数。见 [src/BFS/MovingCount.java](../../src/BFS/MovingCount.java)。
- **钥匙和房间（841 题）**：从 0 号房间 DFS/BFS 能否访问所有房间。见 [src/BFS/VisitRooms.java](../../src/BFS/VisitRooms.java)。
- **所有可能的路径（797 题）**：DAG 上从 0 到 n-1 的所有路径（DFS 回溯）。见 [src/graph/AllPathSourceTarget.java](../../src/graph/AllPathSourceTarget.java)。

**识别"隐式图"的信号**：题目问"最少操作/最少步数把 A 变成 B"，且每一步只能做有限种变换——这就是在状态图上跑 BFS。
