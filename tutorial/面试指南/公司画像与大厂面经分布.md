# 公司画像与大厂面经分布

> **说明**：本文档基于**公开面经、招聘 JD、技术博客的统计规律**整理，用于**定向准备**，不构成任何保证。
> 同一公司不同 BG/团队差异极大，面试官个体差异更大——**把它当"概率分布"，不是"题库"**。
>
> 用法：确定 2~3 家目标公司 → 看画像 → 按"高频考点分布"分配复习时间 → 用"典型题组"自测。

## 零、先搞清楚：你在面哪一类公司

### 0.1 六类公司，六套打法

| 类型 | 代表 | 考察重心 | 准备重点 |
| --- | --- | --- | --- |
| **一线大厂** | 字节、阿里、腾讯、美团 | 基础 + 算法 + 项目深度 + 系统设计 | 全面，不能有明显短板 |
| **增长型中厂** | 快手、小红书、拼多多、滴滴 | 基础 + 项目 + 落地能力 | 项目要能讲深 |
| **传统互联网/电商** | 京东、携程、唯品会 | 工程能力 + 稳定性 | 高并发、数据一致性 |
| **硬件/通信/制造** | 华为、OPPO、vivo | 基础 + 项目 + 抗压 | 基础扎实、能扛 |
| **金融/国企/银行** | 招行、工行、券商、运营商 | 稳定 + 合规 + 安全 + 学历 | 安全、合规、稳定性 |
| **外企/远程** | 微软、亚马逊、Shopify | 算法 + 系统设计 + 行为面 + 英语 | 英文表达 + LP/行为面 |

### 0.2 一个判断技巧

看 JD 的动词：

```
"负责高并发系统的设计与优化" → 重架构与性能
"参与业务需求开发"           → 重业务与工程
"保障系统稳定性"             → 重 SRE/可观测
"研究并落地新技术"           → 重学习与判断
```

## 一、级别体系对照

> **重要**：各公司职级体系不同，title 通胀严重。**面试定级看的是"能力 + 上一份工作的职责"，不是工作年限。**

### 1.1 大致对应（公开信息，仅供参考）

| 经验 | 阿里 | 字节 | 腾讯 | 美团 | 外企 |
| --- | --- | --- | --- | --- | --- |
| 1~3 年 | P5 | 2-1 | T9 | P2-2 | L4 |
| 3~5 年 | P6 | 2-2 | T10 | P3-1 | L5 |
| 5~8 年 | P7 | 3-1 | T11 | P3-2 | L6 |
| 8 年+ | P8 | 3-2 | T12 | P4-1 | L7 |

**注意**：

- 同一级别在不同公司含金量不同，**跳槽时更看"职责范围"而不是 title**。
- 面试表现好可能"高配一级"，表现一般可能"降级录用"——**级别是谈出来的，也是面出来的**。

### 1.2 定级看什么

| 维度 | P6 / 2-2 / L5 | P7 / 3-1 / L6 |
| --- | --- | --- |
| 范围 | 独立负责一个模块/系统 | 负责一个域/多个系统 |
| 影响 | 团队内 | 跨团队 |
| 技术 | 能解决问题 | 能定义问题、做取舍 |
| 带人 | 带 1~2 人 | 带 3~5 人或技术负责人 |
| 业务 | 理解需求 | 能推动业务目标 |

## 二、典型面试流程

### 2.1 大厂通用流程

```
简历筛选 → 笔试/测评（部分）→ 技术一面 → 技术二面 → 技术三面/交叉面 → HR 面 → offer
```

| 轮次 | 时长 | 重点 |
| --- | --- | --- |
| 一面 | 45~60 min | 基础 + 一道算法 + 项目 |
| 二面 | 60~90 min | 项目深挖 + 场景设计 |
| 三面 | 45~60 min | 架构/视野/跨团队 |
| HR 面 | 30 min | 稳定性、动机、薪资 |

**各公司差异**：

| 公司 | 典型轮次 | 特点 |
| --- | --- | --- |
| 字节 | 3 技术 + 1 HR | 效率高，算法占比大，可能加面 |
| 阿里 | 3~4 技术 + HR | 交叉面多，价值观/HR 权重高 |
| 腾讯 | 3 技术 + HR（+GM） | BG 差异大，重基础和项目 |
| 美团 | 3 技术 + HR | 重业务理解和稳定性 |
| 快手 | 3 技术 + HR | 节奏快，基础 + 项目 |
| 小红书 | 3 技术 + HR | 重业务落地与工程能力 |
| 拼多多 | 3 技术 + HR | 强度大，基础扎实 |
| 京东 | 3 技术 + HR | 重工程与稳定性 |
| 百度 | 3 技术 + HR | 重基础与算法 |
| 华为 | 多轮 + 主管面 | 流程长，重抗压 |
| 银行/国企 | 笔试 + 多轮 + 政审 | 重学历、稳定、合规 |
| 外企 | 2~4 轮 + behavior | 重算法、系统设计、英语 |

## 三、公司画像（14 类）

### 3.1 字节跳动

**业务**：抖音、今日头条、飞书、电商、TikTok。

**技术特点**：Go/Java 并存，微服务，K8s，强数据驱动。

**面试风格**：

```
① 算法占比高（通常 1~2 道，中等难度，要求 bug-free）
② 基础问得细（语言、网络、OS、DB）
③ 项目追问深（3 层以上）
④ 效率高，反馈快
```

**高频**：算法、Java/Go 基础、并发、MySQL、Redis、消息队列、项目难点。

**准备建议**：算法每天 2 题保持手感；项目准备"最难的一个点 + 数字"。

### 3.2 阿里巴巴

**业务**：淘宝天猫、阿里云、蚂蚁、菜鸟、本地生活。

**技术特点**：Java 生态最厚，中间件自研（Dubbo、RocketMQ、Sentinel、Nacos、Seata），云原生。

**面试风格**：

```
① 项目与架构并重（会问"为什么这么设计"）
② 技术视野（有没有看过源码、了解业界方案）
③ 价值观面试（客户第一、拥抱变化等）
④ 交叉面多，HR 权重高
```

**高频**：Java 源码、JVM、并发、分布式事务、中间件原理、稳定性、领域建模。

**准备建议**：把"中间件原理"和"分布式一致性"打穿；准备"技术选型"的故事。

### 3.3 腾讯

**业务**：微信、游戏、广告、云、金融科技。

**技术特点**：C++/Go/Java 都有，海量服务，网络与存储要求高。

**面试风格**：

```
① 基础非常细（网络、OS、语言底层）
② 项目看深度
③ BG 差异极大（WXG 更严，CSIG/IEG 各有偏好）
④ 可能有 GM 面
```

**高频**：TCP/IP、epoll、内存管理、并发、分布式、项目。

**准备建议**：网络和 OS 要能讲到底层；准备好"高并发场景"的推演。

### 3.4 美团

**业务**：外卖、到店、酒旅、买菜、配送。

**技术特点**：Java 为主，强业务系统，重视稳定性与数据。

**面试风格**：

```
① 业务理解（能不能讲清业务指标与技术的关系）
② 场景设计（高并发、数据一致性）
③ 稳定性（故障处理、容量）
④ 基础扎实
```

**高频**：MySQL、Redis、MQ、分布式、稳定性、业务建模。

**准备建议**：把"场景设计题"练熟；准备一个"稳定性/故障"的故事。

### 3.5 快手

**业务**：短视频、直播、电商、商业化。

**技术特点**：Java/Go，微服务，推荐与广告系统。

**面试风格**：基础 + 项目 + 算法，节奏快，重落地。

**高频**：Java 并发、JVM、MySQL、Redis、MQ、项目。

### 3.6 小红书

**业务**：社区、电商、商业化。

**技术特点**：Java/Go，云原生，增长快。

**面试风格**：重业务落地 + 工程能力 + 项目深度，算法中等。

**高频**：Java 基础、并发、MySQL、Redis、消息队列、场景设计。

### 3.7 拼多多

**业务**：电商、Temu。

**技术特点**：Java/C++，高并发、强性能。

**面试风格**：基础扎实、算法、项目，强度大、节奏快。

**高频**：并发、JVM、MySQL、Redis、算法、高并发设计。

### 3.8 京东

**业务**：零售、物流、金融。

**技术特点**：Java 为主，强交易与供应链。

**面试风格**：工程能力 + 稳定性 + 项目，偏务实。

**高频**：MySQL、Redis、MQ、分布式事务、稳定性、分库分表。

### 3.9 百度

**业务**：搜索、AI、自动驾驶、云。

**技术特点**：C++/Java/Go，AI 与基础架构。

**面试风格**：基础 + 算法 + 项目，AI 岗位会问模型与工程。

**高频**：算法、OS、网络、分布式、AI 工程。

### 3.10 滴滴

**业务**：出行、国际化、自动驾驶。

**技术特点**：Java/Go，实时调度、地理计算。

**面试风格**：基础 + 场景设计 + 项目。

**高频**：并发、分布式、MySQL、Redis、场景设计（派单/计费）。

### 3.11 华为

**业务**：通信、云、终端、车。

**技术特点**：C/C++/Java/Go，嵌入式与云并存。

**面试风格**：

```
① 流程长（机考 + 多轮技术 + 主管面 + HR）
② 重基础与项目，抗压测试
③ 看学历与稳定性
```

**注意**：区分正编与 OD（外包），问清楚合同主体。

### 3.12 银行 / 国企 / 运营商

**业务**：金融、政务、通信。

**面试风格**：

```
① 笔试（行测/专业）
② 重学历、稳定性、合规
③ 技术深度要求低于大厂，但要求"可靠"
④ 可能政审、体检
```

**高频**：Java 基础、Spring、MySQL、安全合规、分布式事务、系统稳定性。

**准备建议**：强调稳定性、合规意识、长期意愿；准备"为什么选择国企"的答案。

### 3.13 外企 / 远程

**业务**：SaaS、云、工具、跨境电商。

**面试风格**：

```
① 算法（LeetCode Medium，英文题面）
② 系统设计（注重 trade-off 表达）
③ Behavior（STAR，LP/价值观）
④ 英语沟通
```

**高频**：算法、系统设计、行为面、英文表达。

**准备建议**：练英文自我介绍 + 用英文讲项目；熟悉 STAR。

### 3.14 AI 创业公司

**业务**：大模型应用、Agent、AI 搜索、AI 编程。

**面试风格**：

```
① 实战能力强（做过 RAG/Agent 优先）
② 全栈倾向（能自己搭 demo）
③ 节奏快，重结果
④ 可能直接和创始人聊
```

**高频**：RAG、Agent、工程化、成本、效果评估。

**准备建议**：带一个能演示的项目；准备"效果数字"和"踩坑"。

## 五、按公司风格的典型题组

> 以下不是"真题回忆"，而是**按该公司的考察风格组合的练习题组**。

### 5.1 字节风格（算法 + 基础）

```
算法：LRU、二叉树层序、最长无重复子串、合并 K 个链表、岛屿数量
基础：HashMap 扩容、线程池、G1、TCP 三次握手、MVCC
项目：你做过的最有挑战的事 + 3 层追问
```

### 5.2 阿里风格（项目 + 架构 + 中间件）

```
项目：讲一个你主导的系统，画架构图，回答：瓶颈在哪、怎么扩容、挂了怎么办
架构：设计一个订单系统 / 分库分表方案
中间件：RocketMQ 事务消息、Seata AT、Nacos 推送
基础：JVM 调优、并发、分布式事务
```

### 5.3 腾讯风格（基础 + 网络）

```
基础：TCP 拥塞控制、epoll、零拷贝、进程通信
语言：Java 内存模型、GC、类加载
算法：中等难度 1~2 道
项目：深度追问 + 性能优化
```

### 5.4 美团风格（业务 + 场景）

```
场景：设计一个外卖派单/优惠券/订单系统
稳定性：线上故障怎么排查、容量怎么规划
数据：分库分表、缓存一致性、对账
基础：MySQL、Redis、MQ
```

### 5.5 银行/国企风格（稳定 + 安全 + 合规）

```
基础：Java、Spring、MySQL 事务
安全：SQL 注入、越权、加密、审计
合规：数据脱敏、日志留存
行为：为什么来国企、稳定性、长期规划
```

### 5.6 外企风格（算法 + 设计 + 行为）

```
算法：LeetCode Medium（英文题面，边写边说）
设计：Design a rate limiter / URL shortener / chat system
行为：Tell me about a conflict / failure / ambiguity
英语：全程英文或部分英文
```

### 5.7 AI 创业风格（实战）

```
RAG：链路、召回率、评估、成本
Agent：编排、可靠性、工具调用
工程：流式、限流、降级、可观测
项目：带 demo，讲清"从 0 到 1"
```

## 六、定向准备策略

### 6.1 4 周（目标 2~3 家）

| 周 | 重点 | 产出 |
| --- | --- | --- |
| W1 | 基础查漏（Top100 S 级） | 错题清单 |
| W2 | 项目讲稿 + 场景设计 | 3 分钟/8 分钟讲稿 + 5 道设计题 |

| W4 | 模拟面试 + 行为面 | 录音复盘 |

### 6.2 2 周（冲刺）

```
D1~3：Top100 S 级 + 项目讲稿
D4~6：目标公司高频考点（按分布表）
D7~9：场景设计 5 道 + 故障复盘 2 个
D10~12：算法保持手感（每天 2 题）
D13~14：模拟面试 + 行为面 + 反问
```

### 6.3 1 周（临时抱佛脚）

```
只做三件事：
① 项目讲稿（3 分钟版）练到能扛 3 层追问
② Top100 的 S 级 30 题
③ 2 个故障案例 + 3 个反问
```

| 银行/国企 | 基础 40%，行为/合规 30%，项目 30% |
| 外企 | 算法 40%，设计 30%，行为/英语 30% |

## 七、投递节奏与批次

### 7.1 社招的"窗口"

```
① 年初（2~4 月）：HC 释放，机会多
② 年中（6~8 月）：补招，节奏快
③ 年末（10~12 月）：HC 收紧，但竞争也少
④ 避开：大规模裁员后的 1~2 个月（HC 冻结）
```

### 7.2 投递策略

```
① 先投 2 家"练手"（不是最想去的）
② 再投目标公司（状态最好时）
③ 并行推进 3~5 家，避免单点等待
④ 记录每家进度（岗位/轮次/反馈/时间）
```

### 7.3 内推 vs 海投

| 方式 | 优势 | 注意 |
| --- | --- | --- |
| 内推 | 简历必看、进度可查 | 找真内推，别找"内推贩子" |
| 猎头 | 帮你谈薪、匹配 | 确认是否独家、是否收费 |
| 官网海投 | 直接 | 可能石沉大海 |

## 八、怎么判断团队和岗位好不好

### 8.1 反问清单（按角色）

**问技术面试官**：

```
① 团队目前最核心的业务指标是什么？
② 这个岗位入职后 3 个月最重要的目标是什么？
③ 团队现在最大的技术挑战/技术债是什么？
④ 团队的发布流程、故障复盘机制是怎样的？
⑤ 代码 review 和文化是怎样的？
```

**问主管/三面**：

```
① 团队的人员构成和分工？
② 这个岗位的成长路径？
③ 团队未来一年的规划？
④ 您觉得在这个团队做得好的同事有什么特点？
```

**问 HR**：

```
① 团队规模和汇报关系？
② 绩效考核方式和周期？
③ 培训/晋升机制？
```

### 8.2 危险信号

| 信号 | 可能的含义 |
| --- | --- |
| 岗位描述模糊、频繁改 | 需求不清、可能被裁 |
| 面试官全程不问技术 | 可能只是走流程/凑 HC |
| 团队大量离职 | 管理或业务问题 |
| "先来再说，具体做什么再定" | 可能被塞到边缘业务 |
| 只谈加班和奋斗 | 文化可能有问题 |
| offer 催得很急、不让考虑 | 可能 HC 不稳 |

### 8.3 信息渠道

```
① 脉脉/知乎/小红书（看风评，注意甄别）
② 前员工/在职朋友（最真实）
③ 技术博客/开源项目（看技术氛围）
④ 招聘 JD 的历史变化（看业务是否稳定）
```

## 九、避坑清单

| 坑 | 怎么识别 | 怎么处理 |
| --- | --- | --- |
| **外包/驻场** | 合同主体不是目标公司；工牌/邮箱不同 | 问清合同主体、社保缴纳方 |
| **假 HC** | 面试流程拖很久、一直不安排下一轮 | 同步推进其他机会 |
| **offer 撤回** | 只给口头 offer | 要书面 offer（邮件/系统） |
| **降级录用** | 面试后说"只能给低一级" | 评估是否接受，或谈其他补偿 |
| **竞业协议** | 入职时签宽泛竞业 | 看清范围、期限、补偿 |
| **试用期陷阱** | 试用期超长、薪资打折 | 合同写清 |
| **虚假 title** | "高级工程师"但做 CRUD | 问清职责和汇报关系 |

## 写在最后

公司画像的价值不是"押题"，而是**让你把有限的时间花在对的地方**：

1. **算法占比高的公司**，考前必须保持手感。
2. **项目占比高的公司**，把讲稿练到能扛 5 层追问。
3. **稳定性/合规占比高的公司**，准备故障复盘和安全合规。
4. **外企**，提前练英文表达和行为面。

**最后提醒**：所有面经都是"别人遇到的"，不是"你一定会遇到的"。**能力是 1，面经是 0**——没有能力，再多面经也没用。
