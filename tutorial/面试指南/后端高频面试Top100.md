## S 级：必考 30 题（1~30）

### 1. HashMap 的底层结构与扩容

**一句话**：数组 + 链表 + 红黑树；容量 2 的幂，负载因子 0.75，扩容翻倍并拆分链表。

**展开**：

- JDK7 头插（并发扩容成环），JDK8 尾插 + 红黑树。
- 定位：`(n-1) & hash`；hash 做了 `h ^ (h>>>16)` 扰动。
- 树化：链表 ≥ 8 且容量 ≥ 64；退化 ≤ 6。
- 扩容：`hash & oldCap` 判断留在原位还是 `i + oldCap`，**不用重算 hash**。

**追问**：

- 为什么容量是 2 的幂？→ 位运算等价取模且分布均匀；`tableSizeFor` 向上取整。
- 为什么阈值 8？→ 泊松分布下概率极低，主要防哈希攻击；6 是抖动缓冲。
- 为什么线程不安全？→ JDK8 不再成环但会丢数据（size++、链表插入无同步）。

**踩坑**：说"JDK8 解决了线程安全"——没有，只是不死循环。

### 2. ConcurrentHashMap 原理

**一句话**：JDK8 用 CAS + synchronized 锁单个桶头结点，多线程协助扩容，计数用 `CounterCell` 分段累加。

**展开**：

- 空桶 → CAS 放入；非空 → 锁头结点。
- `sizeCtl`：0 未初始化、-1 初始化中、负数扩容中、正数为阈值。
- 扩容：`ForwardingNode` 标记已迁移，`helpTransfer` 协助，stride 分段。
- 不允许 null key/value（并发下无法区分"不存在"和"值为 null"）。

**追问**：

- `size()` 为什么不准确？→ 分段计数，遍历时还在变；推荐 `mappingCount()`。
- `@Contended` 干什么？→ 防伪共享（缓存行填充）。
- JDK7 和 JDK8 的区别？→ Segment 分段锁 → 桶级锁，粒度更细。

**踩坑**：把 `sizeCtl` 的负数只说成"扩容中"，漏了初始化和线程数。

### 3. 线程池 7 参数与执行流程

**一句话**：核心数 → 队列 → 最大数 → 拒绝；**先入队，队列满才扩线程**。

**展开**：

```java
new ThreadPoolExecutor(core, max, keepAlive, unit, queue, factory, handler)
```

- 流程：core 未满建核心线程 → 入队 → 队列满且未到 max 建非核心 → 拒绝。
- 四种拒绝：Abort（抛异常）、CallerRuns（调用线程执行）、Discard、DiscardOldest。
- 状态：RUNNING/SHUTDOWN/STOP/TIDYING/TERMINATED，`ctl` 高 3 位 + 低 29 位。

**追问**：

- 为什么不用 Executors？→ 无界队列或无界线程数，OOM。
- `submit` 和 `execute` 区别？→ submit 返回 Future，异常被吞。
- 怎么优雅关闭？→ `shutdown()` + `awaitTermination` + `shutdownNow()`。

**踩坑**：说"先扩到 max 再入队"——反了。

### 4. 线程池参数怎么配

**一句话**：公式只是起点，实际按 **Little's Law + 压测 + 隔离** 定。

**展开**：

- CPU 密集 `N+1`；IO 密集 `N × (1 + 等待/计算)`，经验 2N~4N。
- 并发数 = QPS × RT；队列长度要对应可接受的排队延迟。
- 必须**有界队列** + **自定义线程名** + **明确拒绝策略**。
- 按依赖/重要性**隔离**多个池。

**追问**：

- 队列长度怎么定？→ 队列长度 / QPS = 排队时间，按可接受延迟反推。
- 监控什么？→ 活跃线程、队列长度、拒绝次数、任务 RT。
- 什么时候该扩容而不是加线程？→ 下游变慢时，加线程只会更糟。

**踩坑**：只背"N+1/2N"，说不出压测和隔离。

### 5. synchronized 与锁升级

**一句话**：对象头 Mark Word + monitor；无锁 → 偏向 → 轻量级（自旋）→ 重量级。

**展开**：

- 同步块：`monitorenter/monitorexit`；同步方法：`ACC_SYNCHRONIZED`。
- 偏向锁：记录线程 ID；轻量级：CAS + 栈中 Lock Record；重量级：OS 互斥量。
- JDK15（JEP 374）起偏向锁默认关闭并废弃。

**追问**：

- 和 ReentrantLock 的区别？→ 可中断、超时、公平、多条件；synchronized 自动释放。
- 锁能降级吗？→ 不能（HotSpot 不支持）。
- 为什么偏向锁被废弃？→ 撤销成本高、收益下降。

**踩坑**：说"JDK18 移除"要谨慎，说"新版本已移除"更稳。

### 6. volatile 的语义

**一句话**：保证**可见性**和**有序性**，**不保证原子性**。

**展开**：

- 写立即刷主存 + 内存屏障（StoreStore/StoreLoad），读直接从主存。
- 禁止重排：DCL 单例的 `instance` 必须 volatile。
- `i++` 不安全 → `AtomicInteger` / 锁。

**追问**：

- 内存屏障有几种？→ LoadLoad/LoadStore/StoreStore/StoreLoad。
- volatile 能替代锁吗？→ 不能，只适合状态标志、单次读写。

**踩坑**：说"volatile 保证原子性"。

### 7. AQS 原理

**一句话**：`volatile int state` + CLH 双向队列 + CAS；独占/共享两种模式。

**展开**：

- `lock()` → `tryAcquire` CAS 改 state，失败入队 park；`unlock()` → `tryRelease` + unpark 后继。
- `state` 语义：ReentrantLock 重入次数、Semaphore 许可数、CountDownLatch 计数。
- 公平：`hasQueuedPredecessors()`；非公平：直接抢。

**追问**：

- 为什么用双向队列？→ 尾部入队、头部唤醒、取消节点要能 prev 回溯。
- PROPAGATE 干什么？→ 共享模式下保证唤醒传播不丢失。
- Condition 怎么实现？→ 条件队列 + 同步队列转移。

**踩坑**：把 AQS 说成"一个锁"，它只是框架。

### 8. ThreadLocal 与内存泄漏

**一句话**：Thread 持有 `ThreadLocalMap`，key 是弱引用、value 是强引用；线程池复用导致 value 不回收。

**展开**：

- 泄漏链路：key 被 GC → Entry key=null，value 仍被 Entry 引用 → 线程活着就不回收。
- 正确用法：`try/finally` 里 `remove()`。
- `get/set` 会顺带清理部分 key=null 的 Entry，但不保证。

**追问**：

- 为什么 key 用弱引用？→ 让 ThreadLocal 对象本身可回收。
- InheritableThreadLocal 的坑？→ 线程池复用失效，要用 TTL。
- 虚拟线程下？→ 每个虚拟线程一份 map，数量爆炸；考虑 ScopedValue。

**踩坑**：只说"会泄漏"，说不出"为什么弱引用还会泄漏"。

### 9. JVM 内存结构

**一句话**：线程私有（PC、虚拟机栈、本地方法栈）+ 线程共享（堆、方法区/元空间）+ 直接内存。

**展开**：

- 堆：新生代（Eden 8 : S0 1 : S1 1）+ 老年代。
- 方法区：JDK8 元空间（本地内存），存类元信息、常量、静态变量。
- 栈帧：局部变量表、操作数栈、动态链接、返回地址。
- 常见异常：`StackOverflowError`、`OOM: Java heap space / Metaspace / Direct buffer memory`。

**追问**：

- 为什么用元空间替代永久代？→ 避免 PermGen OOM、字符串常量池移到堆。
- 指针压缩为什么限制 32GB？→ 4B 引用 × 8 倍对齐。
- 对象一定在堆上吗？→ 逃逸分析后可栈上分配/标量替换。

**踩坑**：把方法区说成"堆的一部分"。

### 10. GC 分代与收集器

**一句话**：分代假设（朝生夕死）→ 新生代复制、老年代标记整理/清除；收集器按停顿目标选。

**展开**：

- 判断存活：可达性分析（GC Roots：栈引用、静态属性、常量、JNI、活跃线程、锁对象）。
- 回收算法：复制（无碎片、浪费空间）、标记清除（碎片）、标记整理（移动成本）。
- 收集器：Serial、Parallel（吞吐）、CMS（低延迟、碎片）、G1（Region、可预测停顿）、ZGC（亚毫秒）。

**追问**：

- CMS 四阶段哪些 STW？→ 初始标记、重新标记。
- G1 为什么能预测停顿？→ Region + RSet + 按回收价值排序（Garbage First）。
- 什么时候用 ZGC？→ 大堆 + 极低停顿要求，代价是吞吐。

**踩坑**：说"CMS 没有 STW"。

### 11. 类加载与双亲委派

**一句话**：加载-验证-准备-解析-初始化；先委派父加载器，避免重复加载与核心类被篡改。

**展开**：

- 准备阶段赋零值，`<clinit>` 在初始化阶段执行。
- 打破场景：SPI（线程上下文类加载器）、Tomcat（WebApp 隔离）、OSGi/热部署。
- 初始化触发：new、静态字段/方法、反射、子类初始化先父类、主类。

**追问**：

- 为什么需要双亲委派？→ 安全（`java.lang.String` 不被替换）+ 避免重复加载。
- Tomcat 为什么打破？→ 不同应用依赖不同版本，需要隔离。

**踩坑**：把"加载"和"初始化"混为一谈。

### 12. 线上 CPU 100% 怎么排查

**一句话**：`top -Hp` 找线程 → 转 16 进制 → `jstack` 定位栈 → 判断是业务死循环、GC 还是锁自旋。

**展开**：

```bash
top -Hp <pid>
printf "%x\n" <tid>
jstack <pid> | grep -A 30 <hex>
# 或 arthas: thread -n 3
```

- 若 GC 线程占满 → 查 `jstat -gcutil`、内存泄漏。
- 若业务线程 → 看是否死循环/正则回溯/序列化。

**追问**：

- 没有 jstack 权限怎么办？→ `arthas`、`jcmd Thread.print`、`kill -3`。
- 怎么确认是 GC 导致？→ 线程名 `GC task thread`、`jstat` 的 FGC 次数。

**踩坑**：只说"看日志"，说不出完整命令链。

### 13. OOM / 内存泄漏排查

**一句话**：先看是哪种 OOM，再用 `jstat` 看趋势、`jmap` 抓堆、MAT 找支配对象。

**展开**：

- 类型：heap space、Metaspace、Direct buffer、unable to create native thread、GC overhead limit。
- 流程：监控告警 → `jstat` 确认老年代上涨 → `jmap -histo:live` → `jmap -dump` → MAT 支配树/引用链。
- 生产必须加 `-XX:+HeapDumpOnOutOfMemoryError`。

**追问**：

- 堆 dump 会 STW 吗？→ 会，大堆要谨慎（可用 `-dump:live` 更准但更慢）。
- 常见根因？→ 缓存无界、ThreadLocal、监听器未注销、连接未关闭、类加载器泄漏。

**踩坑**：直接说"重启解决"，没有根因分析。

### 14. MySQL 索引为什么用 B+ 树

**一句话**：非叶子只存键 → 扇出大 → 树矮 → IO 少；叶子链表 → 范围查询快。

**展开**：

- 16KB 页，三层约存 2000 万行（1170 × 1170 × 16）。
- 对比 B 树：非叶子存数据，扇出小、层高更大。
- 对比 LSM：写放大 vs 读放大，读多写少选 B+ 树。
- 对比哈希：不支持范围查询。

**追问**：

- 为什么不用红黑树？→ 树太高，每层一次磁盘 IO。
- 聚簇索引和二级索引？→ 叶子存整行 vs 存主键（回表）。
- 为什么推荐自增主键？→ 顺序插入，减少页分裂。

**踩坑**：只会背"B+ 树查询快"，算不出扇出。

### 15. 索引失效场景

**一句话**：破坏有序性、无法定位 B+ 树路径的写法都会失效。

**展开**（至少说 6 条）：

1. 左模糊 `LIKE '%x'`
2. 列上函数/运算（`YEAR(col)`、`col+1`）
3. 隐式类型转换（varchar 列传数字）
4. 不满足最左前缀
5. `OR` 连接非索引列
6. 范围查询后的列失效（部分）
7. `!=` / `NOT IN`（低区分度时）
8. 联合索引中间列缺失

**追问**：

- 怎么验证？→ `EXPLAIN` 看 `type`、`key`、`rows`、`Extra`。
- 有函数怎么办？→ MySQL 8 函数索引，或改写 SQL。
- 索引一定好吗？→ 区分度低时全表扫更快（优化器会选）。

**踩坑**：说"加了索引就一定走"。

### 16. 事务隔离级别与 MVCC

**一句话**：RR 默认；MVCC 用版本链 + ReadView 实现快照读，当前读靠锁。

**展开**：

| 级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| RU | 会 | 会 | 会 |
| RC | 不会 | 会 | 会 |
| RR | 不会 | 不会 | 部分（快照读防、当前读靠间隙锁） |
| Serializable | 不会 | 不会 | 不会 |

- ReadView：`m_ids`、`min_trx_id`、`max_trx_id`、`creator_trx_id`。
- RC 每次 SELECT 新建，RR 首次 SELECT 建后复用。
- 快照读 vs 当前读（`for update`、`update`、`delete`）。

**追问**：

- RR 真的没有幻读吗？→ 快照读+当前读混用仍可能。
- 可见性判断四句话？→ 自己可见、早于最小活跃可见、晚于最大不可见、活跃列表内不可见。

**踩坑**：把 MVCC 说成"多版本并发控制就是加锁"。

### 17. redo / undo / binlog

**一句话**：redo 管崩溃恢复（物理、InnoDB），undo 管回滚与 MVCC（逻辑），binlog 管复制与恢复（Server 层）。

**展开**：

| 日志 | 层级 | 类型 | 作用 | 写 |
| --- | --- | --- | --- | --- |
| redo | InnoDB | 物理 | 持久性、crash-safe | 循环写 |
| undo | InnoDB | 逻辑 | 回滚 + MVCC | 随机 |
| binlog | Server | 逻辑 | 主从 + 恢复 | 追加 |

- 两阶段提交：redo prepare → binlog → redo commit。
- 双 1 配置：`innodb_flush_log_at_trx_commit=1` + `sync_binlog=1`。

**追问**：

- 为什么需要两阶段？→ 保证 redo 与 binlog 一致，崩溃恢复不丢不重。
- 组提交解决什么？→ 合并 fsync，降低高并发下的提交成本。

**踩坑**：说 binlog 是 InnoDB 的。

### 18. 慢 SQL 优化

**一句话**：慢日志找 SQL → `EXPLAIN` 看执行计划 → 加/改索引或改写 → 复测。

**展开**：

- `type` 至少到 `range`；`Extra` 避免 `Using filesort`/`Using temporary`。
- 覆盖索引减少回表；联合索引注意最左前缀。
- 深分页：延迟关联、游标分页、限制页数。
- `EXPLAIN ANALYZE`（8.0.18+）看真实行数。

**追问**：

- 为什么加了索引还是慢？→ 回表太多/区分度低/统计信息过期。
- 大表加索引？→ Online DDL（INPLACE）/ gh-ost。
- 怎么防劣化？→ 慢 SQL 周报 + 上线前 EXPLAIN。

**踩坑**：只说"加索引"，不看执行计划。

### 19. 分库分表

**一句话**：分片键决定一切；先索引/归档/分区，最后才分片。

**展开**：

- 垂直/水平；分片键要覆盖 80% 查询、分布均匀。
- 问题：跨片 join、跨片分页、分布式事务、全局 ID。
- 扩容：预分片 > 一致性哈希 > 取模。
- 中间件：ShardingSphere（解析→路由→改写→执行→归并）。

**追问**：

- 跨片分页为什么慢？→ 每片取 offset+size 再归并。
- 非分片键查询怎么办？→ 异构索引表 / ES。

**踩坑**：说"5000 万就要分表"——判断依据是容量与查询，不是行数。

### 20. Redis 为什么快

**一句话**：内存 + 单线程无锁 + epoll + 高效数据结构；6.0 网络 IO 多线程。

**展开**：

- 单线程避免锁与上下文切换，但 **O(N) 命令会阻塞所有人**。
- 数据结构：SDS、listpack、quicklist、跳表、渐进式 rehash。
- 瓶颈通常在网络 RTT 与 syscall → pipeline/Lua。

**追问**：

- 什么时候不快？→ 大 value、O(N) 命令、fork、持久化、swap。
- 为什么单线程还快？→ 瓶颈不在 CPU；锁开销大于并行收益。

**踩坑**：说"Redis 6.0 变成多线程了"——命令执行仍单线程。

### 21. Redis 持久化

**一句话**：RDB 快照（快、可能丢）、AOF 日志（安全、慢）、混合持久化（兼顾）。

**展开**：

- RDB：fork + COW，恢复快，文件小。
- AOF：`always/everysec/no`；重写用子进程 + 重写缓冲区。
- 混合：AOF 重写时前半段 RDB 格式。
- fork 代价：与堆大小相关，10GB 约几十 ms；COW 可能内存翻倍。

**追问**：

- everysec 真的只丢 1 秒吗？→ 磁盘慢时会阻塞，可能退化。
- 为什么单实例不建议超 16G？→ fork/COW/全量同步代价。

**踩坑**：说"AOF 一定不丢数据"。

### 22. 缓存穿透 / 击穿 / 雪崩

**一句话**：穿透=查不存在；击穿=热点 key 过期；雪崩=大量 key 同时失效或实例挂。

**展开**：

| 问题 | 方案 |
| --- | --- |
| 穿透 | 空值缓存（短 TTL）、布隆过滤器、参数校验 |
| 击穿 | 互斥锁重建、逻辑过期、热点永不过期 |
| 雪崩 | TTL 加随机、多级缓存、熔断降级、集群高可用 |

**追问**：

- 布隆过滤器的误判方向？→ "不存在"一定准，"存在"可能误判。
- 互斥锁重建怎么防死锁？→ 锁超时 + finally 释放 + 双重检查。

**踩坑**：三个概念混为一谈。

### 23. 缓存与数据库一致性

**一句话**：先更新 DB 再删缓存；接受最终一致，用延迟双删/Canal 兜底。

**展开**：

- 为什么删而不是改：避免并发覆盖 + 懒加载。
- 为什么先 DB 后删：反过来会把旧值回填。
- 极小窗口：读在更新前、回填在删除后 → 延迟双删。
- 监控：对账 + 抽样校验。

**追问**：

- 延迟双删的延迟怎么估？→ > 读耗时 + 主从延迟，按 P99。
- 能强一致吗？→ 不能（除非不用缓存或加锁串行化）。

**踩坑**：说"先删缓存再更新 DB"是对的。

### 24. 分布式锁

**一句话**：`SET key value NX PX` + Lua 释放 + 看门狗续期；严格场景用 etcd/ZK + fencing token。

**展开**：

- 三个坑：锁过期、误删、主从切换丢锁。
- Redisson：看门狗每 1/3 TTL 续期。
- RedLock 有争议（依赖时钟）；严格互斥用 fencing token。

**追问**：

- 为什么 Lua 释放？→ 保证"判断 + 删除"原子。
- 锁能防重复请求吗？→ 只能防并发，防不了重试 → 要幂等键。

**踩坑**：以为 `SETNX` 就够了。

### 25. Spring Bean 生命周期

**一句话**：实例化 → 属性填充 → Aware → 初始化前后置处理 → 初始化 → 使用 → 销毁。

**展开**：

```
实例化 → 属性注入 → BeanNameAware/BeanFactoryAware
→ BeanPostProcessor.before → @PostConstruct → afterPropertiesSet → init-method
→ BeanPostProcessor.after（AOP 代理）
→ 使用 → @PreDestroy → destroy
```

**追问**：

- AOP 代理在哪一步？→ `postProcessAfterInitialization`。
- 单例 Bean 线程安全吗？→ 不安全（有状态时）。
- 循环依赖在哪一步暴露？→ 实例化后、属性填充前（三级缓存）。

**踩坑**：把初始化顺序说反。

### 26. Spring 循环依赖

**一句话**：三级缓存；第三级存 `ObjectFactory`，延迟生成代理。

**展开**：

- 一级：完整 Bean；二级：早期引用；三级：ObjectFactory。
- 流程：A 实例化 → 放三级 → 注入 B → B 注入 A 时从三级拿早期引用 → 放二级。
- 为什么需要三级：避免所有 Bean 提前代理，保证最多一个代理对象。

**追问**：

- 构造器注入能解决吗？→ 不能（对象还没创建）。
- prototype 能解决吗？→ 不能。
- `@Async` 为什么冲突？→ 代理时机不同，需 `@Lazy`。

**踩坑**：说"二级缓存就够了"。

### 27. @Transactional 失效场景

**一句话**：没走代理、异常没抛出、传播/回滚配置不对，都会失效。

**展开**（至少 6 条）：

1. 非 public
2. 同类自调用（`this.`）
3. 异常被 catch 吞掉
4. 抛受检异常（默认只回滚 RuntimeException/Error）
5. 类没被 Spring 管理
6. 多线程调用（ThreadLocal 不共享）
7. 引擎不支持事务
8. 传播行为设置为 NOT_SUPPORTED

**追问**：

- 怎么排查？→ 打开事务 DEBUG 日志，看是否创建了事务。
- 自调用怎么解决？→ 注入自身 / `AopContext.currentProxy()` / 拆 Bean。

**踩坑**：只说"要 public"。

### 28. MQ 如何保证不丢、不重、有序

**一句话**：不丢靠三段确认 + 副本；不重靠幂等；有序靠单分区 + 单线程消费。

**展开**：

- 生产：同步发送 + 确认 + 重试。
- 存储：多副本 + `acks=all` + `min.insync.replicas>=2`。
- 消费：手动 ack + 处理成功再提交。
- 重复：至少一次 → 幂等（唯一索引/去重表/状态机）。
- 顺序：按 key 分区 + 单线程消费（牺牲并行度）。

**追问**：

- 为什么"不丢"必然"重复"？→ ack 可能丢，重投。
- 顺序消费卡住怎么办？→ 超时跳过 + 记录，或状态机容错。

**踩坑**：说"MQ 能保证 exactly-once"。

### 29. 幂等设计

**一句话**：唯一约束兜底 + 去重表 + 状态机，三者结合。

**展开**：

| 方案 | 适用 |
| --- | --- |
| 唯一索引 | 插入类 |
| 去重表/Redis setnx | 通用 |
| 状态机 | 订单/支付 |
| 乐观锁版本号 | 更新类 |
| token（一次一用） | 表单提交 |

**追问**：

- 幂等键怎么选？→ 业务唯一（订单号+操作类型）或 request_id。
- 幂等和防重有什么区别？→ 幂等是"重复执行结果一致"，防重是"阻止第二次"。

**踩坑**：只用 Redis 去重，没有 DB 唯一约束兜底。

### 30. 分布式事务方案

**一句话**：能不用就不用；强一致 XA/TCC，最终一致本地消息表/事务消息。

**展开**：

| 方案 | 一致性 | 性能 | 侵入 |
| --- | --- | --- | --- |
| XA/2PC | 强 | 差 | 低 |
| TCC | 强 | 中 | 高 |
| SAGA | 最终 | 好 | 中 |
| 本地消息表 | 最终 | 好 | 中 |
| 事务消息 | 最终 | 好 | 低 |

- TCC 三坑：空回滚、悬挂、幂等。
- 选型：优先最终一致 + 对账。

**追问**：

- 本地消息表怎么做？→ 业务表 + 消息表同事务，定时发 + 重试 + 对账。
- TCC 空回滚怎么解决？→ 事务状态表 + Cancel 时判断是否 Try 过。

**踩坑**：上来就说"用 Seata"，不说业务是否需要强一致。

## A 级：高频 40 题（31~70）

### 31. ArrayList vs LinkedList

**答**：数组 vs 双向链表。ArrayList 随机访问 O(1)、尾部增删摊还 O(1)、扩容 1.5 倍；LinkedList 头尾 O(1)、随机访问 O(n)、每个节点额外指针开销。

**追问**：为什么实际几乎总用 ArrayList？→ 缓存友好、内存紧凑；LinkedList 只在频繁头插且数据量大时有优势。

**踩坑**：说"LinkedList 插入删除一定快"——定位位置仍是 O(n)。

### 32. String 为什么不可变

**答**：`final class` + `private final byte[]`（JDK9+）+ 不暴露修改方法。收益：常量池共享、hashCode 可缓存、线程安全。

**追问**：`new String("a")` 创建几个对象？→ 常量池有则 1 个，没有则 2 个。

**踩坑**：只说"final"，不说收益。

### 33. 深拷贝与浅拷贝

**答**：浅拷贝共享引用；深拷贝递归复制。实现：序列化、手动复制、拷贝构造。

**追问**：为什么 `Object.clone()` 是浅拷贝？→ 只复制字段值（引用地址）。

### 34. 泛型擦除

**答**：编译期检查，运行期擦除为上界（默认 Object），插入强制转换。所以不能 `new T[]`、不能 `instanceof`。

**追问**：怎么在运行时拿到泛型？→ 匿名子类 + `getGenericSuperclass`（如 Jackson 的 TypeReference）。

### 35. CAS 与 ABA

**答**：`Unsafe.compareAndSwap` 底层 `cmpxchg`；ABA 用版本号（`AtomicStampedReference`）；自旋开销用 `LongAdder` 缓解。

**追问**：LongAdder 为什么快？→ Cell 分段累加，减少 CAS 冲突。

### 36. 悲观锁 vs 乐观锁

**答**：悲观锁先加锁（`for update`），乐观锁用版本号/CAS。读多写少用乐观，冲突多用悲观。

**追问**：乐观锁失败怎么处理？→ 重试（有限次）或转悲观。

### 37. 死锁的条件与排查

**答**：互斥、持有等待、不可剥夺、循环等待；`jstack` 会直接给出死锁链。

**追问**：怎么预防？→ 统一加锁顺序、`tryLock` 超时、减少锁粒度。

### 38. 线程状态

**答**：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。

**追问**：BLOCKED 和 WAITING 区别？→ 前者等锁，后者等通知/超时。

### 39. 线程间通信

**答**：`wait/notify`、`Condition`、`BlockingQueue`、`CountDownLatch`、`CompletableFuture`、`Semaphore`。

**追问**：为什么 `wait` 要放在 `while` 里？→ 防虚假唤醒。

### 40. CompletableFuture

**答**：异步编排；`thenApply`（map）/`thenCompose`（flatMap）/`thenCombine`/`exceptionally`/`orTimeout`。

**追问**：默认线程池的坑？→ `commonPool`，IO 任务必须传自定义池。

### 41. 阻塞队列

**答**：ArrayBlockingQueue（有界）、LinkedBlockingQueue（默认无界！）、SynchronousQueue、PriorityBlockingQueue、DelayQueue。

**追问**：四组方法？→ 抛异常/返回特殊值/阻塞/超时。

### 42. CopyOnWriteArrayList

**答**：写时复制，读无锁，写加锁；适合读多写极少（白名单、监听器）。

**追问**：缺点？→ 内存翻倍、只能最终一致。

### 43. JMM 与 happens-before

**答**：规定多线程内存可见性；happens-before 八条（程序次序、监视器、volatile、线程启动/终止、传递等）。

**追问**：为什么需要 JMM？→ 屏蔽 CPU 缓存与重排差异。

### 44. 对象内存布局

**答**：Mark Word（8B）+ Klass Pointer（4B 压缩）+ 实例数据 + 对齐填充。

**追问**：Mark Word 存什么？→ hash、GC 年龄、锁标志、偏向线程 ID。

### 45. G1 vs CMS

**答**：G1 是 Region 化、可预测停顿、标记整理（无碎片）；CMS 是标记清除（有碎片）、并发失败会退化为 Serial Old。

**追问**：G1 一定比 CMS 好吗？→ 小堆/低延迟场景未必，RSet 有开销。

### 46. ZGC

**答**：染色指针 + 读屏障 + 并发转移；停顿与堆大小无关；分代 ZGC（JDK21）提升吞吐。

**追问**：代价？→ 吞吐下降（读屏障），CPU 消耗更高。

### 47. 打破双亲委派

**答**：SPI（线程上下文类加载器）、Tomcat（WebApp 隔离、先自己后父）、OSGi（热部署）。

**追问**：SPI 为什么需要打破？→ 核心类要加载第三方实现（JDBC Driver）。

### 48. 聚簇索引 vs 二级索引

**答**：聚簇叶子存整行（一张表一个），二级索引叶子存主键（需要回表）。

**追问**：为什么二级索引不存行？→ 节省空间 + 避免页分裂时多处更新。

### 49. 覆盖索引与回表

**答**：查询列都在索引里 → 不用回表；`Extra: Using index`。

**追问**：怎么优化回表？→ 覆盖索引、延迟关联、减少 `SELECT *`。

### 50. 联合索引最左前缀

**答**：按 a、b、c 排序；跳过 a 查 b 用不上；范围查询后的列失效。

**追问**：`(a,b,c)` 上 `a=1 and c=3` 能用几列？→ 只用 a。

### 51. 锁类型

**答**：记录锁、间隙锁、临键锁（RR 默认）、插入意向锁、意向锁（表级）。

**追问**：间隙锁什么时候加？→ RR 下当前读，防幻读。

### 52. MySQL 死锁与 MDL

**答**：`SHOW ENGINE INNODB STATUS` 看死锁；MDL 是元数据锁，长事务会导致 DDL 阻塞后续查询。

**追问**：MDL 事故怎么防？→ DDL 前查长事务 + 设 `lock_wait_timeout`。

### 53. 主从复制与延迟

**答**：主库 binlog → 从库 IO 线程 → relay log → SQL 线程重放。延迟来自大事务、单线程重放、从库压力。

**追问**：怎么监控？→ `Seconds_Behind_Master` 不准，用心跳表。

### 54. 大表 DDL

**答**：INSTANT（改元数据）/ INPLACE（不锁写）/ COPY（重建）；大表用 gh-ost/pt-osc。

**追问**：为什么 gh-ost 比 pt-osc 好？→ 不用触发器、可限流、可暂停。

### 55. Redis 数据结构与底层

**答**：String（SDS）、Hash/List/Set（listpack↔hashtable）、ZSet（listpack↔跳表+字典）。

**追问**：跳表为什么不用红黑树？→ 实现简单、范围查询友好、无需旋转。

### 56. Redis 集群

**答**：16384 槽、gossip、主从 + 故障转移；MOVED（永久）vs ASK（临时）。

**追问**：为什么 16384？→ 心跳包携带槽位 bitmap，2KB 可接受。

### 57. 过期删除与内存淘汰

**答**：惰性 + 定期删除；八种淘汰策略（noeviction、allkeys-lru/lfu/random、volatile-*）。

**追问**：LRU 是精确的吗？→ 近似（采样 5 个）。

### 58. 热 key / 大 key

**答**：热 key 用本地缓存/打散/多副本；大 key 拆分、`UNLINK`、`--bigkeys` 巡检。

**追问**：大 key 有什么危害？→ 网络阻塞、删除阻塞、集群倾斜、持久化慢。

### 59. Redis 分布式锁与 Redisson

**答**：`SET NX PX` + Lua 释放 + 看门狗续期；RedLock 有争议。

**追问**：看门狗原理？→ 每 1/3 TTL 续期，直到 unlock。

### 60. Spring IoC 与 AOP

**答**：IoC 控制反转（容器管理对象）；AOP 用 JDK 动态代理（接口）或 CGLIB（子类）。

**追问**：Spring Boot 2.x 默认哪种？→ CGLIB（`proxyTargetClass=true`）。

### 61. Spring 事务传播

**答**：7 种；常用 REQUIRED（默认）、REQUIRES_NEW（独立事务）、NESTED（保存点）。

**追问**：REQUIRES_NEW vs NESTED？→ 新连接新事务 vs 同事务保存点。

### 62. SpringBoot 自动装配

**答**：`@EnableAutoConfiguration` → `AutoConfigurationImportSelector` → 读 `AutoConfiguration.imports` → `@Conditional` 过滤 → 注册 Bean。

**追问**：怎么自定义 starter？→ 配置类 + imports 文件 + 条件注解。

### 63. SpringMVC 流程

**答**：DispatcherServlet → HandlerMapping → HandlerAdapter → 拦截器 → Controller → 返回值处理 → 视图/消息转换。

**追问**：过滤器 vs 拦截器 vs AOP？→ Servlet 级 / MVC 级 / 方法级。

### 64. 过滤器、拦截器、AOP 的区别

**答**：Filter 最外层（request/response），Interceptor 能拿 Handler，AOP 能拿方法参数。

**追问**：哪个能改 request body？→ Filter（包装 RequestWrapper）。

### 65. Kafka vs RocketMQ

**答**：Kafka 吞吐最高、日志场景；RocketMQ 支持事务/延时/顺序，电商场景；Pulsar 存算分离、多租户。

**追问**：为什么 RocketMQ 用单一 CommitLog？→ topic 多时避免随机写。

### 66. MQ 顺序消息

**答**：生产按 key 分区 + 消费单线程/按 key 分发。

**追问**：代价？→ 并行度下降，一条卡住阻塞整个分区。

### 67. MQ 积压

**答**：算缺口 → 找瓶颈（并行度/单条耗时/下游）→ 扩容/批量/降级 → 防复发。

**追问**：积压 2 亿怎么算？→ 消费能力 = 实例 × (1000/单条ms)，追平时间 = 积压/(消费-生产)。

### 68. 注册中心选型

**答**：Nacos（AP/CP 可切、配置中心）、Eureka（AP）、ZK/etcd（CP）。

**追问**：注册中心为什么适合 AP？→ 列表短暂不一致可自愈，不可用是全站故障。

### 69. 限流算法

**答**：固定窗口（临界问题）、滑动窗口（Sentinel）、漏桶（恒定）、令牌桶（允许突发）。

**追问**：分布式限流怎么做？→ Redis+Lua、预分配配额、Sentinel 集群流控。

### 70. 熔断与降级

**答**：熔断三态（关闭/打开/半开）；降级返回兜底；隔离分线程池/信号量。

**追问**：熔断阈值怎么定？→ 错误率/慢调用比例 + 最小请求数 + 统计窗口。

## B 级：加分 30 题（71~100）

### 71. 布隆过滤器

**答**：位数组 + 多哈希；判断"一定不存在"或"可能存在"；不能删除（可用计数布隆）。

**追问**：参数怎么定？→ `k = (m/n)ln2`，误判率 `(1-e^(-kn/m))^k`。

### 72. 跳表

**追问**：为什么 Redis ZSet 用它？→ 范围查询友好、实现简单。

### 73. LRU / LFU 实现

**答**：LRU = 哈希 + 双向链表；LFU = 频次桶 + 双向链表。

**追问**：O(1) 怎么保证？→ 哈希定位 + 链表 O(1) 移动。

### 74. 限流与降级的区别

**答**：限流控制入口速率；降级牺牲功能保核心；熔断是自动触发的快速失败。

### 75. 分布式限流

**答**：Redis + Lua（精确但慢）、配额预分配（快但不均）、集群流控（Token Server）。

### 76. 服务优雅上下线

**答**：上线等健康检查；下线先摘流量 → 等在途请求 → 停进程。

**追问**：不做会怎样？→ 发布时短暂 5xx。

### 77. 灰度发布

**答**：按机器/用户/流量比例放量，配合开关与回滚。

**追问**：灰度看什么指标？→ 错误率、RT、业务指标。

### 78. 链路追踪

**答**：traceId + spanId + 上下文透传；采样；异步/线程池要手动传递。

### 79. 分布式任务调度

**答**：调度中心选主 + 分片 + 执行器 + 重试 + 幂等。

**追问**：怎么防重复执行？→ 执行记录唯一键。

### 80. 消息幂等表设计

**答**：`msg_id` 唯一索引 + 状态；插入成功才处理。

### 81. 数据库连接池

**答**：HikariCP 快在 FastList、ConcurrentBag、字节码精简；池大小 `CPU×2+磁盘数` 起步，压测定。

**追问**：`connectionTimeout` 和 `socketTimeout` 区别？→ 拿连接 vs 网络读。

### 82. 序列化选型

**答**：Protobuf（小快、兼容好）、JSON（可读）、Hessian（Dubbo）、Avro（schema 演进）。

### 83. 微服务拆分

**答**：按业务能力（DDD），不按技术分层；先模块化再拆进程；共享库是最大的坑。

### 84. API 幂等 token

**答**：服务端发 token → 提交带上 → 服务端原子删除（Redis `DEL` 返回 1）→ 重复提交失败。

### 85. 多级缓存

**答**：本地（Caffeine）+ Redis；一致性靠短 TTL、广播失效、版本号。

**追问**：本地缓存怎么失效？→ Pub/Sub 广播或 MQ。

### 86. 热点探测

**答**：客户端统计、代理层统计、Redis `--hotkeys`；处理：本地缓存、打散、限流。

### 87. 计数系统

**答**：Redis 计数 + 异步落库 + 定时校准；精确 vs 近似（HyperLogLog）。

### 88. 分布式锁续期

**答**：看门狗每 1/3 TTL 续；GC 停顿时仍可能丢锁 → fencing token。

### 89. 时钟回拨

**答**：雪花算法依赖时钟；小幅等待、大幅抛异常/换 workerId；或用 Leaf/UidGenerator。

### 90. 脑裂

**答**：网络分区导致双主；ZK/etcd 靠多数派，Redis 用 `min-replicas-to-write`；Eureka 自我保护。

### 91. CAP 与 BASE

**答**：分区发生时在 C/A 间取舍；BASE 是 AP 的工程化（基本可用、软状态、最终一致）。

### 92. 一致性哈希

**答**：环 + 虚拟节点；扩容只迁移部分；解决倾斜。

### 93. 服务雪崩

**答**：下游故障导致上游资源耗尽；防线：超时、隔离、熔断、限流、降级。

### 94. 全链路压测

**答**：流量染色 + 影子库表 + 数据隔离 + 阶梯加压找拐点。

### 95. 容量规划

**答**：QPS/存储/带宽/连接数估算 + 压测拐点 + 水位 60~70%。

### 96. 技术选型方法

**答**：列维度（性能/成本/运维/团队）+ 权重 + 打分；更重要的是"知道什么时候不该选"。

### 97. 线上问题排查方法论

**答**：现象 → 影响 → 监控 → 链路 → 现场 → 根因 → 止血 → 修复 → 预防。

### 98. 项目难点怎么讲

**答**：STAR + 量化 + 取舍 + 反思；难点要具体到"什么条件下触发什么"。

### 99. 重构 vs 重写

**答**：优先绞杀者模式（渐进迁移）；重写风险高，只适合边缘系统。

### 100. 反问面试官

**答**：问团队技术挑战、岗位目标、发布流程、成长路径；不问加班和薪资。
