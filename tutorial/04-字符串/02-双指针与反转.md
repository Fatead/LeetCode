# 02 双指针与反转

> **一句话理解**：字符串反转是**对撞双指针**在 `char[]` 上的直接应用——`left` 从左往右、`right` 从右往左，交换后同时内移；所有"部分反转""跳过无效字符"的变体，都只是在改**指针怎么移动**。

---

## 一、什么时候能用 / 什么时候不能用

双指针能成立的**唯一理由**：两个指针的移动方向具有**单调性**——"如果某个位置不满足条件，那它某一侧的所有位置都不满足"。

| 题目特征 | 能不能用双指针 | 为什么 |
| --- | --- | --- |
| 原地反转 / 交换对称位置 | ✅ 对撞双指针 | `left` 与 `right` 互不相干，交换即完成 |
| 回文判断 | ✅ 对撞双指针 | 只需比较对称位置，天然对称 |
| "反转每个单词" / "反转每 2k 个" | ✅ 定长分段 + 段内对撞 | 段的边界能算出来，段之间独立 |
| 跳过某些字符再反转 | ✅ 双指针 + 内层 `while` 跳过 | "跳过"是单向的，不破坏单调性 |
| 需保持相对顺序地删元素 | ✅ 快慢双指针 | 慢指针写、快指针读 |
| 退格字符 `#` | ✅ **从后往前**双指针 | `#` 只影响它**左边**的字符 |
| 从前往后处理退格 | ❌ 不行 | `#` 会回溯删除，前面的决定被后面的输入改写 |
| 需要随机访问历史位置 | ❌ | 该用栈 / `StringBuilder` 重建 |

**三种指针运动**：

```
对撞（相向）：  left →                    ← right      344 / 125 / 680 / 917
同向（快慢）：  slow →   fast →                        1047 / 443
分段：          [0,k) 反转  [k,2k) 不动  [2k,3k) 反转 …  541 / 557
```

**口诀**：**"对称问题用对撞，原地删改用快慢，区间重复用分段。"**

## 二、Java 通用模板

### 2.1 模板 A：对撞双指针反转（最核心，必须背）

```java
/**
 * 对撞双指针反转模板（闭区间 [left, right]）
 * 适用：整串反转、段内反转、回文比较
 */
private void reverse(char[] chars, int left, int right) {
    while (left < right) {          // ① 相遇即停：奇数长度时中间那个字符本来就不用动
        char temp = chars[left];    // ② 必须先存左边，否则被覆盖后丢失
        chars[left] = chars[right];
        chars[right] = temp;
        left++;                     // ③ 两个指针同时内移
        right--;
    }
}
```

**三个关键点**：

**① 为什么是 `left < right` 而不是 `<=`？** 交换是对称操作，`left == right` 时交换自己等于什么都没做。**边界证据**：奇数长度时中间那个字符本来就该留在原位，`left == right` 恰好是它。

**② 为什么必须先 `char temp = chars[left]`？** `chars[left] = chars[right]` 会覆盖左值。顺序必须是"存左 → 左=右 → 右=temp"。写反了整段会变成同一个字符。

**③ 为什么两个指针都动？** 一次交换处理了**两个**位置。只动一个会让 `left` 追上 `right` 后继续交换——结果"反转了又反转回去"。

### 2.2 模板 B：双指针 + 内层跳过（917 / 345 / 125）

```java
public String reverseOnlyLetters(String s) {
    char[] chars = s.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        while (left < right && !Character.isLetter(chars[left])) left++;    // ① 跳到有效字符
        while (left < right && !Character.isLetter(chars[right])) right--;  // ② 跳到有效字符
        char t = chars[left];                                               // ③ 交换
        chars[left] = chars[right];
        chars[right] = t;
        left++;
        right--;
    }
    return new String(chars);
}
```

> ⚠️ **最容易错的地方**：内层 `while` 的 `left < right` **不能省**。省掉后，当整串都是无效字符时 `left` 会一路冲出 `right` 甚至越界，抛 `StringIndexOutOfBoundsException`。

**执行轨迹**（`s = "a-bC-dEf-ghIj"`）：

```
初始   a - b C - d E f - g h I j      left=0 right=13
left 跳到 'a'(0)，right 跳到 'j'(13) → 交换（不变），left=1 right=12
left 跳到 'b'(2)，right 跳到 'I'(11) → 交换 b/I，   left=3 right=10
left 跳到 'C'(3)，right 跳到 'h'(10) → 交换 C/h，   left=4 right=9
left 跳到 'd'(5)，right 跳到 'g'(9)  → 交换 d/g，   left=6 right=8
left 跳到 'E'(6)，right 跳到 'f'(8)  → 交换 E/f，   left=7 right=7 → 退出
结果 "j-Ih-gfE-dCba" ✅
```

### 2.3 模板 C：从后往前处理退格（844）

```java
public boolean backspaceCompare(String s, String t) {
    int i = s.length() - 1, j = t.length() - 1;
    int skipS = 0, skipT = 0;                       // 待删除字符数
    while (i >= 0 || j >= 0) {
        while (i >= 0) {                            // 在 s 中定位下一个"有效字符"
            if (s.charAt(i) == '#') { skipS++; i--; }
            else if (skipS > 0) { skipS--; i--; }
            else break;
        }
        while (j >= 0) {                            // 对 t 做同样的事
            if (t.charAt(j) == '#') { skipT++; j--; }
            else if (skipT > 0) { skipT--; j--; }
            else break;
        }
        if (i >= 0 && j >= 0) {
            if (s.charAt(i) != t.charAt(j)) return false;
        } else if (i >= 0 || j >= 0) {
            return false;                           // 一方还有有效字符，另一方没了
        }
        i--;
        j--;
    }
    return true;
}
```

**为什么从后往前就"单调"了？** `#` 只删除它**左边**最近的那个字符。从右往左扫时，"这个 `#` 要删谁"永远只取决于**已经扫过的右边**，无需回退。从左往右扫就不行：你可能刚收下一个字符，就被后面的 `#` 删掉了。

## 三、核心应用一：整串反转与回文

### 3.1 例题：344. 反转字符串

**题意**：原地反转 `char[]`，要求 `O(1)` 额外空间。

**思路演进**：

```
暴力：新建一个数组倒着填，再复制回来 → O(n) 额外空间
优化：对称位置直接互换 → O(1) 空间
```

**优化的那一步消除了什么冗余**：消除了"复制一份数据"的冗余。既然要的是"倒过来"，那么 `s[0]` 该去的位置就是 `s[n-1]`，而 `s[n-1]` 该去 `s[0]`——**一趟交换同时安置两个元素**，不需要额外的缓存数组。

```java
public void reverseString(char[] s) {
    int left = 0, right = s.length - 1;
    while (left < right) {          // 相遇即停
        char temp = s[left];        // 先存左，再覆盖，最后回填
        s[left] = s[right];
        s[right] = temp;
        left++;
        right--;
    }
}
```

> 参考实现：[src/array/ReverseString.java](../src/array/ReverseString.java)

**复杂度**：时间 `O(n)`（共 `⌊n/2⌋` 次交换，每次处理 2 个位置），空间 `O(1)`。

**执行轨迹**（`s = ['h','e','l','l','o']`）：

```
初始   h e l l o       left=0 right=4
第1轮  o e l l h       left=1 right=3
第2轮  o l l e h       left=2 right=2 → left < right 为假，停
结果   olleh（中间的 'l' 没动，本来就该在中间）✅
```

**边界**：空数组 `[]` → `left=0, right=-1`，不执行 ✅；单元素 `['a']` → `left=right=0`，不执行 ✅；偶数 `['a','b']` → 交换一次后 `left=1, right=0`，停 ✅。

*反转字符串是【对撞双指针·原地交换】，关键突破点是"一次交换同时处理两个位置，所以 `left < right` 即可"，边界是奇偶长度都不需要特判。*

### 3.2 同模板变体：125. 验证回文串

**题意**：只考虑字母和数字、忽略大小写，判断是否回文。

**思路演进**：

```
暴力：先把有效字符过滤成新串 s'，再判断 s' 是否等于它的反转 → O(n) 空间 + 两遍遍历
优化：双指针 + 内层跳过，直接在原串上比较 → O(1) 空间，一趟扫描 ✅
```

```java
public boolean isPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        // ① 跳过左边的非字母数字（必须带 left < right）
        while (left < right && !Character.isLetterOrDigit(s.charAt(left))) left++;
        // ② 跳过右边的非字母数字
        while (left < right && !Character.isLetterOrDigit(s.charAt(right))) right--;
        // ③ 统一转小写再比，避免 'A' != 'a'
        if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right))) {
            return false;
        }
        left++;
        right--;
    }
    return true;
}
```

> 参考实现：[src/string/Palindrome.java](../src/string/Palindrome.java)（仓库版是"先过滤成新串再对称比较"，功能正确但空间 `O(n)`；面试推荐上面的 `O(1)` 双指针版）

**复杂度**：时间 `O(n)`（每个字符最多被 `left` 或 `right` 访问一次），空间 `O(1)`。

| 输入 | 结果 | 为什么 |
| --- | --- | --- |
| `".,"` | `true` | 两个字符都被跳过，`left` 撞上 `right`，循环结束 |
| `"0P"` | `false` | `'0'` 是数字、`'P'` 是字母，都有效；`'0' != 'p'` |
| `"a."` | `true` | 右边跳过 `'.'` 后 `right == left`，比较自身必然相等 |

> ⚠️ `Character.isLetterOrDigit('中')` 返回 `true`。只要 `a-z A-Z 0-9` 就得自己写区间判断——回文题最隐蔽的坑。

*验证回文串是【对撞双指针 + 跳过无效字符】，关键突破点是"内层 while 必须复用 left < right 的边界"，边界是整串无有效字符时返回 true。*

## 四、核心应用二：分段反转

### 4.1 例题：541. 反转字符串 II

**题意**：每 `2k` 个字符一组，反转每组**前 k 个**；剩余不足 `k` 个则把剩余全部反转。

**思路演进**：

```
暴力：按 2k 切块，每块调一次 reverse 再拼回去
      → 要处理"不足 k / 不足 2k"两种情况，还多一次 O(n) 拼接
优化：外层 for 一次跳 2k，内层用 min 算出本段右端后原地反转
      → 没有拼接、没有分块，三种剩余情况被 min 一句话吃掉 ✅
```

**优化的那一步消除了什么冗余**：把"三种剩余情况"压成**一个 `Math.min`**。`min(i + k - 1, n - 1)` 同时表达"够 k 个就反转 k 个"和"不够 k 个就反转到底"。

```java
public String reverseStr(String s, int k) {
    char[] chars = s.toCharArray();
    for (int i = 0; i < chars.length; i += 2 * k) {      // ① 每 2k 个字符一组
        int left = i;
        // ② 右端取 min：剩余 >= k 时是 i+k-1，剩余 < k 时是 n-1（尾巴全反转）
        int right = Math.min(i + k - 1, chars.length - 1);
        while (left < right) {
            char temp = chars[left];
            chars[left] = chars[right];
            chars[right] = temp;
            left++;
            right--;
        }
    }
    return new String(chars);
}
```

> 参考实现：[src/string/ReverseString2.java](../src/string/ReverseString2.java)（仓库版用 `substring` + `StringBuilder.reverse()` 分段拼接，并用 `if (s.length() % (2*k) > k)` 显式区分剩余情况；功能正确但是 `O(n)` 额外空间、分支更多）

**复杂度**：时间 `O(n)`（每个字符最多被访问两次），空间 `O(n)`（`char[]`）。

**执行轨迹**（`s = "abcdefg"`, `k = 2`，每组 4 个字符）：

```
i=0: [0, min(1,6)=1] → 交换 a,b  →  "bacdefg"
i=4: [4, min(5,6)=5] → 交换 e,f  →  "bacdfeg"
i=8: 8 >= 7 → 退出
结果 "bacdfeg" ✅（第 3 组只剩 "g" 1 个字符，不足 k=2，全部反转 = 不动）
```

**边界**：

| 情况 | 代码里的表现 | 结果 |
| --- | --- | --- |
| `k = 1` | 每段 `[i, i]`，`left == right`，不交换 | 原串 |
| 剩余恰好 `k` 个 | `min(i+k-1, n-1) == i+k-1` | 反转这 k 个 |
| 剩余 `< k` 个 | `min` 取到 `n-1` | 反转剩余全部 |
| 剩余恰好 `2k` 个 | 下一轮起点 `i+2k == n`，循环退出 | 正确 |
| `k >= n` | `i=0` 一轮，`min(k-1, n-1) = n-1` | 整串反转 |

*反转字符串 II 是【定长分段 + 段内对撞反转】，关键突破点是 `right = min(i + k - 1, n - 1)` 一句话吃掉"不足 k 个"的分支，边界是 `k = 1` 时 `left == right` 自然空转。*

### 4.2 同模板变体：557. 反转字符串中的单词 III

**题意**：把每个单词单独反转，单词顺序和空格位置不变。这是分段反转的最简形态——**分隔符就是空格，段的边界靠扫描找**。

```java
public String reverseWords(String s) {
    char[] chars = s.toCharArray();
    int i = 0, n = chars.length;
    while (i < n) {
        int start = i;
        while (i < n && chars[i] != ' ') i++;   // ① 找到单词右边界
        reverse(chars, start, i - 1);           // ② 段内反转
        i++;                                    // ③ 跳过空格，进入下一个单词
    }
    return new String(chars);
}
```

> 参考实现：[src/string/ReverseWords3.java](../src/string/ReverseWords3.java)（仓库版用 `split(" ")` + `new StringBuilder(str).reverse()`，更短但是 `O(n)` 额外空间；原地版更容易被追问"能不能不用 `reverse()` 库函数"）

**复杂度**：时间 `O(n)`，空间 `O(n)`（`char[]`）。**边界**：末尾无空格时最后一轮让 `i == n`，`i++` 后循环退出 ✅；单词长度 1 时 `reverse(l, l)` 不交换 ✅。

*反转单词 III 是【扫描定界 + 段内反转】，关键突破点是"用一个 `i` 同时充当扫描指针和段起点"，边界是末尾无空格时 `i == n` 的循环退出。*

## 五、核心应用三：单词级反转（151）

### 5.1 例题：151. 反转字符串中的单词

**题意**：颠倒单词顺序，并**规范空格**——去掉首尾空格，单词之间只留一个空格。

**思路演进**：

```
暴力：split(" ") 后倒序拼接 → 要额外处理空串和首尾空格
优化 A：trim() + split("\\s+") 后倒序拼 → 正则一次吃掉多空格，天然无空串 ✅
优化 B：整体反转 + 每个单词再反转一次 → 原地，O(1) 额外空间
```

**写法 A（推荐先写这个）**：

```java
public String reverseWords(String s) {
    if (s == null || s.length() == 0) return "";
    // \\s+ 一次吃掉"任意多个空白"，天然不产生空串（对比 split(" ") 的坑）
    String[] words = s.trim().split("\\s+");
    StringBuilder sb = new StringBuilder();
    for (int i = words.length - 1; i >= 0; i--) {
        sb.append(words[i]);
        if (i > 0) sb.append(' ');      // 分隔符加在"前面"，就不用最后再删
    }
    return sb.toString();
}
```

> 参考实现：[src/string/ReverseWords.java](../src/string/ReverseWords.java)、[src/string/ReverseWordsInSentence.java](../src/string/ReverseWordsInSentence.java)（仓库两版都是"切词后倒序拼"：前者用 `Stack` 存词再弹栈，后者用 `split(" ")` 倒着 append 并手动跳过空串）

**为什么 `split("\\s+")` 比 `split(" ")` 好？**

```java
"a  b".split(" ")      // ["a", "", "b"]   → 必须跳过空串
"a  b".split("\\s+")   // ["a", "b"]       → 天然干净
```

**边界**：`" "` → `trim()` 得 `""` → `"".split("\\s+")` 得 `[""]` → 拼出 `""` ✅。`split` 对空串返回长度 1 的数组是个反直觉行为，但在这题里正好给出正确答案。

**写法 B（整体反转 + 单词内反转，面试进阶）**：

**核心观察**：

```
原串     the sky is blue
整体反转  eulb si yks eht          ← 单词顺序对了，但每个单词内部是反的
单词内再反转一次  blue is sky the  ✅
```

**为什么这招有效？** 整体反转把"单词的顺序"和"单词内字符的顺序"**同时反转了**。第二次按单词反转又把字符顺序翻转回来，只留下顺序的反转——正是我们要的效果。

```java
public String reverseWords2(String s) {
    char[] chars = s.toCharArray();
    reverse(chars, 0, chars.length - 1);            // ① 整体反转
    StringBuilder sb = new StringBuilder();
    int i = 0;
    while (i < chars.length) {
        while (i < chars.length && chars[i] == ' ') i++;   // ② 跳过连续空格
        if (i == chars.length) break;                      // ③ 尾部空格，收工
        int start = i;
        while (i < chars.length && chars[i] != ' ') i++;   // ④ 扫完一个单词
        reverse(chars, start, i - 1);                      // ⑤ 单词内再反转
        if (sb.length() > 0) sb.append(' ');               // ⑥ 单词间只留一个空格
        sb.append(chars, start, i - start);                // 是 (char[], offset, 长度)
    }
    return sb.toString();
}
```

> ⚠️ **`StringBuilder.append(char[], offset, len)` 的第三个参数是**长度**，不是"右端点"**。写成 `append(chars, start, i)` 会多输出一个字符。

**复杂度对比**：

| 写法 | 时间 | 空间 | 面试建议 |
| --- | --- | --- | --- |
| A：`split` + 倒序拼 | `O(n)` | `O(n)` | ✅ 首选，5 分钟写完 |
| B：两次反转 | `O(n)` | `O(n)`（`char[]`；入参若为 `char[]` 则 `O(1)`） | 被问"能不能原地"时给 |

*反转字符串中的单词是【整体反转 + 单词内反转】，关键突破点是"整体反转同时翻转了单词顺序和字符顺序，第二次反转抵消后者"，边界是首尾空格与单词间多空格都要靠跳过逻辑吃掉。*

## 六、核心应用四：允许删一个字符的回文（680）

### 6.1 例题：680. 验证回文串 II

**题意**：最多删掉一个字符，判断剩下的能否构成回文。

**思路演进**：

```
暴力：枚举每个位置删除，对剩下的串做一次回文判断 → O(n^2)
优化：只在"第一次不匹配"的位置上分叉，两条路各试一次 → O(n)
```

**关键观察（正确性论证）**：设 `left`、`right` 是**第一次**出现 `s[left] != s[right]` 的位置。

```
s[left] 与 s[right] 是当前最外侧的一对字符，它们不相等。
要让它变成回文，只能：
  ① 删掉 s[left]，再用 s[left+1..right] 继续判断
  ② 删掉 s[right]，再用 s[left..right-1] 继续判断
没有第三种可能 —— 这一对必须"消掉一个"，删除其他位置的字符改变不了
s[left] 与 s[right] 仍然配对的局面。
而且后续不能再删（题目只允许删一次），所以两段都必须"本身是回文"。
→ 两个分支各做一次纯回文判断即可，不重不漏 ✅
```

```java
public boolean validPalindrome(String s) {
    int left = 0, right = s.length() - 1;
    while (left < right) {
        if (s.charAt(left) != s.charAt(right)) {
            // 第一次失配，两条路都得试：删左 or 删右
            return isPalindrome(s, left + 1, right) || isPalindrome(s, left, right - 1);
        }
        left++;
        right--;
    }
    return true;                        // 全程没失配，本身就是回文
}

/** 纯回文判断，闭区间 [left, right] */
private boolean isPalindrome(String s, int left, int right) {
    while (left < right) {
        if (s.charAt(left) != s.charAt(right)) return false;
        left++;
        right--;
    }
    return true;
}
```

> 参考实现：[src/string/Palindrome2.java](../src/string/Palindrome2.java)（结构与上面完全一致：外层找第一次失配，内层 `isPalindrome(s, left, right)` 做纯回文判断）

**复杂度**：时间 `O(n)`——外层指针总共走 `n/2` 步，两个分支加起来最多再走 `n` 步，**不是 `O(n^2)`**，因为两个分支各自最多扫完剩余部分一次（`||` 还会短路）；空间 `O(1)`。

**执行轨迹**（`s = "abca"`）：

```
left=0 'a'  right=3 'a'  → 相等，left=1 right=2
left=1 'b'  right=2 'c'  → 失配！
  ├─ 删左：isPalindrome(s, 2, 2) → left == right → true ✅ 短路返回 true
  └─ 不必再试删右
```

**边界的经典用例**：

| 输入 | 结果 | 走哪条分支 |
| --- | --- | --- |
| `"aba"` | `true` | 全程不失配 |
| `"abca"` | `true` | 删 `'b'` 后剩 `"aca"` |
| `"abc"` | `false` | 删左得 `"bc"` ✗，删右得 `"ab"` ✗ |
| `"deeee"` | `true` | 删 `'d'` 得 `"eeee"` |
| `""` / `"a"` | `true` | 循环不执行 |

*验证回文串 II 是【对撞双指针 + 一次分叉】，关键突破点是"第一次失配处必然要删 `s[left]` 或 `s[right]` 之一"，边界是只允许删一次所以分叉后必须用纯回文判断。*

## 七、核心应用五：退格与长按

### 7.1 例题：844. 比较含退格的字符串

**题意**：`#` 表示退格（删除它左边最近的字符），判断两个字符串处理后退格是否相等。

**思路演进**：

```
解法 1：重建字符串（栈思想）——遇普通字符 append，遇 '#' 删末尾
        → O(n) 时间、O(n) 空间，最简单
解法 2：从后往前双指针 → O(n) 时间、O(1) 空间，见 2.3 的模板 C
```

**解法 1**：

```java
public boolean backspaceCompare(String s, String t) {
    return build(s).equals(build(t));
}

private String build(String str) {
    StringBuilder sb = new StringBuilder(str.length());
    for (int i = 0; i < str.length(); i++) {
        char c = str.charAt(i);
        if (c == '#') {
            if (sb.length() > 0) sb.deleteCharAt(sb.length() - 1);   // 退格：原地删末尾
        } else {
            sb.append(c);
        }
    }
    return sb.toString();
}
```

> 参考实现：[src/string/CompareBackSpace.java](../src/string/CompareBackSpace.java)
>
> ⚠️ **仓库版写法可以改进**：它在每次退格时执行 `SNew = new StringBuilder(SNew.substring(0, SNew.length()-1))`——**新建对象 + 复制前面所有字符**，退格 `k` 次就是 `O(k·n)`。正确做法是 `sb.deleteCharAt(sb.length() - 1)`，原地删末尾是 `O(1)`（只有 `toString()` 才需要整体收缩）。这是"选对了 API，但用错了方法"的典型例子。

**执行轨迹**（从后往前双指针，`s = "ab##"`, `t = "c#d#"`，两者处理后都是 `""`）：

```
s: i=3 '#' → skipS=1, i=2 '#' → skipS=2, i=1 'b' → 被跳过(skipS=1),
   i=0 'a' → 被跳过(skipS=0), i=-1 → 停
t: j=3 '#' → skipT=1, j=2 'd' → 被跳过(skipT=0), j=1 '#' → skipT=1,
   j=0 'c' → 被跳过(skipT=0), j=-1 → 停
i = j = -1 → 两边都没有有效字符 → i-- j-- 后 while(i>=0||j>=0) 为假 → 返回 true ✅
```

**复杂度**：

| 解法 | 时间 | 空间 |
| --- | --- | --- |
| 重建字符串 | `O(n + m)` | `O(n + m)` |
| 从后往前双指针 | `O(n + m)` | `O(1)` |

*比较含退格的字符串是【从后往前双指针 + 跳过计数器】，关键突破点是"`#` 只影响左边，所以从右往左扫时指针永不回退"，边界是一方先扫完时必须用 `i >= 0 || j >= 0` 判定不等。*

### 7.2 例题：925. 长按键入

**题意**：`typed` 是 `name` 在打字时**某些字符被长按重复输入**后的结果，判断 `typed` 是否可能来自 `name`。

**思路**：双指针，`i` 指 `name`、`j` 指 `typed`，三种情况：

```
① name[i] == typed[j]      → 正常匹配，i++ j++
② typed[j] == typed[j-1]    → 这个字符是"长按重复"出来的，跳过，j++
③ 以上都不是                → typed 里出现了 name 里不该有的字符 → false
```

```java
public boolean isLongPressedName(String name, String typed) {
    int i = 0, j = 0;
    while (j < typed.length()) {
        if (i < name.length() && name.charAt(i) == typed.charAt(j)) {
            i++;
            j++;
        } else if (j > 0 && typed.charAt(j) == typed.charAt(j - 1)) {
            j++;                        // ② 长按出来的重复字符，直接跳过
        } else {
            return false;               // ③ 多出了 name 里没有的字符
        }
    }
    return i == name.length();          // typed 扫完了，name 也必须刚好扫完
}
```

> 参考实现：[src/string/LongPressedName.java](../src/string/LongPressedName.java)（仓库版是"按连续段分组、逐段比较 `countName <= countType`"的写法，功能正确但双指针版更短、更好讲）

**复杂度**：时间 `O(n + m)`，空间 `O(1)`。

**为什么返回 `i == name.length()` 而不是 `true`？**

```
name = "abc", typed = "ab"    → j 先走完，i = 2 < 3 → name 没匹配完 → false ✅
name = "abc", typed = "abbc"  → 全部匹配，i = 3 → true ✅
```

**`j > 0` 不能省**：`j == 0` 时 `typed.charAt(-1)` 会越界。它同时表达了语义——`typed` 的**第一个字符必须和 `name` 的第一个字符相同**，没有"长按"的余地。

| `name` | `typed` | 结果 | 关键点 |
| --- | --- | --- | --- |
| `"alex"` | `"aaleex"` | `true` | `"aa"` 和 `"ee"` 都是长按 |
| `"saeed"` | `"ssaaedd"` | `false` | 结尾多出 `'d'`，且它不是前一个字符的重复 |
| `"leelee"` | `"lleeelee"` | `true` | 连续段的长度只要 ≥ 原串即可 |

*长按键入是【双指针 + 连续段判断】，关键突破点是"`typed[j] == typed[j-1]` 就是把长按的重复字符跳过"，边界是 `j > 0` 防止越界、收尾必须检查 `i == name.length()`。*

## 九、易错点清单

| 易错点 | 后果 | 正确做法 |
| --- | --- | --- |
| 交换时先写 `chars[left] = chars[right]` | 左值被覆盖丢失 | 先 `char temp = chars[left]`，再覆盖，再回填 |
| 交换后只有一个指针内移 | 反转结果错乱 | 两个指针都必须动 |
| 反转循环用 `left <= right` | 奇数长度多一次自交换（不错但不专业） | 用 `left < right` |
| 内层 `while` 漏写 `left < right` | `StringIndexOutOfBoundsException` | `while (left < right && !valid(...))` |
| `substring(l, r)` 当闭区间用 | 少一个字符（`ReverseLeftWords` 的 bug） | `r` 是**开区间** |
| `split(" ")` 处理多空格 | 出现空串，需额外过滤 | `s.trim().split("\\s+")` |
| `StringBuilder.append(char[], from, to)` | 以为是左闭右开，其实第三参是**长度** | `append(chars, start, len)` |
| 退格用 `new StringBuilder(sb.substring(0, len-1))` | `O(k·n)` 的隐藏开销 | `sb.deleteCharAt(sb.length() - 1)` |
| 退格从前往后用双指针 | 刚收下的字符会被后面的 `#` 删掉 | 从后往前扫 + 跳过计数器 |
| 比较含退格的串漏判"一方还有字符" | 结果错误 | `else if (i >= 0 \|\| j >= 0) return false;` |
| 680 只贪心删一个方向 | 漏解 | 两条路都要试：`isPalindrome(l+1,r) \|\| isPalindrome(l,r-1)` |
| 925 收尾忘记检查 `i == name.length()` | `name` 没匹配完也返回 `true` | `return i == name.length();` |
| 541 的 `min(i + k - 1, n - 1)` 只写 `i + k - 1` | 最后一段越界 | 一定要取 `min` |
